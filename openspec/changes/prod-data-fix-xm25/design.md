# design — 25分厦门资产整清（建账成对 + 未生效单据清理）

## Context

实测（2026-09-15）：117 行台账（数量 80/820 + 耗材 37/1881）全由 117 张建账调整单解释；0 实例；42 张采购单全部"待审批"（纯实例行，逐行 ×1 的导入形态），从未生效——`check_ledger_consistency` 的流水重算只计 已通过/已入库，这些单据删除对台账零影响。

## Decisions

### D1. 成对删除 + 未生效单据直删，单事务合并

- 建账侧沿用 hz235/nb32 路径：调整单与台账行成对同删，replay 与 stored 双零自洽。
- 未生效单据（42 张）：不参与流水重算，删除无需回退；级联明细行，行-实例关联随行级联（instance 侧 PROTECT 不受影响——删的是链接行不是实例，且本分公司无实例）。
- 两侧同事务：任一断言失败整体回滚。

### D2. 前置断言边界

1. 无**生效**单据（from/to 任一方向）——有则说明台账另有解释源，不适用本路径，中止；
2. 无实例档案——有则转出生单/生平路径；
3. 建账侧无需再断言单据（上面第 1 条全覆盖）。

### D3. 通知清理与幂等

未生效单据的创建通知（related_object_id 指向单据 id）同批删除；两侧均空时幂等跳过。形态沿用：常量固化、dry-run、末尾内嵌对账复验。

## Risks / Trade-offs

- [误删生效单据] → 生效状态断言前置，失败零变更
- [待审批单被审批人在执行瞬间通过] → 断言在事务内复查后删除，窗口极小；且即使漏网，对账复验立即暴露
- [员工重导] → 节点/员工/字典保留，导入路径无阻碍

## Migration Plan

部署 → 备份 → dry-run 复核（117+117、42 张单号）→ `--apply` → 独立对账 + 抽查（台账 0、待审批列表空、员工在）→ 幂等复证。回滚走备份整库还原。
