# 设计：规格错填供应商数据纠错

## Context

实例档案列的派生关系：`规格 = birth_line.本批规格（空则回退品目字典）`、`供应商 = birth_line.供应商 or transfer.供应商`。员工错填发生在采购入库的行级「本批规格」。纠错落点即 `TransferLine`：本批规格 → 供应商（行级优先于单头，回写行级即可让派生列归位）。

## 匹配规则（口径来自用户）

| 品目圈定 | 规格匹配 | 动作 |
|----------|---------|------|
| 品目名称含「电脑」或「笔记本」 | 本批规格 **精确等于**：小熊U租 / 悟空 / 易点云 / 小熊 / 自购 | 规格值 → 行级供应商；本批规格清空 |
| 品目名称含「手机」 | 本批规格 **包含**：瑞克 / 华为 / 自购（任一） | 同上 |

- 圈定与匹配均按行独立判断；跨类不互通（电脑名单不适用于手机行，反之亦然）
- **保护**：`行.供应商 or transfer.供应商` 已有值 → 跳过，输出「行ID/单据/规格现值/既有供应商」清单待人工确认
- 幂等：本批规格清空后不再命中

## 命令设计

```
python manage.py prod_data_fix_supplier_from_spec            # dry-run：清单+统计，不落库
python manage.py prod_data_fix_supplier_from_spec --apply    # 落库，逐行 update_fields
```

输出：命中待改 N 行（电脑 x / 手机 y）、跳过保护 m 行、逐行明细（单据编号/品目/内部编号或行号/规格原值）。

## 执行序列（生产）

1. 部署级备份（pg_dump）
2. 生产 dry-run → 明细发给用户确认口径（尤其"包含"匹配的手机行）
3. `--apply` 执行 → 重跑 dry-run 应为 0 命中（幂等自证）
4. 抽查实例档案：规格列空、供应商列正确

## Risks / Trade-offs

- [手机"包含"匹配可能圈进如"华为Mate"这类真实规格] → dry-run 明细人工过目后才 apply；确有误圈由用户拍板剔除关键词
- [行级供应商与单头不一致的语义] → 派生逻辑本就行级优先，行为与既有展示一致
- [回退品目字典的规格行不受影响] → 命中仅发生在"出生行本批规格有错值"的记录上，品目字典规格不参与、不被清
