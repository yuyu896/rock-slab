# ledger-consistency-guard Specification（修改）

## MODIFIED Requirements

### Requirement: 对账命令

系统 SHALL 提供 `check_ledger_consistency` 管理命令，执行双重不变量：

一（数量）：对每「分公司 × 品目」行，以单据流水（期初调整单 + 期初时刻之后的已通过流转单 + 全部非期初调整单）重算在库/在用/回收库期望值，与台账存储值逐列比对。

二（实例）：对每「分公司 × 实例管理品目」，各状态实例计数 MUST 等于台账对应列（在库实例数==在库数量、在用==在用数量、回收库==回收库数量；退役实例不参与，其减少量由回收去向=直接处置的单据流水解释）。

全部一致时输出零差异并以退出码 0 结束；任何不一致 MUST 输出差异清单（分公司、品目、列、台账值、期望值）并以退出码 1 结束。数量管理品目挂有实例 MUST 输出警告清单（不改变退出码，交管理员决断改管理方式或退役）。

#### Scenario: 全库零差异

- **WHEN** 系统所有数量变动均经唯一写入口，执行 `check_ledger_consistency`
- **THEN** 输出零差异汇总，退出码 0

#### Scenario: 漂移被检出

- **WHEN** 绕过唯一写入口直接篡改某台账行在库数量后执行命令
- **THEN** 输出该行差异明细（台账值 vs 期望值），退出码 1

#### Scenario: 实例计数与台账不符被检出

- **WHEN** 某实例管理品目在分公司 A 在库数量为 5，但状态在库的实例仅 4 个
- **THEN** 对账输出实例维度差异（台账 5 vs 实例 4），退出码 1

### Requirement: 唯一写入口与架构测试

台账数量的全部写操作 MUST 收敛于台账服务模块（`assets/services/ledger.py`）；固定资产实例（状态/使用人/分公司/行-实例关联）的全部写操作 MUST 收敛于实例服务模块（`assets/services/instances.py`，由台账唯一写入口同事务调用）。项目 MUST 包含架构测试：扫描 `backend/apps` 源码，断言台账数量写模式与实例写模式仅出现在服务模块、migrations 与 tests 白名单内；违规即测试失败。

#### Scenario: 架构测试抓到越权写

- **WHEN** 某视图代码直接对 AssetStock 数量列执行 F() 更新或 save
- **THEN** 架构测试失败并指出违规文件

#### Scenario: 架构测试抓到越权实例写

- **WHEN** 某视图代码直接修改 FixedAsset.当前状态 或批量删除实例
- **THEN** 架构测试失败并指出违规文件

## ADDED Requirements

### Requirement: 存量实例对齐期初调整单

实例层接入迁移 MUST 对「实例管理品目 × 分公司」的 台账列 vs 实例计数 差异生成期初调整单（is_initial=True，事由注明「实例层接入对齐」），以实例计数为准对齐台账（实例档案是实物盘点过的更细粒度事实）；调整单 MUST 经台账唯一写入口创建。branch 为空的存量实例 MUST 跳过对齐并输出警告清单。迁移完成后 `check_ledger_consistency`（数量 + 实例双不变量）MUST 零差异。

#### Scenario: 迁移对齐台账到实例计数

- **WHEN** 迁移前某品目在分公司 A 台账在库 5，存量实例在库 3
- **THEN** 迁移生成期初调整单（在库 −2，事由「实例层接入对齐」），迁移后对账零差异

#### Scenario: 分公司为空的实例不参与对齐

- **WHEN** 某存量实例 branch 为空
- **THEN** 该实例跳过对齐计数，迁移输出警告清单提示补全分公司归属
