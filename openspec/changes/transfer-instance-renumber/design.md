## Context

内部编号在实例出生（采购生成）时按 `{品目编号}-{分公司code}-{序号}` 从 `InstanceSequence`（品目×分公司，select_for_update 锁行自增）分配（instances.py:96-125）。调拨生效路径 `apply_line_instances`（instances.py:139）目前仅 `inst.branch = transfer.to_branch`（:153），不动编号——生产 DB20260918-001 的 2 台 NB018 号实例现挂 32分宁波（计数器 NB018=103、NB032=101）。单据明细实例经 `get_instances` 序列化（serializers.py:31-34，`{id, code}`）。

业务拍板：调拨换号（按调入公司序列往后排）+ 单据双编号展示（前/后）。规格探讨已定驳回不换号、调回拿新号、标签零改动、旧号反查不做。

## Goals / Non-Goals

**Goals:**

- 调拨审批通过的同事务内：实例过户 + 按调入公司计数器换新号 + 「调拨前编号」快照进 TransferLineInstance
- 调拨单明细（PC 详情）双编号展示；序列化层输出前编号
- 存量漂号实例（编号分公司段 ≠ 当前分公司 code）管理命令补齐，走同一取号服务

**Non-Goals:**

- 曾用号字段与旧号反查（前编号快照在调拨单流水，可推导）
- 标签打印改动（打印当前编号即新号；调拨单即对照凭据）
- 台账/对账逻辑（编号不参与数量与序列号核对，零影响）
- 其他四类单据换号（采购出生号、领用/归还/回收不动号——号只在跨公司转移时变）

## Decisions

### D1：换号收口在 apply_line_instances 调拨分支，与过户同事务；取号=空号补位（业务拍板）

审批通过 → ledger/instance 生效的既有事务内追加三步：取号 → `renumber_instance(inst, f'{code}-{to_branch.code}-{no}')` → 写 `TransferLineInstance.调拨前编号 = 旧号`。驳回/草稿不走此路径（未生效），编号天然不动。

取号为**空号补位**：新函数 `_next_no_gap_aware(item, branch)`——先 `select_for_update` 锁该品目×分公司计数行（与出生发号共用同一把锁，串行化一切取号），锁内取现存编号尾段集合，**优先返回 {1..last_no} 中的最小空缺号**（last_no 不动）；无空缺才 `last_no+1` 并写回。禁止以编号字符串比较推断（字符串序 9 > 101）。口径（与业务确认的默认）：仅调拨换号补位，采购出生发号照旧追加（保持连号习惯）；复用空号=新机器顶旧号，业务方已认（空号主要来自随单据同清的全清批次，无归档污染）。
- 备选1：审批动作处换号——绕开生效事务，审批后未生效窗口编号与 branch 脱节；否决。
- 备选2：纯追加不补位——业务方明确要求补位；否决。

### D2：前编号快照在 TransferLineInstance，一列 CharField blank

新增 `调拨前编号 = CharField(max_length=100, blank=True, default='')`（纯 AddField，无 DML）。语义：仅调拨类型的行实例有值，值=该实例本次调拨前的内部编号。展示层（序列化/前端）按「有值才显示」渲染，其他类型零影响。
- 备选：FixedAsset 加曾用号链字段——第二份存储违反「每样信息只存一处」（前编号事实已在单据行）；且反查需求已裁不做；否决。

### D3：序列化 get_instances 增输出前编号，前端详情按类型展示

`get_instances` 输出 `{id, code, 前编号?}`（对齐既有驼峰透传惯例，中文字段名原样）。前端调拨详情实例编号渲染：有前编号的显示 `旧 → 新`；无前编号（存量老调拨单行、非调拨类型）显示现状单编号。创建页行编辑器（draft.instances）不变——选品时还没有前编号概念。

### D4：存量补齐命令 renumber_transfer_instances（预览/确认）

扫描口径：实例的编号分公司段（内部编号倒数第二段）≠ 当前 branch.code 且存在生效调拨单流水（从 TransferLineInstance 反查其调拨单）——现生产仅 DB20260918-001 的 2 台。对每台：`_next_no_gap_aware` 取号（同补位规则）→ `renumber_instance` → 回写其调拨单行的调拨前编号（幂等：已有前编号或编号已匹配的跳过）。默认预览打印「旧号 → 新号」清单，`--confirm` 执行。与 normalize_* 命令族同模式（架构测试白名单同先例）。

### D5：调拨导出不加实例粒度行

调拨导出当前为明细行粒度（无实例列），维持不变——双编号需求的消费场景是详情页人工对照（贴标签），导出加实例行会改变既有格式且无业务要求。

## Risks / Trade-offs

- [换号后历史单据（调拨前的领用单）上的旧号查不到实例] → 定位为「当时事实」的历史记录语义；跨变迁追溯经调拨单前编号快照链完成；旧号反查已明示不做
- [实物标签与系统号短暂不一致（换号后未贴标）] → 调拨单双编号即对照凭据，运营流程：收货方照「调拨后编号」重打标签
- [并发：同品目调拨生效与采购生成同时取号] → `_next_seq` select_for_update 锁行 + 内部编号唯一约束兜底（与出生发号同机制）
- [存量命令误伤] → 预览模式默认；扫描口径要求存在生效调拨流水，纯历史导入漂号（无流水）不碰
- [调回原公司拿新号引发业务困惑] → 规则已与业务确认（编号反映当前归属，非出生地终身制）

## Migration Plan

单 AddField 迁移（TransferLineInstance.调拨前编号）。部署顺序：代码上线（deploy.sh 含迁移）→ 生产跑 `renumber_transfer_instances`（预览核对 2 台 → `--confirm`）→ 对账零差异复核。回滚：代码回退即可，已换号的编号与快照无损（换号本身可逆语义对称）。
