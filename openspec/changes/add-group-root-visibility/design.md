## Context

当前组织树：区域 → 行政组 → 分公司，**无顶层根**。`filterEmployeesByNode` 的分支：branch / team(真实) / team(未分组) / region。全无归属员工（`branch`/`team`/`region` 都 null）落不到任何分支，**任何节点都看不到，仅搜索可见**。

线上数据：21 用户，其中 1 个全无归属（180男神，`13800000000`）——即被误认为"缺失"的账号。

## Goals / Non-Goals

**Goals:**
- 顶层「启航集团」虚拟根，显示全员（含全无归属）。
- 各层级员工不隐藏。

**Non-Goals:**
- 不建模管理层级（行政总监 / 行政经理 → 区域）——后续单独提案。
- 不新建集团模型（用前端虚拟根，当前单一集团）。
- 不改后端模型/API。

## Decisions

### D1. 集团根为前端虚拟节点
**选择**：`orgTree` computed 外包一层集团根节点（`type='group'`, `label='启航集团'`, `children=现有区域树`）。无后端模型。
**理由**：当前只有一个集团（启航集团），虚拟根够用，避免新模型 + 迁移。未来若需多集团再建 `Company` 模型。
**备选**：新建 `Company` 模型——当前过度。

### D2. 集团根显示所有员工
**选择**：`filterEmployeesByNode` 增加 `group` 类型分支 → 返回 `users` 全集（所有员工）。
**理由**：集团根是顶层，应一览全员，含全无归属的（解决 180男神看不到）。全无归属员工此前仅搜索可见，现在至少在集团根可见。

### D3. 各层级不隐藏（确认）
- **集团根**：所有员工（新）
- **区域**：`u.region=该区域`（已支持，含区长等无分公司/组归属的）
- **行政组 / 未分组 / 分公司**：按既有归属规则（已支持）

即：全无归属员工此前在任何节点都看不到，本提案后**至少在集团根可见**；其余层级本就支持。

## Risks / Trade-offs

- **[集团根列表过长]** 大组织时集团根显示全员会很长 → 当前规模（21 人）无碍；未来可加搜索/分页。
- **[集团名硬编码]** 「启航集团」写死在前端 → 当前单一集团可接受；多集团时再改配置/模型。

## Migration Plan

仅前端改动。部署：`deploy.sh`（前端 build + nginx reload），无后端 migrate。
