# design — 33分宁波按内部编号点删实例

## Context

目标 3 实例（A-a00011-NB033-16/17/19）出生于两条多实例行：

| 出生单 | 行 | 数量 | 出生实例 | 目标 |
|---|---|---|---|---|
| CG20250610-004 | 行1 | 6 | 12–17 号 | 16、17（保留 12–15） |
| CG20250404-004 | 行1 | 13 | 19–31 号 | 19（保留 20–31） |

镜像：台账在库 75 = 实例 75（全在库、无生平单据）。整行/整单删除会误伤同行的保留实例——此前的连删路径全部不可用。

## Decisions

### D1. 行数量粒度的应用之逆

对每条涉行：`数量 −= 该行被删实例数`；删目标实例与关联；台账在库同额直减。对账数学：流水重算随行数量自减 k，存储值同减 k，镜像两侧同减——三处同步后 replay == stored == 实例计数。

替代方案（否决）：保留行数量、挂 −3 调整单——采购单将永远声称买了 19 台而实例只有 16 台，行账错位留痕；行数量修正后"如同少买了 3 台"语义干净，与既有连删口径（如同从未发生）一致。

### D2. 前置断言（点删特有）

1. 目标全部存在、都在目标分公司、状态在库（非在库说明有生平，点删会破坏镜像）；
2. 出生单为生效采购单；
3. **行账一致**：各涉行 `数量 == 该行出生实例数`——不等说明历史已错位，减行不再安全；
4. 品目级镜像一致（台账 == 在库实例数）。

### D3. 作用域与形态

全部操作以目标内部编号集合收敛；他分公司同品目零波及（对账+抽查双验）。命令形态沿用：常量固化、dry-run、单事务、末尾内嵌对账复验、幂等（目标不存在即跳过）。

## Risks / Trade-offs

- [误删同名实例] → 内部编号全局唯一，无歧义；dry-run 打印每个编号与其出生行变动
- [行数量减错] → 按行分组计数减行，断言行账一致前置
- [发号序列断档] → 序列保留自增（16/17/19 成为空号，不回收防撞号），后续导入无影响

## Migration Plan

部署 → 备份 → dry-run 复核（3 编号、两行 6→4/13→12、75→72）→ `--apply` → 独立对账 + 抽查 → 幂等复证。回滚走备份整库还原。
