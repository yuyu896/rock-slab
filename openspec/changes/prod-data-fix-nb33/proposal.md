## Why

33分宁波的 3 个一体机实例（内部编号 A-a00011-NB033-16/17/19）系错误登记，用户要求点删（2026-09-15）。实测：三者均出生于**多实例行**（CG20250610-004 行1 ×6 出生 12–17 号、CG20250404-004 行1 ×13 出生 19–31 号），同行还出生着需保留的实例——整行/整单删除不可用，需行数量粒度的"应用之逆"。镜像现状：台账在库 75 = 实例 75；同品目他分公司 2222 个实例须零波及。

## What Changes

- 新增一次性纠错管理命令 `prod_data_fix_nb33`（默认 dry-run，`--apply` 执行，事务+对账门禁）——**按内部编号点删实例**：
  1. 删除 3 个目标实例及其行-实例关联；
  2. 各出生行 `数量` 同步减去该行被删实例数（6→4、13→12）——流水重算随之自减，"如同少买了这几台"；
  3. 台账在库同额直减（75→72），镜像保持；
  4. 发号序列与其他实例不动。
- 前置断言：目标全部存在且在本分公司、状态在库、出生单为生效采购单、各出生行 数量==该行出生实例数（行账一致才可安全减行）、镜像一致。
- 执行后 `check_ledger_consistency` 必须零差异。
