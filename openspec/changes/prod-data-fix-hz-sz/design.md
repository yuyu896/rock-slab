## Goals / Non-Goals

**Goals:**
- 两案后 `check_ledger_consistency` 零差异
- 案1 调整单与台账行成对同删，节点/授权保留供重导
- 案2 实例连完整生平单据清退，聚合净额回退一次到位

**Non-Goals:**

## Decisions

### D1. 案1 成对删除：调整单 + 台账行必须同批

该分公司流水全由调整单构成（无流转单据）。只删台账行 → 流水重算有值无行（"台账行缺失"差异）；只删调整单 → 行有值流水为零（列差异）。成对同删后 replay=0、stored 无行，天然一致。前置断言"无实例、无流转单据"守住适用边界——有流转单据的分公司不适用本法（需 case-2 式生平处理），断言失败即中止。

### D2. 案2 生平连删 + 聚合净额回退（对 0914/0915 模式的关键扩展）

前案模式只处理"全在库"实例（出生单回退即净额）。退役实例的生平含领用/回收单，其数量贡献与出生单相互交织：
- **逐单回退不可行**：在用列现值为 0，先回退领用单的在用 −1 会中途变负被拒；
- **聚合回退**：全部涉单计划按 (分公司×品目×列) 求净额（本案 在库 −1、在用 0），一次应用并断言非负——数学上等价于"这些单据从未发生"。

涉单收集 = 行-实例关联（instance__branch=该分公司）∪ 出生行所属单据的并集；断言每张涉单：生效状态、每行品目为实例管理、且该行所链实例**全部**在该分公司（防他分公司实例的单据被误删——行链多分公司实例即越界中止）。

### D3. 命令形态沿用 + 助手复用

`prod_data_fix_hz_sz`：常量固化、`--apply` 开关、案级 atomic、末尾内嵌对账复验、幂等跳过报告。案2 复用 0914 的 `_transfer_ledger_plan`（实时算量）与 `_delete_transfer_with_born_instances`（单据级删除顺序）；聚合回退为本命令新写（`_rollback_ledger` 是逐单语义，不适用）。

## Risks / Trade-offs

- [案2 误删他分公司实例的单据] → 行级作用域断言（所链实例全在本分公司）+ dry-run 打印每张单号与净额
- [案1 边界漏判（其实有流转单据）] → 前置断言无实例无流转单据，失败中止零变更
- [聚合净额与实删不符] → 净额执行时实时从明细行计算；断言最终值非负
- [重导撞号/丢授权] → 案2 发号序列保留；案1 节点与授权保留
