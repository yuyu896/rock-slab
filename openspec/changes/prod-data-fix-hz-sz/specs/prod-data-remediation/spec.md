## ADDED Requirements

### Requirement: 调整单建账资产整清

生产纠错命令 SHALL 支持整清"资产全部由调整单建账"的分公司：该分公司的全部台账调整单与台账行 MUST 在同一事务内成对删除（只删其一必然造成流水重算与存储值的对账差异）。适用前置：该分公司 MUST 无实例档案且无流转单据（from/to 均无），否则 MUST 中止并提示改用生平连删路径。组织节点、节点授权、品目字典 MUST 保留。

#### Scenario: 成对清空建账数据

- **WHEN** 某分公司 81 行台账全部来自 81 张建账调整单，命令以 `--apply` 整清
- **THEN** 调整单与台账行全部删除，`check_ledger_consistency` 零差异
- **AND** 组织节点与节点授权保留，员工可重新导入建账

#### Scenario: 存在流转单据时拒绝

- **WHEN** 目标分公司存在任一流转单据（或实例档案）
- **THEN** 命令前置断言失败中止，零变更，提示改用生平连删路径

### Requirement: 实例生平连单整清

生产纠错命令 SHALL 支持删除分公司实例档案时**连同其完整单据生平**：涉单集合 SHALL 为"行-实例关联指向该分公司实例 ∪ 出生行所属单据"之并集；每张涉单 MUST 断言生效状态、明细行均为实例管理品目、且每行所链实例全部属于该分公司（越界即中止）。台账回退 MUST 按全部涉单计划聚合净额一次应用（逐单回退会在中途产生负值），聚合后各列 MUST NOT 为负。实例发号序列 MUST 保留。

#### Scenario: 退役实例的完整生平清退

- **WHEN** 某分公司 2 个实例（1 在库走过领用+回收-重新入库、1 退役走过领用+回收-直接处置），命令以 `--apply` 整清
- **THEN** 6 张生平单据（2 采购/2 领用/2 回收）、2 个实例、行-实例关联、关联通知全部删除
- **AND** 台账按净额聚合回退（在库 −1、在用 0），`check_ledger_consistency` 零差异

#### Scenario: 涉单越界即中止

- **WHEN** 某涉单明细行同时链接了其他分公司的实例
- **THEN** 命令断言失败中止，零变更（防误删他分公司实例的单据）

#### Scenario: 聚合回退不产生中途负值

- **WHEN** 生平单据含"领用后在用列被回收清零"的交织流水，台账在用现值为 0
- **THEN** 聚合净额一次应用（在用净额为 0 则不变），不因单张单据的中间回退值变负而失败
