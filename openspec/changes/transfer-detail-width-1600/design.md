## Context

版宽基准沿革：列表页 1600（用户拍板基准=回收单旧宽）；详情页 1080 是早期默认，page-width-unify 时明确留案未办（"其他页面版宽不动"）。明细表自撤回改版后供应商进明细行，列只增不减。

## Goals / Non-Goals

**Goals:** 详情与列表版宽一致，明细表获得横向空间。

**Non-Goals:** 不动实例档案/台账等其他窄页（用户未提出）；不做 100% 占满（超宽屏行长难扫读，列表页当年已弃）；不动移动端。

## Decisions

| 决定 | 理由 |
|------|------|
| 1600 与列表页同基准 | 列表↔详情切换无跳变；一个基准贯穿核心页面 |
| 只改 max-width 一行 | 信息区 flex 自适应、明细表自适应列宽，无需配套改动 |
| 修在共享布局组件 | 一处生效五种详情页，避免五处复制粘贴漂移 |

## Risks / Trade-offs

- [五页同步变宽是否波及不该宽的页] → TransferDetailLayout 仅被五种单据详情页使用（已核引用），无其他消费方
- 回归面：视觉走查五种详情页各一；build 类型门禁；无逻辑断言可断
