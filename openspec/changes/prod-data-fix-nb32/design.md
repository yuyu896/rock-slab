# design — 32分宁波非实例品目整清

## Context

数据形态（2026-09-15 实测）：

| 维度 | 非实例品目 | 实例品目 |
|---|---|---|
| 台账行 | 34 行全非零（在库 90） | 3 行（在库 187，与实例计数镜像一致） |
| 调整单 | 34 张（建账导入） | 6 张（解释镜像库存） |
| 实例 | — | 187 个全在库、无出生行（存量迁移形态） |
| 流转单据 | 无（from/to 均 0） | 无 |

与杭州235（prod-data-fix-hz-sz 案1）同族：纯调整单建账、无单据，成对删除即对账自洽（replay=0、stored 无行）。本案新增**管理方式维度过滤**：只清 `management_type in (quantity, consumable)` 的行与调整单，实例品目一侧完全不进删除集合。

## Goals / Non-Goals

**Goals:** 非实例品目台账与调整单成对清空；187 实例与其实例品目台账/调整单/镜像原样；对账零差异；幂等。

**Non-Goals:** 不动实例档案（含其 6 张调整单——删之镜像必炸）；不动组织节点与其他分公司；不参数化泛化。

## Decisions

### D1. 管理方式过滤的成对删除

删除集合 = `AssetStock(branch=32分宁波, item__management_type__in=('quantity','consumable'))` ∪ `LedgerAdjustment(同过滤)`。实例品目的行与调整单不过滤进来，天然保留。成对性由"无流转单据"断言保证（有单据则数量账另有解释源，需生平路径）。

### D2. 前置断言

1. 该分公司无流转单据（from/to）——同杭州235 路径边界；
2. 非实例品目上不存在实例档案（`FixedAsset(branch, item__management_type != 'instance')` 为空）——防数据错挂时误判保留面；
3. 实例品目镜像不检查（不动它，全局对账兜底）。

### D3. 命令形态沿用

常量固化、dry-run/`--apply`、atomic、末尾内嵌对账复验。本案逻辑极简（两个 queryset 成对删），无需复用 0914 助手。

## Risks / Trade-offs

- [误删实例品目数据] → 管理方式过滤双向校验：删除集合只含非实例品目；dry-run 打印逐行清单复核
- [边界漏判（其实有流转单据）] → 前置断言零单据，失败中止零变更
- [员工后续重导数量型库存] → 调整单建账路径仍在（台账增量导入），无阻碍

## Migration Plan

部署 → 备份 → dry-run 复核 → `--apply` → 独立对账 + 抽查（数量行 0、实例 187 与镜像台账原样）→ 幂等复证。回滚走备份整库还原。
