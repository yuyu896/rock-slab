## Context

- 资产导入模板现 20 列（已在前序变更去掉序号、警戒线、分公司编号）：分公司、资产编号、资产类目、电脑序列号、供应商、物品分类、资产名称、图片、入库日期、是否租用、数量、规格、单价、购入金额、出库日期、所属部门、使用人、当前状态、是否充足、备注。
- 固定资产导入模板 19 列（`FA_HEADERS`），其中 `FA_READONLY_COLS = {0,1,2,4,5,6,10,11,12,13,14,15}` 标 12 列为「此列自动继承，无需填写」。
- 用户填写的固定资产列（不在 readonly）：资产编号(3)、电脑序列号(7)、供应商(8)、入库日期(9)、所属部门(16)、使用人(17)、当前状态(18)。
- 两个导入均**按列名映射**（`cell(row, 名称)`），缺列返回空；固定资产导入按 `资产编号` 查父资产、继承 分公司/分公司编号/branch（`views.py:506-508`），并按列名读填写列（资产名称缺省回退父资产 `:499`）。

## Goals / Non-Goals

**Goals:**
- 两模板只含用户需填写的列，去掉系统派生/自动继承的冗余列。

**Non-Goals:**
- 不改导入字段读取逻辑（按列名映射、缺列默认/继承已稳健）。
- 不改导出列、不删模型字段。

## Decisions

### 决策 1：资产模板去 5 列
- **做法**：表头去 `电脑序列号、图片、是否租用、是否充足、使用人`（序号/警戒线/分公司编号 既已移除）。
- **理由**：用户无需在导入时填这些；缺列走默认（是否租用=否、是否充足=是）/空，导入不受影响。

### 决策 2：固定资产模板只留 7 个填写列、清空 readonly
- **做法**：`FA_HEADERS = [资产编号, 电脑序列号, 供应商, 入库日期, 所属部门, 使用人, 当前状态]`；`FA_READONLY_COLS = set()`（无只读列 → 不再有「自动继承」标注）。
- **理由**：固定资产导入已按列名读这 7 列、其余继承父资产；序号与只读继承列移除后行为不变，模板更简洁、无误导性「自动继承」标注。

## Risks / Trade-offs

- **[用户旧模板含已去列]** 按列名映射仍兼容（旧列被读取或忽略）。
- **[固定资产资产名称]** 去列后导入回退父资产名称（`:499` `or parent_asset.资产名称`）——符合「继承」语义。

## Migration Plan

1. 后端：两个 `download_template` 表头调整 + `FA_READONLY_COLS` 置空。
2. 纯后端模板改动，**无 DB 迁移**；部署即生效。
