## Why

P3 第二刀：报表口径切换与体验清理。报表后端自 P1 起口径正确（数量=台账三列、金额=采购明细行），但前端报表页是一个"装饰性拼盘"：总值增速 +12.3%、使用率 +2.1%、库存不足 12 全是硬编码假数据；分公司排行"数量/价值"tab 是没接线的装饰；资产分类环图取自 V2 已删除的品目字段恒为空（后端 by_category 闲置）；月度趋势的字段映射对不上后端返回（全部流水被算进"调拨"），无数据时填 6 个月假数据；变动明细表的操作类型/操作人/时间三列恒为 "-"（后端根本不返回这些字段名）；分公司明细表的"使用中"列是拿占比乘总数的伪计算、"资产总值"把数量当金额展示；状态分布颜色 key 与实际三态对不上。报表页目前讲的不是真话。

## What Changes

- **后端双口径补全**：`by_branch` 每分公司返回 在库/在用/回收库/总量 四列数量 + 采购金额（已生效采购单按明细行金额、入库分公司归属）；`overview` 增加 `lowStockCount`（在库 < 生效警戒线的台账行数）与 `valueGrowthRate`（采购金额月环比）；调拨流水报表行补 `operator`（单头创建人）。
- **前端去假修真**：指标卡全部接真数据（总值增速用 valueGrowthRate；库存不足用 lowStockCount 且"立即查看"跳台账页不足筛选；使用率环比无真实来源，移除假趋势角标）；分公司排行"数量/价值"双 tab 接线（价值=采购金额）；分类环图改接 by_category；月度趋势按正确字段重聚合（入库=采购+归还、出库=领用+回收、调拨，按数量求和），无流水展示空态不再造假；分公司/分类明细表展示真实列；变动明细表按后端真实字段渲染（含单据编号/经办人/数量）；状态色 key 对齐 在库/在用/回收库；导出同步修正。
- **台账页不足筛选**：AssetStock 筛选参数 `sufficient=0`（在库 < 行级警戒线 ?? 品目默认），台账页加"是否充足"下拉，承接报表"库存不足"下钻。

## Capabilities

### New Capabilities
- `report-metrics`: 报表双口径输出（数量=台账、金额=采购明细行）与报表页真实数据契约——禁止硬编码数值与错误字段映射，无数据展示空态。

### Modified Capabilities

（无——report-data-scoping 的授权过滤与明细行聚合口径不变，金额聚合本就属其既有约束；台账筛选为新增参数不改既有需求。）

## Impact

- 后端：`apps/reports/views.py`（overview/by_branch/transfers 三个端点扩展）、`apps/assets/filters.py`（sufficient 参数）。
- 前端：`views/Reports.vue`（指标卡/图表/明细表/导出全面修真）、`api/reports.ts`、`types/index.ts`、`views/assets/AssetSummary.vue`（充足筛选 + 路由查询参数承接）。
- 测试：后端新增 overview 不足计数/金额环比、by_branch 金额（多分公司多明细行采购）、流水行含经办人、sufficient 筛选用例；前端 vitest 断言报表页无硬编码假数据残留、tab 切换与环图数据源。
- 不动：对账与台账写路径（纯读侧改动）；dateRange 语义（台账数量为时点快照，时间过滤仅作用于单据层指标，页面文案说明）。
