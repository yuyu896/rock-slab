## Context

盘点两种形态的范围定义在 `inventories/views.py`：实例盘 `_generate_instance_items`（在用×分公司×可选类目快照）、台账盘 `_generate_items`（所选库别列>0 的台账行）。inventory-checklist-safety（已实施未部署）在此之上加了 `_scope_count` 空清单拦截——刻意与生成条件同源。三家分公司实证：潍坊 0 在用 102 在库（现行实例盘永远空）、济宁全量填表 44 行在库实例报错。FixedAsset 四态在库/在用/回收库/退役；AssetStock 三列+总量（物化派生不落库）。

## Goals / Non-Goals

**Goals:**

- 实例盘覆盖全部非退役实例；台账盘专属非实例品目（总量口径）；零交集
- 与 safety 的拦截/提示随范围语义同步进化（五处联动一次改齐）
- 差异处置边界明确：数量品自动平账（扣在库）、实例品待跟进人为

**Non-Goals:**

- 盘点锁、状态机、漏盘规则、报告结构
- 「部门实例盘点」既有 spec 的旧部门维度语义（另行清理）
- 潍坊空清单任务处置（运维动作）
- 一键回收扩展到在库实例（在库 missing 语义=实物不在库里，出路是人为查，不是回收单）

## Decisions

### D1：分派规则唯一收口在品目 management_type

实例盘清单=分公司×可选类目下全部非退役实例；台账盘清单=该范围内 management_type≠instance 且总量>0 的台账行。生成函数与 `_scope_count` 同步改（保持同源不变式）。台账盘 expected_qty=总量（三列合计——回收库列历史归零，合计即实物总数）。
- 济宁验证：89 台实例全部进实例盘；台账盘只剩数量/消耗品行。
- 潍坊验证：102 台全进实例盘。

### D2：台账盘差异自动平账固定扣在库列，库别概念整体下线

`task_target_column` 固定返回在库列（库别字段保留作存量兼容，choices 不再暴露）。差异调整单只作用于数量/消耗品行——总量差异≈在库差异（数量品在用≈0、消耗品无在用），扣在库无歧义。若数量品确有在用量且差异出自在用，台账盘报告提示人工核实（差异行备注呈现），不自动猜列。
- 备选：差异单按「在库优先、在库不足扣在用」——引入猜测，违背单据确定性；否决。

### D3：实例盘模板加「状态」列 + 导入表头守卫

模板列序变为 `序号/内部编号/序列号/品目编号/品目名称/状态/使用人/所属部门/核对结果/备注`（状态插在品目名称后，填表人先见状态再核对人）。加列使核对结果列索引 7→8、备注 8→9——**导入解析必须同移**，并加**表头守卫**（首行须与模板表头一致，不符 400 提示重新下载模板）——旧模板文件（无状态列）会被守卫拦下而非静默错位（transfer-responsible 先例：用户拍板不管旧文件兼容）。台账盘模板列不变（无加列）。

### D4：在库实例的核对与差异处置

核对语义：在库实例「已找到」=库里见到这台实物；「未找到」=库里没有（可能已被处置/调拨未走单/丢失）。missing → 报告待跟进（现有机制），**不出现「一键回收」**（一键回收前置=在用；在库 missing 的正解是人为查明后走对应单据）。清单/报告展示按「在库/在用」分组，在库组使用人/部门列显示为空。

### D5：拦截与提示文案随新语义重写

开始拦截：实例盘空=「该分公司（所选类目内）无实例档案可盘」；台账盘空=「范围内无非实例管理品目的台账行」。删除「早于领用审批」病因（新模型下审批时序不影响范围）。导入 hint 同步为「清单为空——开始盘点时范围内无对象；请核对范围或作废重建」。

### D6：实例点选补全（并入，2026-09-24 另一会话核验坐实）

①**未选分公司禁用**：InstancePicker 补 ItemPicker 同款 `disabled`（branchName 为空禁用+提示「请先选择所属分公司」）——现状无 branch 时跨分公司取前 100，用户先选分公司才见全量。②**滚动加载+搜索双管**：候选滚动触底取下一页（后端分页上限 100 不破，page++ 续取）；面板顶部加搜索框（按内部编号/序列号过滤，137 台里直达目标台）。③**待审批占用**：治本=后端预检——创建/编辑预检矩阵加一条：实例被未生效单据（待审批/草稿）绑定行引用 → 拒绝并报占用单号（UI 排除有 TOCTOU 窗口，预检才是闸门；行锁终检已兜底生效时点）；体验=点选器候选并行拉取该品目×分公司的占用映射，占用行标注单号置灰。④**领用列表死筛选**：AssignList 删 toBranch 筛选项（454d5a1 调拨模板遗留，领用 to_branch 恒空、选值必空）。⑤**报错单前缀**：instances._err 的报错文案去掉「明细行 X（品目）」前缀（该前缀唯一收口在 ledger 生效循环的 _with_line_context——check_line_instances 仅被生效路径调用，双包一层致前缀重复；烟台占用冲突弹窗实证）。
- 归还/回收/调拨的创建页点选器同步受益（组件级修复）。

## Risks / Trade-offs

- [模板加列导致旧文件导入错位] → D3 表头守卫硬拦 + 400 文案引导重下模板
- [台账盘总量口径遇上数量品在用余额] → 差异行备注呈现提示人工核实（D2），不自动猜列
- [实例盘范围扩大后清单变大（百台级）] → 模板/清单本就逐台行；分组展示缓解浏览；导入/点选/扫码三通道照旧
- [占用预检的误伤面]（驳回单复活编辑场景）→ 驳回单引用不拦（其重提转待审批时再拦），仅拦待审批+草稿；占用映射查询按 品目×分公司 收敛开销
- [与 safety 统一部署的顺序依赖] → 归档顺序 safety → 本变更；spec delta 按此排序（A/B 的 MODIFIED 指向 safety 归档后的主 spec）
