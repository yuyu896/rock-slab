## MODIFIED Requirements

### Requirement: 流转单编辑权限覆盖确认的草稿生命周期

采购、领用、调拨和回收单据的创建、草稿/驳回编辑、提交/重提和创建人撤回 MUST 分别由对应的 `edit_*` 权限覆盖；调拨拒收 MUST 并入 `edit_transfer`。编辑权限 MUST 以前置查看权限和建单所需的台账/品目查看权限为条件。

#### Scenario: 编辑采购单前置
- **WHEN** 用户只有编辑采购入库单但缺少采购单查看或品目查看
- **THEN** 创建、编辑、提交、撤回和导入请求 MUST 被拒绝

#### Scenario: 调拨拒收并入编辑
- **WHEN** 用户持有编辑调拨单并满足查看调拨单、查看台账前置
- **THEN** 用户可对发往授权分公司的待审批调拨单执行拒收
- **AND** `reject_transfer_inbound` MUST NOT 作为新权限授予

#### Scenario: 回收不提供批量导入
- **WHEN** 用户请求回收批量导入
- **THEN** 接口 MUST 拒绝该入口
- **AND** 回收创建和编辑继续使用页面单据流程

### Requirement: 流转导入错误必须整份驳回

采购、领用和调拨导入 MUST 在任何一行校验错误时回滚整份文件，不创建或提交其他有效行。未登记品目错误 MUST 只返回行号和文件中的编号。

#### Scenario: 混合有效和错误行
- **WHEN** 导入文件同时包含有效行和越权、数量或品目错误行
- **THEN** 接口 MUST 返回错误明细
- **AND** 数据库 MUST 不新增任何该文件单据

### Requirement: 流转导出必须严格按请求类型过滤

`/api/transfers/export?type=...` MUST 先按请求类型过滤可见单据，再按用户数据范围、状态和分公司筛选，导出文件不得混入其他类型。

#### Scenario: 采购导出不含领用单
- **WHEN** 用户请求 `type=purchase` 且查询集同时包含采购和领用单
- **THEN** 导出文件 MUST 只包含采购单明细

### Requirement: 流转草稿仅创建人可查看和操作

采购、领用、调拨和回收单处于“草稿”状态时，列表、详情、导出、编辑、提交和删除 MUST 只允许单据创建人访问，并仍须通过对应权限和数据范围校验。系统管理员 MUST NOT 绕过创建人限制查看或操作他人草稿。此限制 MUST 应用于所有复用流转单查询集的页面和 API。对已驳回单据，系统管理员已确认的编辑和重提例外继续保留；此例外 MUST NOT 扩展到草稿。

#### Scenario: 创建人查看并操作本人草稿
- **WHEN** 用户查询本人创建的草稿，且具备相应查看及操作权限
- **THEN** 用户 MUST 能查看草稿并按现有状态和数据范围规则执行已授权操作

#### Scenario: 普通用户不能查看同范围他人草稿
- **WHEN** 用户尝试通过列表、详情、导出或复用的流转查询接口读取同一数据范围内其他员工的草稿
- **THEN** 该草稿 MUST 不出现在结果中
- **AND** 直接读取请求 MUST 被拒绝

#### Scenario: 系统管理员不能绕过草稿创建人限制
- **WHEN** 系统管理员尝试查看、编辑、提交或删除他人创建的草稿
- **THEN** 请求 MUST 被拒绝且草稿状态和内容 MUST 保持不变

#### Scenario: 系统管理员可按既有例外处理他人已驳回单据
- **WHEN** 系统管理员查看他人已驳回的采购、领用、调拨或回收单
- **THEN** 系统管理员 MUST 能按既有权限规则编辑并重新提交该单据
- **AND** 草稿创建人限制 MUST NOT 应用于已驳回状态

#### Scenario: 草稿查询不受客户端创建人参数影响
- **WHEN** 客户端在草稿列表或导出请求中提交其他创建人标识
- **THEN** 服务端 MUST 仅返回当前账号本人创建的草稿

### Requirement: 归还页面和新权限必须移除

归还入库页面、路由、导航和可新授予权限 MUST 移除；历史归还数据 MUST 保留供台账、报表和审计读取，归还写接口 MUST 继续拒绝。

#### Scenario: 历史数据保留但页面不可达
- **WHEN** 用户访问归还页面或提交归还写请求
- **THEN** 页面路由 MUST 不可达且写请求 MUST 被拒绝
- **AND** 历史归还数据 MUST 继续参与既有内部统计和审计读取
