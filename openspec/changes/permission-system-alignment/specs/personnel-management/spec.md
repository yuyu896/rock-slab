## ADDED Requirements

### Requirement: 员工和组织写权限必须以前置查看权限为条件

新增、编辑、删除员工以及新增、编辑、删除组织节点 MUST 分别要求对应员工账号或组织架构查看权限。员工编辑权限包含新增、编辑、删除员工；组织编辑权限包含新增和编辑组织，删除组织保持独立。

#### Scenario: 只有查看员工
- **WHEN** 员工只持有查看员工账号
- **THEN** 员工 MUST 不能新增、编辑或删除员工账号

#### Scenario: 组织删除独立
- **WHEN** 用户持有组织架构查看和删除组织节点
- **THEN** 用户可按数据范围尝试删除组织节点
- **AND** 编辑组织权限 MUST NOT 因为查看权限自动获得

### Requirement: 修改集团名称必须为全组织范围

修改集团单例名称 MUST 同时要求编辑组织节点权限和全组织数据范围；分公司、行政组或区域范围用户不得修改集团名称。

#### Scenario: 有限范围修改集团名称
- **WHEN** 只有部分组织数据范围的用户请求修改集团名称
- **THEN** 接口 MUST 返回 403 或 400
- **AND** 集团名称 MUST 保持不变

### Requirement: 岗位或分公司变化必须重置数据范围

新员工默认只获得所属分公司的数据范围，岗位本身 MUST NOT 扩大数据范围。员工岗位或分公司变化时，系统 MUST 将数据范围重置为当前所属分公司的默认范围。改岗 MUST 按新岗位基线重置账号业务权限；单独更换分公司 MUST 保留现有账号业务权限。首次向现有在职员工补授岗位基线 MUST 保留其现有数据范围。

#### Scenario: 员工改岗
- **WHEN** 管理员将员工改为另一岗位
- **THEN** 员工业务权限 MUST 按新岗位默认基线重置
- **AND** 旧岗位基线和旧个人权限调整 MUST 清除
- **AND** 数据范围 MUST 重置为该员工当前分公司的默认范围

#### Scenario: 员工单独更换分公司
- **WHEN** 管理员只更换员工所属分公司而不改变岗位
- **THEN** 员工现有业务权限 MUST 保留
- **AND** 数据范围 MUST 重置为新分公司的默认范围

#### Scenario: 岗位不扩大员工数据范围
- **WHEN** 新建员工或更改员工岗位
- **THEN** 数据范围 MUST 只包含其所属分公司默认范围
- **AND** 不得仅因岗位名称或岗位等级扩大到行政组、区域或全组织

#### Scenario: 首次补授岗位基线保留数据范围
- **WHEN** 管理员为现有在职员工首次补授岗位默认权限
- **THEN** 员工原有自定义数据范围 MUST 保持不变
- **AND** 数据范围差异另行列出核对

### Requirement: 删除员工账号必须通过双重权限和组织保护校验

删除员工账号 MUST 同时要求“查看员工账号”和“编辑员工账号”，并按操作者当前数据范围校验目标员工。删除本人也 MUST 满足这两项权限，不得绕过授权检查。系统 MUST 拒绝删除最后一个在职系统管理员。若员工担任区域负责人、行政组长或分公司负责人，删除前 MUST 为其负责的每个组织节点指定新的有效负责人。

#### Scenario: 缺少任一权限时不能删除
- **WHEN** 操作者缺少“查看员工账号”或“编辑员工账号”任一权限
- **THEN** 删除任何员工账号（包括本人）的请求 MUST 被拒绝

#### Scenario: 目标员工超出数据范围
- **WHEN** 操作者持有查看和编辑权限但目标员工不在其当前数据范围
- **THEN** 删除请求 MUST 被拒绝，目标员工账号和关联数据 MUST 保持不变

#### Scenario: 删除最后一个在职系统管理员
- **WHEN** 删除请求目标是最后一个在职系统管理员
- **THEN** 系统 MUST 拒绝删除
- **AND** 该账号及管理员登录能力 MUST 保持不变

#### Scenario: 删除组织负责人前指定继任者
- **WHEN** 目标员工负责一个或多个组织节点但其中至少一个节点尚无新的有效负责人
- **THEN** 删除请求 MUST 被拒绝
- **AND** 组织节点 MUST 继续保留原负责人

### Requirement: 员工账号物理删除不得破坏历史业务记录

删除员工账号 MUST 物理移除员工及其组织人员记录，使其不能继续登录，且组织架构和员工列表 MUST NOT 保留该员工的当前账号资料。系统 MUST 自动删除其尚未提交的采购、领用、调拨和回收草稿，以及个人通知和审批抄送记录。待审批流转单、已驳回流转单、盘点任务及流水、对账任务及版本/差异处理、台账手工调整和审计日志 MUST 保留；删除账号时解除业务外键关联，并保存历史显示所需的创建人/经办人姓名快照。删除员工时 MUST 清除审计日志中的手机号快照，但 MUST 保留操作人姓名。

待审批单据和盘点任务不因创建人离职或删除而作废。其员工关联解除后，由当前数据范围内具备岗位审批资格的行政组长及以上人员或系统管理员处理；若当前无人可处理，业务状态 MUST 保持待审批或原任务状态，不得级联删除或自动审批。

#### Scenario: 删除员工时清除未提交草稿
- **WHEN** 员工账号删除且该员工创建了未提交的采购、领用、调拨或回收草稿
- **THEN** 这些未提交草稿 MUST 自动删除
- **AND** 已进入待审批或已驳回状态的单据 MUST NOT 因该规则删除

#### Scenario: 删除员工不影响待审批单和盘点任务
- **WHEN** 员工账号删除且该员工关联待审批流转单或盘点任务
- **THEN** 业务记录 MUST 保留且状态不变
- **AND** 删除员工 MUST NOT 要求其待审批记录或盘点任务先完成

#### Scenario: 无可处理人员时保留待审批状态
- **WHEN** 删除创建人后当前范围内暂时没有符合岗位规则的审批人
- **THEN** 待审批单据 MUST 保持待审批
- **AND** 系统 MUST NOT 自动驳回、删除或审批该单据

#### Scenario: 已驳回单据解除账号关联并保留姓名
- **WHEN** 删除员工账号且该员工创建了已驳回流转单
- **THEN** 单据 MUST 保留历史创建人姓名并解除已删除账号的外键
- **AND** 系统管理员 MUST 能继续编辑或重新提交该单据

#### Scenario: 保留其他业务历史和操作人姓名
- **WHEN** 删除员工账号且其关联盘点、对账、台账调整或审计记录
- **THEN** 对应记录 MUST 保留并解除指向已删除账号的外键
- **AND** 历史显示 MUST 保留创建人或经办人姓名
- **AND** 审计记录 MUST 清除手机号快照

#### Scenario: 删除后账号和个人消息不可继续使用
- **WHEN** 员工账号删除成功
- **THEN** 该账号 MUST 不能再登录，已有认证凭证 MUST 失效
- **AND** 该员工的个人通知和审批抄送记录 MUST 删除
- **AND** 组织架构和员工列表 MUST NOT 再显示该账号资料
