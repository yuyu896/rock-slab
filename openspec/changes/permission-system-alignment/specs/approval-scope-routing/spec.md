## ADDED Requirements

### Requirement: 资产流转和盘点审批必须按岗位与数据范围判定

采购、领用、调拨、回收和盘点的审批资格 MUST 使用统一策略判定，不得依赖逐单审批人名单。分公司行政只能审批本人创建的待审批单；行政组长及以上可审批当前数据范围内的待审批单；系统管理员可审批任意待审批单。

#### Scenario: 分公司行政审批本人单据
- **WHEN** 分公司行政持有对应审批权限并请求审批本人创建的待审批单
- **THEN** 请求 MUST 被允许

#### Scenario: 分公司行政审批他人单据
- **WHEN** 分公司行政持有对应审批权限但请求审批同范围内他人创建的待审批单
- **THEN** 请求 MUST 被拒绝

#### Scenario: 行政组长及以上按范围审批
- **WHEN** 行政组长或更高岗位持有对应审批权限，请求审批当前数据范围内他人创建的待审批单
- **THEN** 请求 MUST 被允许
- **AND** 数据范围外单据 MUST 被拒绝

#### Scenario: 系统管理员审批任意单据
- **WHEN** 系统管理员请求审批任意待审批流转单或盘点任务
- **THEN** 请求 MUST 被允许，不受审批人名单或数据范围记录限制

### Requirement: 审批列表和审批动作必须使用相同策略

待审批列表的可见性、详情读取和审批/驳回动作 MUST 使用同一岗位与数据范围策略，并且审批权限 MUST 以前置查看权限为条件。

#### Scenario: 缺少查看权限不能读取待审批详情
- **WHEN** 用户持有审批权限但没有对应单据或任务查看权限
- **THEN** 用户 MUST 不能通过列表、详情或直接接口读取待审批内容

#### Scenario: 审批人路由不再逐单指定
- **WHEN** 单据进入待审批状态
- **THEN** 系统 MUST 根据请求用户、创建人、岗位、权限和数据范围实时判定审批资格
- **AND** MUST NOT 要求单据保存一个逐单指定的审批人名单
