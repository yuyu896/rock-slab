## Context

当前仓库已经有账号级权限、数据范围、权限分配页和权限矩阵，但实现仍混合了两套口径：权限目录保留旧的创建/编辑/提交/导入操作码，部分接口只校验写权限，审批仍依赖按分公司计算的审批人名单，前端授权页也没有表达查看权限前置。后续讨论还确认了岗位默认权限自动同步、员工硬删除及历史数据保留、流转草稿仅创建人可见和操作、审计日志仅系统管理员可访问。本变更将全部最终规则统一落到目录、迁移、前端和运行时鉴权上。

本变更还涉及两个高风险边界：一是旧权限码迁移不能把粗粒度能力静默扩大到新权限；二是审计日志、对账供应商信息、导出文件和归还历史数据都必须在移除或收紧入口后保持数据完整性。系统管理员继续使用内置全权例外；普通账号的权限和数据范围均以显式授权为准。

## Goals / Non-Goals

**Goals:**

- 建立唯一的中文权限目录、稳定权限码、模块归属、说明和前置关系。
- 让授权页、授权 API、页面入口和后端接口使用同一依赖关系。
- 按岗位层级与数据范围统一判定五类流转单和盘点任务的审批资格。
- 完成审计日志、对账、资产台账、实例档案、组织名称和导出的已确认边界。
- 按已确认的岗位默认权限清单同步账号授权，更新岗位和分公司时按规则重置权限及数据范围。
- 删除员工账号时真正删除账号、清理未提交流转草稿和个人通知，同时保留已提交及其他业务历史。
- 以只读预览、逐账号差异和可恢复快照迁移旧权限；旧权限不自动放大。
- 移除归还权限和前端页面，同时保留历史数据供内部台账、报表和审计使用。

**Non-Goals:**

- 不改变资产台账、流转单和盘点状态机本身的业务含义。
- 不把查看权限隐式转换为任何写权限。
- 不恢复归还入库的新建、编辑、提交、审批或独立历史页面。
- 岗位本身不参与运行时鉴权；岗位默认权限被明确写入账号授权记录，岗位不会扩大数据范围。
- 不在没有用户确认的情况下自动映射旧权限或扩大数据范围。
- 不在本变更中决定旧的、无法无损映射的历史权限应授予哪些新操作；这类记录必须进入人工核对清单。

## Decisions

### 1. 使用版本化权限目录和显式依赖图

`OPERATION_CATALOG` 继续作为后端与前端的目录来源，但目录条目增加稳定版本、中文名称、模块、说明、前置权限和已废弃标记。合并后的新操作使用统一命名：基础资料和员工组织沿用 `edit_*`，流转使用 `edit_purchase`、`edit_assignment`、`edit_transfer`、`edit_recovery`，盘点使用新码 `edit_inventory`。

依赖关系由目录生成一份只读依赖图，前端用它决定复选框是否可选和取消时清理哪些权限，后端用同一图校验保存请求和运行时接口。前端不再自行维护一套仅用于显示的依赖表。

替代方案是只在每个接口里手工增加 `view_*` 校验。该方案会让授权页可以保存接口必然拒绝的组合，也容易遗漏移动端和候选项接口，因此不采用。

### 2. 旧权限码只迁移为历史记录，不直接映射扩大能力

旧码不再出现在可新授予目录，但继续以历史权限记录返回给管理员。迁移命令先生成只读预览：列出账号、旧码、新码候选、数据范围变化和无法无损映射项。只有明确一对一或已确认的映射才可应用；其余保留待核对标记。

迁移前保存账号权限和数据范围快照。旧权限迁移先只读预览并人工核对；首次岗位基线补授仅处理在职员工，将该岗位已确认的基线并入既有明确授权，不修改现有数据范围。无法确认的旧权限不得映射为新权限。迁移写入与审计记录在同一事务中完成；验证失败时恢复快照。系统管理员不写入授权表，继续由内置规则拥有全部权限。

### 3. 以策略函数替代审批人名单路由

新增统一审批策略服务，输入用户、单据类型、单据创建人、业务分公司和当前数据范围，输出是否可以审批。规则固定为：分公司行政只能审批本人创建的待审批单；行政组长及以上可审批当前数据范围内的待审批单；系统管理员可审批任意待审批单。

审批列表可见性和审批动作使用同一策略，并且先通过对应查看权限校验。移除本级审批人优先、上级回退和逐单分配审批人的运行时依赖；通知收件人也按数据范围收敛。

替代方案是保留审批人名单、只修改目录说明。该方案无法实现已确认的岗位和范围规则，因此不采用。

### 4. 审计日志仅向系统管理员开放并按数据范围过滤

审计日志页面、导航和全部后端读取接口只允许系统管理员访问；普通岗位不得被授予 `view_audit_logs`，即使请求中伪造该权限也不能访问。日志查询仍按当前数据范围过滤，系统管理员的全组织范围可见全部日志。审计日志没有统一的分公司字段，因此新增只读资源映射器：盘点任务、台账调整、流转单、对账任务/差异、员工记录等映射到可见分公司；登录、权限变更、全局字典/组织操作和无法映射的资源对有限范围账号隐藏。日志可见但快照无法安全裁剪时，保留日志并隐藏快照。

数据范围只决定系统管理员可见的日志集合，不产生审计日志授权；非管理员不提供审计日志页面或接口访问，即使其持有其他全局查看权限也不例外。

### 5. 将页面入口和接口权限分层处理

查看权限控制页面和只读数据，写权限只控制相应写动作。编辑、导入、审批、删除等依赖查看权限的操作在前端置灰并在后端拒绝缺失前置的请求。导出随对应查看权限开放，但流转导出必须额外按请求 `type` 过滤。

跨模块候选接口也采用完整前置：实例编辑需要实例查看和供应商字典查看；更换使用人需要实例查看和部门字典查看；台账筛选和实例下钻分别要求对应字典/实例查看权限。

对账是特殊页面：任务列表、详情和导出要求“查看对账 + 查看供应商字典”；“维护对账”还必须具备“查看对账”，并与供应商字典查看一起作为其前置。维护权限只控制差异处理、归档和供应商订单预览/导入/替换等维护行为，不单独开放页面或导出。

### 6. 分阶段移除归还入口

第一阶段从新目录和授权页移除 `view_return` 及归还写权限，旧码只保留迁移记录；前端删除归还页面、路由、导航和创建入口；后端写接口继续拒绝。历史 Transfer 数据不删除，台账重放、报表和审计读取历史表时继续识别归还类型。

### 7. 以行为测试锁定边界

每个前置关系至少覆盖授权页置灰、取消清理、直接 API 拒绝和合法组合放行；审批覆盖四类岗位/范围组合；导入覆盖任一错误整份回滚；导出覆盖类型隔离；审计覆盖管理员专属访问、资源映射、无映射隐藏和快照隐藏；归还覆盖页面不可达和历史数据保留。

### 8. 岗位默认权限写入账号授权并保留个人差异

岗位默认授权以用户确认的 `D:\4、磐盘相关\岗位开通权限核对表.xlsx` 为基准，并将批准后的三类普通岗位权限码清单固化到版本控制中的基线配置。系统管理员继续使用内置全权。岗位基线仅用于授予 OperationGrant，不参与每次运行时授权判断；授权页显示员工当前实际生效的勾选状态，不显示“继承/追加/取消”等来源标签。

新建员工按岗位授予基线；改岗时清空原岗位基线与个人调整，按新岗位基线重新建立权限。首次同步现有在职员工时仅补授其岗位基线，合并已有明确授权，不扩大现有数据范围；不能确认的新旧权限码进入人工核对，不自动映射。以后修改岗位基线时先展示受影响员工及权限差异，管理员确认后更新基线并保留个人追加和个人取消。停用保留账号授权和数据范围；重新启用时同步当前岗位基线、保留个人调整和现有范围。

新员工和岗位/分公司变更后的默认数据范围仅为所属分公司。岗位本身不扩大数据范围。岗位或分公司变化都重置数据范围；仅换分公司时保留账号业务权限，改岗时业务权限按新岗位基线重置。现有在职员工首次补授基线时保留当前数据范围，范围差异另行核对。

### 9. 员工账号硬删除，保留已提交业务历史

删除员工必须同时具备“查看员工账号”和“编辑员工账号”，按当前数据范围校验目标员工；员工本人也仅在持有这两项权限时可删除本人。不得删除最后一个在职系统管理员。若目标员工担任区域负责人、行政组长或分公司负责人，删除前必须先为每个相关组织节点指定新的有效负责人；删除事务须验证继任人已经生效。

账号删除在事务中物理删除用户并使其登录凭证失效；联动清除该员工创建的未提交采购、领用、调拨和回收草稿及其个人通知、审批抄送。待审批流转单、盘点任务及盘点流水、已驳回单、对账任务和版本、台账调整及其他历史业务记录均保留。历史外键改为可空或置空，并持久化创建人/经办人显示姓名；审计日志保留操作人姓名快照但清除手机号快照。待审批事项的负责人关系解除后由范围内管理员或行政组长及以上继续处理；若暂时无人可处理，业务状态仍保留待审批。

## Risks / Trade-offs

- [旧权限迁移导致权限收窄或扩大] → 先生成只读预览，无法无损映射的旧码不自动迁移，并保存恢复快照。
- [前端依赖和后端依赖不一致] → 从同一目录依赖图生成前端状态，并在后端保存 API 和每个敏感接口重复校验。
- [审批列表和审批动作口径不一致] → 使用同一个审批策略函数生成列表可见性和动作授权，并为岗位边界增加回归测试。
- [审计资源无法映射或快照包含越界数据] → 对有限范围账号隐藏无法映射日志；无法安全裁剪快照时只返回日志元数据。
- [岗位基线变更造成授权静默扩大或收窄] → 基线变更先提供逐人差异并要求管理员确认；个人追加和取消单独保存；权限分配页只显示实际结果，不影响内部审计来源。
- [硬删除员工级联删除历史业务数据] → 仅删除未提交流转草稿和个人消息；已提交业务通过可空外键及姓名快照保留，删除与组织负责人替换在事务中校验。
- [移除归还页面影响历史查询] → 保留数据库、台账和报表数据链路；迁移期间验证历史统计和审计引用不受影响。
- [大范围权限改造回归风险高] → 分阶段上线目录/迁移、运行时校验、前端入口和归还移除，每阶段运行定向后端与前端测试。

## Migration Plan

1. 生成新目录和依赖图，标记旧码、归还码、系统管理员专属权限和不可新授予码；不改变现有运行时权限。
2. 执行旧权限迁移与岗位基线补授的只读预览，逐账号核对权限和数据范围差异，保存快照。
3. 部署账号级岗位基线、授权前置校验、审批策略、审计管理员专属与范围过滤、导出类型过滤和数据范围限制。
4. 首次只为现有在职员工补授岗位基线，保留原授权和范围；无法无损映射的旧码保持待核对，不自动授予新码。
5. 部署授权页和权限矩阵更新，验证当前有效权限勾选、前置置灰、取消清除提示、保存失败和管理员例外。
6. 实施员工硬删除及历史关联迁移；先保证历史外键和姓名快照可保留，再开放删除入口。
7. 删除归还前端页面、路由、导航和可授予权限，验证历史台账、报表和审计数据仍可使用。
8. 完成回归测试后，保留权限迁移快照、基线变更审计和旧码核对记录，供必要时恢复或追溯。

回滚时先恢复新权限和数据范围快照，再关闭新目录/前端入口；不删除迁移期间产生的业务数据和历史归还数据。

## Open Questions

没有影响本提案成立的产品规则待决项。旧权限码的逐账号映射结果属于实施前必须人工核对的迁移材料，不在提案阶段静默决定。
