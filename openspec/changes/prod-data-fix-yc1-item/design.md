# design — 盐城品目整体更正（A-a00008 → A-a00011，含换号）

## Context

34 台一体机被录成笔记本：出生链单点（一张纯单 CG20260911-016 单行 ×34）、无生平/调整/待审批，A-a00011 在盐城空白。品目是台账镜像的维度，改品目必须四处同批联动，否则镜像/对账必炸。

## Decisions

### D1. 四处联动 = 品目维度的"应用之逆"

出生行 item 改正后流水重算自动把 +34 从笔记本移到一体机；存储值同侧移动（笔记本行清零删除、一体机行新建 34）——replay 与 stored 同迁，0 检查差异。镜像两侧（实例计数/台账列）随实例 item 与台账行同步迁移。

### D2. 换号 1:1 保序号

`A-a00008-YC001-N → A-a00011-YC001-N`（序号不变，仅前缀随品目）。A-a00011@盐城发号行新建 last_no=34（后续导入从 35 续）；A-a00008 发号行保留 34（空号不回收，同点删先例）。断言目标编号全局无占用（内部编号唯一约束兜底）。

### D3. 断言面（比前案更严）

- 目标实例全在库、生平行数==1（仅出生链——有领用/回收则品目迁移破坏生平语义，转人工）；
- 出性行行账一致（数量==该行出生实例数）；
- 两品目在盐城：无调整单（有则流水源残留笔记本侧）、无待审批行、目标品目无实例无台账行；
- 新编号全局无占用、镜像一致。

### D4. 保留项

序列号（本就是一体机序列号）、单价/金额/供应商（按实际采购录入）、单号/日期、他分公司 44 台笔记本。

## Risks / Trade-offs

- [旧标签失效] → 品目本印错，需重打（用户已知）
- [换号撞全局唯一] → 断言前置 + DB 唯一约束兜底
- [生平残留] → 生平行数断言拦截

## Migration Plan

push → 部署 → 备份 → dry-run（34 台逐台旧号→新号）→ `--apply` → 独立对账 + 抽查（两品目台账/镜像/编号/发号行、他司零波及）→ 幂等复证。
