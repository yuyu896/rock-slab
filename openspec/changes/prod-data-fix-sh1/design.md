## Context

与 prod-data-fix-20260915 案A（19分台州×工作手机）完全同型的再次适用：378 实例全在库、出生于 47 张纯工作手机行已入库采购单、镜像零差异、零调整单。区别仅数量级（47 单 vs 2 单）。

## Decisions

### D1. 直接复用 0915 案A 逻辑结构

按出生实例分公司归属反查出生单（作用域天然收敛）；断言 purchase+生效+**纯 A-a00007 行**（混行中止转人工）；镜像断言复用 0915 的 `_assert_in_stock_mirror`；删除顺序与算量复用 0914 助手（`_transfer_ledger_plan` 实时算量 / `_rollback_ledger` 逐条回退——全为采购 +在库 计划，无负值风险 / `_delete_transfer_with_born_instances`）。

### D2. 命令形态沿用

常量固化（上海分公司、A-a00007）、dry-run/`--apply`、单事务、末尾内嵌对账复验、幂等跳过。

## Risks / Trade-offs

- [误伤他分公司工作手机] → 出生实例归属反查收敛 + 混行断言 + 对账/抽查双验（基准 2681 实例）
- [执行中数据再变] → 断言在事务前实判，回退量实时计算

## Migration Plan

部署 → 备份 → dry-run 复核（47 单/−378）→ `--apply` → 独立对账 + 抽查（他品目与他分公司不动）→ 幂等复证。回滚走备份整库还原。
