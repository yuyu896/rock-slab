# 设计

## 数据与写入

新增 `FixedAssetAssigneeChange`，保存变更前后的使用人和部门名称、操作账号快照、时间及可选原因。该表只追加，不提供通用编辑或删除接口。

通过单实例 `POST /api/assets/fixed-assets/{id}/change-assignee` 完成交接。服务在事务中锁定实例，确认实例处于在用状态、调用者具备目标分公司的数据范围，并且实例未被草稿或待审批流转单占用，再同时更新当前责任人和追加历史记录。相同使用人和部门不产生新事件。变更不调用台账服务。

接口只接受单个实例的使用人、有效部门 ID 和可选原因。自由文本使用人不要求关联员工账号。交接不修改资产状态、分公司或库存数量。

## 生平与编辑界面

生平响应合并流转行和交接事件，按发生时间倒序返回。原五列展示保留；交接行类型为「使用人变更」，单据显示 `-`，使用人列只显示新使用人和新部门，日期只显示年月日。

编辑弹窗在用实例允许修改使用人和部门，非在用实例显示只读值。底部「保存」先提交一般档案字段，成功后才调用专用交接接口。交接失败时保留弹窗和输入值，并按实例 ID 刷新档案基线，使重试不会遗漏采购日期清空操作。

## 授权

接口要求 `manage_instances` 操作权限，并验证目标实例的分公司在用户授权范围内。部门列表使用现有完整部门字典。通用档案写入和批量维护继续拒绝使用人、部门字段。
