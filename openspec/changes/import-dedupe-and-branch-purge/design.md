# 导入去重 + 三公司清理 — 技术设计

## Context

跨次上传无去重（合单只在单次内）；宁波需保留实例清其余；三分/五分全清。

## Decisions

### D1：指纹小表 ImportFingerprint（transfers app）

`(user FK, sha1 CharField(40), created_at)` + `(user, sha1)` 唯一索引。import_excel 入口：读文件字节算 SHA-1 → 查 24h 内同 (user, sha1) → 命中 400；未命中解析成功后落指纹（解析失败不落——允许修正后重传同内容？失败文件无单据产生，重传无害，不落 ✓）。旧指纹由查询时间窗过滤，无需清理任务（表增长缓慢，500/天级）。

### D2：宁波保留式清理（运维脚本，一次性）

事务内依赖序：
1. 断出生行：宁波实例 birth_line 置 null（services 层函数，架构白名单）
2. 删行实例关联（宁波实例的）→ 删采购单 154 张（此时无 PROTECT 引用）→ 删旧调整单 34 条
3. 每台账行（37 行）逐行补一条期初调整单（is_initial=True，目标列=在库数量 当前值，事由「历史数据吸收：宁波采购单清理」）——对账重放=期初单吸收全部历史 ✓ 实例镜像=台账行不动 ✓
4. 对账验证零差异；序列保留（实例编号连续）

### D3：三分/五分全清（同南京口径）

行实例关联 → 实例 → 单据 → 台账行 → 调整单 → 序列，全删。

### D4：驳回流程已核实无缺陷

approve approved=False 只改状态不触 ledger（数据实证：驳回单台账无行）；②现象随①④消失，不改代码。

## Risks / Trade-offs

- [指纹表新表] — 5 字段小表，不涉铁律（非业务实体，防重传基建）
- [宁波实例失去生平] — 预期（单据已删，生平显示存量档案）；台账保留值

## Migration Plan

代码随部署；生产运维脚本执行后对账验证。
