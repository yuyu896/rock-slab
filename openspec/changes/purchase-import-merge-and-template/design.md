# 导入合单 + 模板瘦身 — 技术设计

## Context

import_excel 循环逐行建单（一行一单）；采购模板 12 列（含名称/金额/经办人）；TYPE_TEMPLATES 驱动模板下载。24 案已定 build 语义化建单与方向（采购→调入）。

## Goals / Non-Goals

**Goals:** 采购/领用导入合单；采购模板 9 列、领用去名称列；经办人=操作人、金额自动算。

**Non-Goals:** 调拨/回收导入不动；导出 Excel 列（回显性质）不动。

## Decisions

### D1：两段式——先逐行解析累积组，再按组建单

循环体保留既有行级校验（分公司/编号/字典/数量），通过后把 `line_kwargs` 按分组键 append 进 `groups[key] = (header_dict, [lines])`；循环后逐组 `Transfer.build + _build_lines(多行)`（行号按组内序）。采购分组键 `(日期, 分公司, 供应商, 需求部门, 备注)`；领用 `(日期, 分公司, 用途, 备注)`；调拨/回收不走分组（维持一行一单，key=None 直接建单）。行级错误计入 errors 不入组——同组天然不受拖累。

### D2：采购模板 9 列与索引

TYPE_TEMPLATES purchase 表头与导入索引同步：`0 日期｜1 分公司｜2 资产编号｜3 规格型号｜4 供应商｜5 数量｜6 单价｜7 需求部门｜8 备注`。名称不读（字典联查）；金额导入时 `Decimal(单价)*数量` 落行（单价空则金额空）；采购经办人=`request.user.name or phone`（不读列）。领用索引左移（删名称列后使用人等 -1）。

### D3：单据编号与通知按组

每组一张单 → 编号生成/通知按组调用；imported 计数改为「成功单据数 + 成功行数」双输出（响应兼容：保留 imported=行数口径？改为 imported=单数, imported_lines=行数——前端展示 errors 为主，兼容加字段）。

## Risks / Trade-offs

- [大文件组合并后明细行很多] — 行数上限校验已覆盖；组内行多无碍（页面同构）
- [分组键含备注差异导致碎单] — 备注行级差异会拆单；文案提示用户保持单头列一致。或分组键去备注？取含备注（备注是单头语义），模板说明提示

## Migration Plan

纯代码；旧模板（12 列）导入新代码：多余列（名称 idx3 等）被新索引错读——**模板变更需通知用户重新下载模板**；导入响应中对「列数>预期」可提示模板过期（不强制）。
