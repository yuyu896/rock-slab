# 实例级供应商覆盖——批量修改只影响勾选台

## Why

批量修改供应商写**出生行**（`birth_line.供应商`），而同一采购行的 N 台实例共享同一出生行（数量 N 的采购行生成 N 台全部指向该行；生产实测最严重一行挂 81 台、前 10 行合计 701 台）。勾选 1 台修改 → 同行全部实例供应商被连带给改——员工"选某几项改，所有供应商都被改"的根因。

## What Changes

- `FixedAsset` 加可选 `供应商` 字段（个体覆盖，记录性档案属性，同 序列号/备注 定位；migration additive）
- 实例供应商派生链改为三级：**实例.供应商 → 出生行.供应商 → 出生单头.供应商**（个体覆盖优先，无覆盖时沿用批次口径）
- `batch-update` 供应商分支改写**实例自身字段**（不再触碰出生行）——勾选谁改谁，同行其余实例不受影响
- 存量数据：已污染的出生行值照旧参与派生（无法区分批次原值与误改值，不回滚）；此后修改走实例字段
- 非目标：出生行/单头供应商语义不变（批次口径）；品目字典不动

## Capabilities

### New Capabilities

（无）

### Modified Capabilities

- `fixed-asset-instance`: 供应商派生三级链 + 批量修改写实例字段

## Impact

- **后端**: FixedAsset 模型（+migration）、序列化派生、batch-update 供应商分支；测试
- **前端**: 零改动（沿用 供应商 派生字段）
