## Context

`Inventory.vue` 在 `triggerImport` 中记录任务 ID、打开原生文件选择器，再通过零延时定时器检查 `input.files`。用户尚在选文件时列表为空，定时器清空任务 ID，`handleImportFile` 随后因缺少任务 ID 直接返回。当前 `importBusy` 同时包含待选任务，并用于禁用文件输入框，进一步混合了选择、确认和上传三个阶段。

隔离 Chromium 中，打开选择器后等待 150 毫秒再选文件，当前代码的确认和上传调用均为零。仅在内存中移除该定时器，同一流程即可触发确认与上传。现有成功测试在打开选择器后立即注入文件，取消测试直接执行定时器，均漏掉真实事件顺序。

业务入口位于 `InventoryTaskList.vue`，有效权限通过 `can('edit_inventory')` 判断，上传经 `importInventoryResult(taskId, file)` 调用 `POST /api/inventories/{id}/import-result`。

## Goals / Non-Goals

**Goals**

- 用户等待任意时长后选文件，确认和上传仍绑定本次点击的盘点任务。
- 取消选择、取消确认、校验失败、请求成功和失败后，用户均能继续操作。
- 确认和上传期间防止重复操作，同一文件再次选择仍可触发确认。
- 通过事件顺序测试覆盖已复现故障。

**Non-Goals**

`.xls` 格式提示、零条导入反馈和大表超时作为独立问题另行评估。本变更聚焦前端文件选择生命周期。

## Decisions

### 分开管理待选目标和提交锁

待选任务 ID 仅记录选择目标，`importBusy` 由确认中、上传中状态计算。文件选择期间保持输入框可用，确认和上传期间禁用导入入口并在处理函数入口检查重复调用。

| 阶段 | 任务和文件 | 导入操作锁 | 文件输入框 |
| --- | --- | --- | --- |
| 空闲 | 无待选目标 | 释放 | 可用 |
| 选择文件 | 保存待选任务 ID | 释放，支持取消后再次打开 | 可用 |
| 确认 | 捕获本次任务 ID 和 File | 持有 | 禁用 |
| 上传 | 使用已捕获的任务 ID 和 File | 持有 | 禁用 |

选择阶段释放提交锁，使未派发 `cancel` 的浏览器在用户取消后也能再次点击任务导入按钮，并以新点击设置待选目标。继续将待选目标计入提交锁会使此类取消留下无法恢复的禁用状态。

### 使用明确事件处理文件选择结束

删除 `importPickerCancelTimer`，选择结果由 `change` 处理，明确取消由原生 `cancel` 处理。取消处理仅在仍等待文件时清理待选状态，确认或上传期间的迟到事件不得清理已捕获的导入上下文。组件卸载时清理当前选择状态。

固定延时、延长现有定时器和仅依赖窗口重新获得焦点，均不能区分用户仍在选择与明确取消，因此不能用于判定选择结束。实施时验证目标浏览器的 `cancel` 行为，并验证未派发 `cancel` 后再次点击仍能恢复。

### 在异步确认前固定本次导入上下文

`handleImportFile` 先检查重复操作和输入有效性，保存本次 `taskId` 与 `File`，再进入确认阶段。用户确认后使用捕获值发起一次请求，确认与上传之间保持操作锁连续。后续选择状态变化不得改写正在确认或上传的任务。

确认取消或关闭时释放操作锁和输入值。请求完成后在 `finally` 中释放状态，沿用现有成功与错误展示。失败后的重新导入由用户重新选择并确认触发。

### 每次打开前和终止后清空文件输入值

每次打开选择器前使用原生支持的 `input.value = ''` 清空文件值，并在取消、校验失败、确认结束和上传结束的相应路径清理。以真实重选验证同一文件仍产生有效的 `change`，替换 `text → file` 类型切换方案。再次上传继续由用户明确确认，后端按既有重复盘点规则处理。

### 回归测试保留文件选择的等待阶段

在 `BatchImportConfirmation.test.ts` 中打开选择器后先执行待处理定时器或等待一个宏任务，再注入文件并派发 `change`，断言出现确认且只向原任务上传一次。取消测试改为派发真实 `cancel` 事件，并补充未派发 `cancel` 后重新打开的路径。

结合参数化用例覆盖台账盘与实例盘入口、同文件重选、跨任务重试、确认取消或关闭、非法扩展名、请求失败、确认中及上传中重复事件。浏览器验证使用正常导入按钮，延迟选文件并检查确认框和请求目标。

## Risks / Trade-offs

- 原生 `cancel` 在目标浏览器中的行为存在差异 → 通过事件验证和未收到 `cancel` 后可重新打开的路径保证恢复能力。
- 文件选择期间错误复用提交锁会禁用输入框或锁死后续点击 → 分别验证选择、确认、上传阶段的输入框及按钮状态。
- 迟到的取消或重复 `change` 影响进行中的请求 → 在确认前捕获导入上下文，并根据当前确认或上传状态守卫事件处理。
- 现有取消测试将定时器执行视为取消 → 替换其事件假设，并保留等待后选择文件的失败回归用例。

## Migration Plan

通过定向前端测试和生产构建后，按项目现有流程发布前端资源。使用盘点中的测试任务验证延迟选文件、取消后再次选择和同文件重选，确认请求的任务 ID 及次数。若出现回归，恢复上一版前端构建产物。

## Open Questions

目标浏览器的原生 `cancel` 事件行为需在实施验证中记录，验证范围以实际使用的浏览器为准。
