## ADDED Requirements

### Requirement: 实例图片压缩与缩略图

系统 MUST 为每个成功上传的新实例图片生成压缩主图和列表缩略图。压缩主图 MUST 使用 WebP，最长边不超过 2048 像素，质量初值为 82；缩略图 MUST 使用 WebP，最长边不超过 240 像素、保持原始比例且不放大，质量初值为 75。系统 MUST NOT 持久化新上传的原始文件。浏览器 MUST 在源图最长边超过 2048 像素或文件超过 1 MB 时先压缩再上传；服务端 MUST 校验实际图片内容和解码像素上限，并为不满足输出约束的客户端输入执行规范化。

服务端保存的原有图片 MUST 保持其文件内容和存储路径不变。图片 API MUST 返回主图 `图片` URL 与可空的 `缩略图` URL；两个非空 URL MUST 包含当前持久化图片版本。

#### Scenario: 新上传保存压缩主图和缩略图
- **WHEN** 用户上传一张符合输入校验的实例图片
- **THEN** 系统保存符合主图尺寸/格式约束的压缩主图和对应缩略图，不保留上传原件，并返回两个带相同当前版本标识的 URL

#### Scenario: 非前端客户端上传超规格图片
- **WHEN** 客户端直接向图片端点提交受支持但超过主图输出约束的图片
- **THEN** 服务端在保存主图和缩略图前将其规范化到规定格式和尺寸，且不保留输入原件

#### Scenario: 既有主图保持不变
- **WHEN** 系统为部署前已有实例图片生成缩略图
- **THEN** 原主图的存储路径、文件内容和图片版本保持不变，API 同时返回原主图 URL 和生成后的缩略图 URL

#### Scenario: 上传处理失败不切换图片
- **WHEN** 新图片解码、规范化或缩略图生成失败
- **THEN** 实例仍引用原主图和原缩略图，且未被引用的新文件被清理

### Requirement: 存量实例图片缩略图回填

系统 SHALL 提供可预览、幂等且可重试的管理命令，为已有实例图片生成独立缩略图。命令 MUST NOT 改写或删除原主图，不得更改图片版本或业务字段；已有缩略图 MUST 跳过；单图失败 MUST 记录在汇总结果中且不得阻止后续图片处理。没有缩略图的实例 MUST 仍可通过主图 URL 展示。

#### Scenario: 回填预览不写文件或数据库
- **WHEN** 运维人员在预览模式运行存量缩略图命令
- **THEN** 命令报告待处理、已存在和不可处理图片数量，不创建、更新或删除媒体文件及数据库字段

#### Scenario: 回填成功并可重复运行
- **WHEN** 运维人员显式执行回填命令并随后再次执行
- **THEN** 首次为缺少缩略图的图片创建缩略图，原主图与版本不变；再次运行跳过已生成缩略图且不重复创建文件

#### Scenario: 部分图片无法生成缩略图
- **WHEN** 批次中某张源图片损坏或不受支持
- **THEN** 命令记录该实例的失败并继续处理其他图片，失败实例仍返回原主图且缩略图为空

## MODIFIED Requirements

### Requirement: 实例图片版本化与安全替换

系统 MUST 为每张实例档案图片提供可识别的持久化版本。每次成功上传或删除图片时，系统 MUST 更新该图片版本；普通档案字段更新 MUST NOT 改变图片版本。非空主图 URL MUST 包含版本标识；存在缩略图时，其 URL MUST 包含相同版本标识。每次成功替换 MUST 返回与替换前不同的主图和缩略图 URL。每次替换 MUST 使用此前未使用的主图及缩略图存储路径，不得因上传文件名相同而覆盖旧文件路径。

图片替换 MUST 先成功保存并验证压缩主图与缩略图，再成功更新档案中的两个引用和版本，最后清理旧文件。若任一新媒体文件保存/处理或档案更新失败，系统 MUST 保留原图片引用及原文件，并清理未被引用的新文件。既有图片 MUST 在首次读取时获得带版本标识的 URL，以避免继续使用未版本化的客户端缓存键。

#### Scenario: 既有图片返回版本化 URL
- **WHEN** 客户端读取已有图片的实例档案
- **THEN** `图片` 字段包含持久化版本标识；若 `缩略图` 非空，该字段也包含相同版本标识

#### Scenario: 同名图片替换生成新 URL
- **WHEN** 用户连续两次上传文件名相同的图片并且两次请求均成功
- **THEN** 第二次响应及后续查询的主图和缩略图 URL 均与第一次不同，且指向同一次上传产生的图片版本

#### Scenario: 任一变体生成失败保留旧图片
- **WHEN** 已有图片的实例替换图片，但压缩主图、缩略图或档案更新任一步骤失败
- **THEN** 档案仍引用原主图和原缩略图，原文件仍存在，未被引用的新文件被清理

#### Scenario: 成功替换后清理旧文件
- **WHEN** 新压缩主图和缩略图保存成功且档案更新事务提交
- **THEN** 档案引用同一新图片版本的主图与缩略图，旧文件随后被清理，客户端可通过新 URL 请求对应变体

#### Scenario: 删除图片后重新上传
- **WHEN** 用户成功删除实例图片，之后再次上传图片
- **THEN** 删除后的档案不返回主图或缩略图 URL，重新上传后的两个 URL 使用高于删除前的图片版本且不同于此前 URL
