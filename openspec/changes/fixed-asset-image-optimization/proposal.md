## Why

实例档案列表目前直接加载原图，生产已有 7,032 张图片、合计约 4.57 GB，页面打开时会为多行图片传输较大的文件。新上传图片也需要统一压缩与缩略图处理，同时保留现有生产原图，降低改造风险。

## What Changes

- 为现有实例图片分批生成列表缩略图，不覆盖或移动生产原图；缩略图缺失时继续回退到原图。
- 新上传图片在浏览器端按需压缩，并由服务端校验及规范化；只保存压缩后的主图和缩略图，不保留新上传的原始文件。
- 图片 API 同时返回主图和缩略图 URL；实例列表按需加载缩略图，点击预览时加载主图。两个 URL 均沿用持久化图片版本标识。
- 图片替换或删除时同步维护主图和缩略图，遵守先提交新引用、后清理旧文件的失败安全约定。
- 修正受信任反向代理之间的协议头传递，确保 HTTPS 页面获得 HTTPS 图片 URL。

## Capabilities

### New Capabilities

（无）

### Modified Capabilities

- `fixed-asset-instance`：定义现有图片保留、新图片压缩存储、缩略图生成、双图片 URL、版本化及文件替换语义。
- `fixed-asset-table-columns`：定义列表按需显示缩略图并在预览时使用主图。
- `nginx-reverse-proxy`：定义代理链保留外部 HTTPS 协议，供 Django 生成正确的绝对图片 URL。

## Impact

- 后端 FixedAsset 图片字段、上传端点、序列化器、图像校验与处理、数据库迁移和存量缩略图生成命令。
- 前端实例档案 API 类型、列表图片加载和预览行为。
- 生产媒体目录会增加存量缩略图；既有原图不变。未来上传仅保存压缩主图和缩略图。
- Nginx 反向代理配置与相关部署验证。
