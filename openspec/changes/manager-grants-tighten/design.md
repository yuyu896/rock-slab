## Context

权限体系口诀「岗位定操作、任命定范围、特例才单独授予」：岗位模板只做分配页预填，运行时鉴权只看 OperationGrant 表与 admin 身份。2026-09-08 批量建号后曾给全员按 8 项模板种授权；09-11 用户拍板分公司行政收紧为 6 项并已在生产数据层完成（113/113 精确收敛），代码模板与门禁（`check_seed_grants` 按模板抽样）仍持旧口径导致 FAIL。

## Goals / Non-Goals

**Goals:**
- 岗位模板 manager 清单 8→6，与生产数据口径一致，门禁转绿
- 模板语义不变：仍仅预填，不参与运行时鉴权

**Non-Goals:**
- 不动 leader（12 项全量，09-08 拍板）/ director（8 项）/ admin 模板
- 不做存量授权迁移命令——生产数据已先行人工收敛，本地开发库将在测试中重建
- 不改前端（预填勾选来自后端岗位目录接口，自动跟随）
- 不改 seed/check 命令逻辑（动态读模板，口径自动对齐）

## Decisions

| 决定 | 理由 |
|------|------|
| 只改 `positions.py` 一处清单 + 测试断言 | 模板是唯一事实源，命令/接口/前端全部派生 |
| 新 6 项集合 = manage_assets / view_audit / view_all_notifications / view_reports / manage_instances / dispose_assets | 用户 09-11 拍板；保留两种批量导入通道（manage_assets），收掉审批/建号/调账，审批流上收组长与区负责人 |
| 测试以 `template_operations('manager')` 断言集合而非逐项硬编码 | 减少下次调整的连带改动面（本次仍需更新硬编码清单处的断言） |

## Risks / Trade-offs

- **审批人力收窄**：113 位分公司行政不再能审批流转/盘点，审批依赖 14 位组长、4 位区负责人与 3 位 admin——用户已拍板接受
- **模板与存量可能漂移**：模板只影响新号预填；若未来手工给个别人加回授权属"特例单独授予"，符合体系设计，不视为漂移
- 回滚简单：还原清单即恢复旧口径，无数据迁移
