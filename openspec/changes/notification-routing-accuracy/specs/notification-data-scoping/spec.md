## MODIFIED Requirements

### Requirement: 通知收件人必须按数据范围授权收敛

审批与抄送通知 MUST 仅发送给对源单据**业务分公司**持有数据范围授权的用户：业务分公司口径为 `Transfer.业务分公司`（采购/归还=调入方，领用/调拨/回收=调出方）或任务 `branch`，即 `resolve_user_scope(recipient).branches` 包含该分公司的用户（admin 与「全部数据」授权者天然覆盖）。不得按角色全量广播，也不得向无权查看该业务数据的用户推送含资产名称 / 编号 / 调出调入分公司的通知明细。**分公司无法解析时 MUST NOT 广播**：仅 admin 与「全部数据」授权者接收。审批结果通知（创建人+自动抄送）在单据生效状态 MUST 触发：`已通过` 与 `已入库`（采购）均按审批通过处理；创建人 MUST 经 `created_by` 外键定位（外键为空的存量单据回退姓名匹配）。自通知排除 MUST 优先按 `created_by_id` 比较。

#### Scenario: 跨区域调拨不通知无关区域审批人
- **WHEN** 区域 A 发起一笔调拨，其调出分公司属于区域 A
- **THEN** 仅授权范围含区域 A 该分公司的用户收到待审批通知；区域 B 的 manager（对该分公司无授权）不收到通知

#### Scenario: director 按授权范围收到通知
- **WHEN** 一笔单据进入待审批，且某 `director` 的 `ManagementScope` 授权包含该分公司
- **THEN** 该 director 收到通知；授权范围不含该分公司的 director 不收到

#### Scenario: Web 采购按调入方路由不广播

- **WHEN** 用户经 Web 建采购单（仅提交调入分公司，调出分公司为空），该单进入待审批
- **THEN** 授权范围含**调入方**分公司的审批人收到待审批通知；范围不含调入方的其他分公司审批人不收到（不再全量广播）

#### Scenario: 采购审批（已入库）结果通知照常

- **WHEN** 审批人通过一笔采购单（状态置「已入库」）
- **THEN** 创建人（经 created_by 定位）收到审批结果通知，持 `view_all_notifications` 且范围覆盖调入方者收到自动抄送

#### Scenario: 重名用户不错收结果通知

- **WHEN** 单据创建人与另一用户同名，审批通过
- **THEN** 仅 `created_by` 指向的用户收到结果通知，同名他人不收到
