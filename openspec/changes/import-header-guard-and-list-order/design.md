# 表头守卫 + 键瘦身 + 列表排序 — 技术设计

## Context

生产：旧模板可传（无表头校验）→ 错位解析 → 分组键散 → 一行一单"复发"；分组键含备注放大拆单。采购列表默认按日期倒序，待审批散落。

## Goals / Non-Goals

**Goals:** 表头集合校验快速失败；分组键去备注；采购列表待审批置顶+分公司排序。

**Non-Goals:** 列序容错（集合一致但顺序不同——Excel 列序无约定意义，按名读列可支持？本期严格集合校验，顺序不敏感因解析按索引……矛盾：解析按索引取列！表头顺序不同索引即错。**表头须顺序一致**？——按名定位列索引更健壮：解析前建 name→idx 映射，`_cell(row, '分公司')` 按名取——彻底免疫列序。本期实现按名取列+集合校验，一步到位）。

## Decisions

### D1：按名取列 + 表头集合校验

解析前读首行建 `col_map = {表头名: idx}`；校验 `set(col_map) == set(TYPE_TEMPLATES[type]['headers'])`，不等即 400。所有 `_cell(row, idx)` 改 `_cell(row, '列名')`（内部查 col_map）。顺序免疫+旧模板拒绝双达成。

### D2：分组键去备注

purchase 键 `(日期, 分公司, 供应商, 需求部门)`；assign 键 `(日期, 分公司, 用途)`。备注 = 组内首行 header 的备注（累积时首个生效）。

### D3：采购列表前端排序

PurchaseList 拿到 results 后 computed 排序：状态优先级（待审批=0，草稿=1，其余=2）→ 分公司名 → 日期倒序。仅采购页（其他列表不动）。

## Risks / Trade-offs

- [表头重名/多余空列] — trim 处理；空表头列忽略
- [前端排序与分页交互] — 当前页内排序（后端分页不变）；待审批总量多时跨页仍需翻——可接受（用户要"前面"即页内优先）

## Migration Plan

纯代码；部署后旧模板上传立即被拒（预期行为，通知员工）。
