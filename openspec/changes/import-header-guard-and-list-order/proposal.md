# 导入表头守卫 + 合单键瘦身 + 采购列表排序

## Why

生产实证三个问题同源/相关：① 旧 12 列模板仍可上传（导入无表头校验），错位列值把分组键打散——表现为"两行仍生成两单"；② 分组键含备注，两行备注不一致即拆单（生产"同键 2 张"痕迹）；③ 采购列表乱序，待审批单散落难找。

## What Changes

- **表头守卫**：导入逐类型校验首行表头与 TYPE_TEMPLATES 期望表头一致（按集合比较，忽略列序差异时？——严格按表头集合匹配，多余/缺失列即 400「模板已更新，请重新下载」快速失败，杜绝旧模板乱数据
- **合单键瘦身**：采购分组键 `日期+分公司+供应商+需求部门`（**去备注**，备注取组内首行）；领用 `日期+分公司+用途`（去备注同理）
- **采购列表排序**：待审批在最前，其余按分公司名+日期倒序（前端列表内排序，不动后端全局 ordering）
- 非目标：调拨/回收导入（一行一单不变，但表头守卫同样覆盖）；后端 API 排序参数不加

- 生产运维：通知员工旧模板彻底作废（上传即被拒并提示重新下载）
