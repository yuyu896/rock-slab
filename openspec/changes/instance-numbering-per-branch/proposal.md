# 实例编号按分公司发号 + 领用单实例单台选择

## Why

实例内部编号现为全局序列（品目跨所有分公司共用计数器）：序号被拉到 400+ 甚至 1228，且用户从编号看不出实例归属哪家分公司。正式使用要求编号可辨识归属、序号短。另：领用出库的实例选择当前支持一行多选多台，但实例管理物品的出库要求实例与使用人一一对应——一行多台对应一个使用人的形态没有必要且易错。

## What Changes

- **编号格式**：`{品目编号}-{分公司代码}-{分公司内序号}`（如 `A-a00007-JH002-1`）；`InstanceSequence` 从「品目一行」改为「品目 × 分公司」一行（锁行自增机制不变），每分公司每品目从 1 起号；全局唯一性保持（代码入编）
- **存量重编号**：一次性命令把存量实例（生产=金华 75 台）按新格式重排（同品目按现有编号序从 1 顺序重编），单据关联/序列号补录/图片随实例对象自动跟随；执行后需重打标签
- **领用单实例单台**：领用出库明细行实例选择改**单台**——一行 = 一个使用人 = 一台实例（数量恒 1，锁定），多台/多人则多行；点选即选、不再多选勾选。调拨/归还/回收的实例选择维持多选（无使用人对应约束）
- 非目标：调拨/归还/回收选择形态不变；编号展示、扫码查询、导出列均无需改（编号仍是字符串唯一键）

## Capabilities

### New Capabilities

（无）

### Modified Capabilities

- `fixed-asset-instance`: 内部编号锁行发号要求改为品目 × 分公司矩阵 + 新格式 + 存量重编号
- `transfer-create-pages`: 领用明细行实例选择改单台（一行一使用人一实例，数量恒 1）

## Impact

- **后端**: `InstanceSequence` 模型改造（item OneToOne→FK + (item, branch) 唯一，migration）、`_next_seq`/`generate_instances`（分公司维度+新格式）、`renumber_instances` 重编号命令（预览/确认）
- **前端**: `InstancePicker` 加单选模式（assign 专用）、`TransferLinesEditor` 领用行数量恒 1 与提示
- 生产：部署后执行重编号（金华 75 台）
