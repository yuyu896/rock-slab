# 设计：移动端安装向导页 + PC 工作台安装二维码

## Context

移动端已是扫码终端（/mobile/scan 落地），PWA 基础设施（manifest/图标/MobileLayout 安装横幅）已上线。缺的是"最后一公里"：把任意员工从"拿到一个链接"带到"桌面有图标"。iOS 无任何程序化安装口子、微信内无法安装、安卓自动横幅依赖有效证书——向导页的本质是把这些环境差异翻译成傻瓜步骤。

## Goals / Non-Goals

**Goals:**

- 一码发全员：扫码后按设备自动显示对应步骤，微信先引导跳出
- 安卓 Chrome 一步安装按钮；其余环境图文步骤兜底
- PC 工作台提供二维码分发入口，本地/生产自适应
- `/install` 公开可访问（登录前完成安装动作）

**Non-Goals:**

- 不做 APK 下载（将来到货后向导页替换步骤区即可，结构预留）
- 不做截图素材的自动化生成（首版用文字+图标示意，真机截图后补）
- 不做服务端统计"安装数"

## 页面形态（/install）

## Decisions

**D1：环境识别用 UA + 事件可用性双信号**

`isWechat = /MicroMessenger/i.test(ua)`、`isIos = /iphone|ipad|ipod/i.test(ua)`；安卓 Chrome 的判定交给 `beforeinstallprompt` 是否触发（300ms 内未触发即回退菜单图文步骤）。国产厂商浏览器 UA 杂乱，不逐一识别，统一走"菜单 → 添加到主屏幕"图文兜底。

**D2：二维码运行时生成，指向 `location.origin + '/install'`**

Dashboard 卡片用现有 `qrcode` 库 `toCanvas` 渲染（180×180 含白边）：本地测试扫出本地地址、生产扫出生产域名，一套代码两端自适应，无需静态图片资产。

**D3：`/install` 为顶层公开路由**

与 `/login` 同级（不在 MainLayout/MobileLayout 内），自带极简页头；`meta: { requiresAuth: false, title: '安装磐盘' }`。「打开磐盘」跳 `/mobile/scan`，登录守卫自动接管未登录用户。

**D4：向导页与 MobileLayout 安装横幅职责分工**

横幅面向"已在使用中"的用户（可关闭）；向导页面向"第一次"的用户（专职引导、含打开入口）。两者复用同一 `beforeinstallprompt` 事件源但互不依赖。

## Risks / Trade-offs

- [国产浏览器添加桌面入口路径各异] → 文案写通用表述（浏览器菜单里的"添加到主屏幕/添加桌面"），真机反馈后细化
- [微信跳浏览器后 UA 变化需重新识别] → 跳出后页面重新加载，识别逻辑自然重跑，无需处理
- [首版无真机标注截图] → 图文用图标+文字描述，保证流程可走；截图素材后续补上更佳
