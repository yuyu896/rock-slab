## ADDED Requirements

### Requirement: 盘点任务详情页物品明细表

盘点任务详情页 MUST 展示物品明细表，列至少包含：资产编号、资产名称、应盘数量、实盘数量、差异、结果、备注；差异 MUST 带方向标记（盘盈为正/绿、盘亏为负/红），未盘点项实盘显示未盘。明细数据 MUST 与盘点报告接口同源（同一任务的 items 全量），未开始（无盘点项）时 MUST 显示空态提示而非空白表格。

#### Scenario: 查看进行中任务的物品明细

- **WHEN** 用户打开一个已开始、部分品目已盘（其中一项应盘 5 实盘 3）的盘点任务详情页
- **THEN** 物品明细表列出全部盘点项，已盘项显示实盘数量与结果，差异项显示 −2 且标红，未盘项实盘列显示未盘

#### Scenario: 未开始任务明细空态

- **WHEN** 用户打开一个 pending 状态（尚未生成盘点项）的任务详情页
- **THEN** 物品明细区显示空态提示（盘点开始后生成物品清单），不渲染空表格

### Requirement: 按人盘点流水视图

盘点任务详情页 MUST 展示盘点流水视图：逐条列出盘点记录（盘点时间、盘点人、资产编号、资产名称、数量、设备），数据取自任务 checks 接口；用户 MUST 能按盘点人筛选流水（含"全部"）。checks 接口 MUST 支持按 checked_by（用户）过滤，且每条记录 MUST 返回展示字段：盘点人姓名（checked_by_name）、资产编号（asset_code）、资产名称（asset_name）——仅回 UUID 不可接受。手机扫码页最近记录 MUST 使用同一展示字段渲染，MUST NOT 引用接口不返回的字段。

#### Scenario: 按盘点人筛选流水

- **WHEN** 任务由张三、李四两人分别提交过盘点记录，用户在流水视图选择盘点人"张三"
- **THEN** 列表仅显示张三的盘点记录（服务端按 checked_by 过滤），切换"全部"恢复全量

#### Scenario: 流水记录含展示字段

- **WHEN** 客户端请求任务 checks 接口
- **THEN** 每条记录返回 checked_by_name、asset_code、asset_name（非 UUID），手机扫码页最近记录渲染出编号、名称、数量、时间而非空白

#### Scenario: 无盘点记录空态

- **WHEN** 任务尚无任何盘点提交，用户查看流水视图
- **THEN** 显示空态提示，不渲染空表格

### Requirement: 详情页无效操作控件清除

盘点任务详情页 MUST NOT 存在无事件绑定的操作控件：「继续盘点」死按钮 MUST 删除（继续/重盘的有效入口维持任务列表行操作不变）；保留的「导出报告」按钮 MUST 绑定有效下载行为。此后详情页新增操作控件 MUST 有有效绑定或不予上线。

#### Scenario: 详情页无死按钮

- **WHEN** 用户打开任意状态的盘点任务详情页
- **THEN** 页头操作区只有「导出报告」且点击触发报告下载，不存在「继续盘点」按钮；重盘入口仍仅出现在任务列表行
