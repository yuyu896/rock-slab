## ADDED Requirements

### Requirement: 台账导入确认的原子性与现值复核

台账增量导入的确认阶段（confirm）MUST 在单个数据库事务内完成全部差异的应用与调整单留痕：任一行失败（数量不足或现值漂移）时整体回滚，MUST NOT 留下部分调整或残留调整单。确认 MUST 在锁定全部涉及台账行后、逐行应用前复核**当前现值等于解析阶段的快照值**，不相等时 MUST 返回 400（code `IMPORT_STALE`，错误信息含行号、品目编号与分公司定位）且不应用任何行。调整单事由中的数值口径 MUST 与真实应用前值一致。加锁顺序 MUST 与流转生效路径的全局序一致（按分公司×品目排序锁齐）。

#### Scenario: 中途失败全部回滚

- **WHEN** 确认应用两行差异，第二行应用失败（如联动后为负）
- **THEN** 返回 400，第一行也未应用，台账无变动，不产生任何调整单

#### Scenario: 解析与确认之间的并发变动被拒

- **WHEN** 差异预览后、确认前，该台账行被其他操作变动（当前值 ≠ 解析快照）
- **THEN** 确认返回 400 IMPORT_STALE（含行号定位），台账保持并发后的值不被覆盖，重新上传解析后可正常确认

#### Scenario: 正常确认全量应用

- **WHEN** 确认时所有行现值与解析快照一致
- **THEN** 全部行按差量应用（响应 applied=行数），每行生成调整单，事由数值与真实前值一致

#### Scenario: 重复上传同一文件

- **WHEN** 同一导入文件确认成功后再次以 confirm 上传
- **THEN** 第二次因现值已变（或差量为零）不产生新的台账变动，不出现重复调整
