## Context

资产汇总台账每行对应一个分公司和品目，数量由在库、在用、回收库三列组成，总量由三列相加得到。当前台账页和 Excel 导出都使用资产汇总查询，但该接口也供物品选择器、移动端盘点及其他业务流程使用；全局改变接口默认结果可能让这些流程漏掉仍需处理的记录。

后端现有 `positive_column` 筛选支持逗号分隔的多列 OR 条件。台账数量通过统一服务维护，服务会拒绝将数量变为负数，因此任一列大于 0 等价于总量大于 0。

## Goals / Non-Goals

**Goals:**

- 台账列表与 Excel 导出均排除三项数量全为 0 的记录。
- 在库为 0，但在用或回收库仍有数量的记录继续显示。
- 仅改变台账页面和导出的查询结果，保持其他资产汇总接口调用方的默认行为。

**Non-Goals:**

- 不删除台账记录，不改写库存数量、单据或历史流水。
- 不修改资产汇总接口对其他调用方的默认查询行为。
- 不增加数据库字段或数据迁移。

## Decisions

1. **由台账页请求显式启用数量筛选。** 列表请求和导出请求都传入 `positive_column=在库数量,在用数量,回收库数量`，利用现有多列 OR 筛选。三项数量均为 0 的行会被排除；任一列仍有正数的行会保留。筛选在分页计数之前执行，因此总数和分页结果对应过滤后的台账。
2. **保持通用接口默认行为。** 物品选择器、移动端和其他共享接口调用不传该筛选参数，仍取得原有结果。将零总量过滤设为接口全局默认值会超出需求范围，并可能影响这些工作流。
3. **导出复用列表筛选口径。** 导出请求携带与列表相同的数量条件及当前业务筛选条件，使下载内容与用户在台账页查询的范围一致。
4. **保留记录与历史。** 此变更只影响查询呈现，不触碰台账模型、数据库记录和历史单据；需要追溯时仍可通过既有记录与流水查看。

## Risks / Trade-offs

- [列表与导出漏传或使用不同数量条件] → 前端复用同一数量筛选常量，并分别测试列表和导出请求。
- [误将所有在库为 0 的记录过滤] → 使用三项数量的 OR 条件，覆盖在用或回收库仍有数量的情形。
- [共享接口调用方意外受影响] → 将筛选设为台账页请求的显式参数，并验证未传参数时默认结果保持不变。

## Migration Plan

无需数据库迁移或生产数据清理。部署应用代码后，台账列表和导出立即按新规则查询；回退应用代码即可恢复原展示行为。
