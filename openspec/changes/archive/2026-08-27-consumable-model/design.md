## Context

- 管理方式两档（quantity/instance）贯穿：字典 choices、`_line_plan` 联动矩阵（与对账命令同源 import）、预检矩阵、前端各处 `=== 'instance' ? '实例管理' : '数量管理'` 二元展示。
- 生产 B 类（低值易耗品类）品目大量挂在库（纸杯 900/6000 等）与在用（印泥 +6、纸巾 +240 等，来自 08-23 期初单）。
- 字典页有「管理方式切换须无存量」锁（挂实例或任一列非零即锁，serializer 层校验 `management_locked`）。
- 对账命令以流水重放推期望值：期初单吸收历史、期初后生效单据按 `_line_plan`（读**当前**管理方式）重放。

## Goals / Non-Goals

**Goals:** 管理方式三档；消耗品领用 = 耗用发放（在库−N 总量降，不进在用）；回收/归还/回收库来源对消耗品关死；存量 B 类经预览清单迁移。

**Non-Goals:** 不做部门消耗统计报表（修宪提及"可出"，另案）；不改采购/调拨/盘点对消耗品的行为（天然兼容）；不放松字典页切换锁（存量切消耗品统一走迁移命令，页面对既有品目维持锁约束）；不迁移实例管理 B 类（人工决断）。

## Decisions

1. **矩阵只分流 assign 一处**：`_line_plan` 的 recovery/return 分支不动（消耗品新建这两类单在预检层拒绝，历史单重放口径不变）。选预检拦截而非矩阵拒绝的理由：预检三路径（表单/编辑/导入）同口径收口，且生效层保持"矩阵与历史重放稳定"。
2. **对账等价性论证**：quantity→consumable 迁移时若该品目在用=0——在库/回收库列新旧矩阵重放相同（assign 两矩阵都在库−N）；在用列新矩阵贡献 0、台账实际 0，等价。故迁移的硬门槛 = 在用=0；回收库非零同样拦（消耗品无回收语义，余额会成为死数），双零才迁。
3. **迁移命令直改模型字段**（`.update(management_type=...)`），绕过 serializer 的切换锁——锁防的是 quantity↔instance 互切破坏实例镜像，quantity→consumable 在双零门槛下无镜像/对账风险；页面对既有品目维持锁（不放松），存量切换唯一入口是命令（预览→确认），与 migrate_positions 同运维风格。
4. **领用来源约束**：领用来源是单头字段；消耗品行 + 来源=recycle_bin 在预检拒绝（"消耗品无回收库存可领"）。单据可混合行（消耗品行与数量/实例行同单），仅行级分流。
5. **预检文案兼容三档**："数量管理品目无需选择实例" → "非实例管理品目无需选择实例"（预检与终检两处）。
6. **前端统一标签映射**：`MANAGEMENT_TYPE_LABELS`（数量管理/实例管理/消耗品）进 constants，替换全部二元判断；ItemPicker 候选行 meta 显示三档标签；领用编辑器对消耗品行显示"耗用发放"提示（领出即消耗、不进在用、不可回收）。

## Risks / Trade-offs

- [迁移后历史 B 类在用余额品目被跳过，账上仍是"在用"] → 命令明确列出待处理清单与指引（先调整归零再迁）；不自动改账（铁律 2：数量变动走单据，人工决定归零方式）。
- [混合单（同单数量品目+消耗品行）语义复杂] → 行级分流天然支持，明细行各自按品目矩阵走，报告/对账按行累计不受影响。
- [用户在字典页新建品目误选消耗品] → 表单档位说明文案（领出即消耗、不可回收）；无存量时可自由改回（锁不触发）。

## Migration Plan

1. 代码部署（migration 纯 DDL choices 扩充，对数据零影响）。
2. 服务器 `python manage.py migrate_consumables`（dry-run）核对清单——重点看"需先归零"名单。
3. 确认后 `--apply`；再次 dry-run 应显示无可迁移项。
4. 回滚：代码回滚即可；已迁品目如需回 quantity，在双零状态下页面可改（锁不触发）或再跑命令（无反向命令，页面改）。
