# 分公司排序治理 + 筛选多选 + 采购单排序核查

## Why

用户反馈三件事：①分公司（下拉/字典各处）排序"有点乱"；②分公司筛选只能单选，需要多选；③采购入库单排序逻辑需要核查是否合理。本变更**先核查后定案**——以下为 2026-09-22 调查结论，修改方案待用户拍板后补 design/specs/tasks。

## 调查结论

### ① 分公司排序现状——乱在"编码失控"，不在排序代码

排序链路全系统唯一依据：`Branch.Meta.ordering = ['code']`（编码字典序）；组织树按 Region(code) → Team(name) → Branch(code)。排序代码本身一致，**乱源是 72 家分公司的编码本身**（生产实据）：

| 失控表现 | 实例 |
|---|---|
| 前缀风格不统一 | 城市缩写 CZ031（常州）vs 城市全拼 JIN351（济南） |
| 数字位语义混载 | BJ001=北京流水号；FZ028 的"28"=28分福州**店号**；CD039 的"39"=39分成都店号；HZ235=杭州235公共物资 |
| 测试数据混入生产 | CS002 测试二公司、CS003 测试分公司仍在册 |
| 显示与排序脱钩 | 界面显示分公司**名称**，顺序却按 code——名称拼音序 ≠ code 序，肉眼看似随机 |

### ② 分公司筛选现状——单选、名称值、九页共用

- 前端 [BranchFilterSelect](../../../frontend/src/components/BranchFilterSelect.vue)：ElSelect **单选**（可搜索/可清空），值语义 `''=全部 / 分公司名称`；消费方 **9 个页面**（采购/领用/调拨/回收单/回收台账/资产台账/实例档案/盘点任务/调整记录）
- 后端 [filters.py](../../../backend/apps/transfers/filters.py)：`toBranch = CharFilter(field_name='调入分公司')` 精确单值匹配；多选需改 `__in`，且各页筛的字段不同（调入/调出/所属），需逐页核对

### ③ 采购入库单排序现状——两层语义叠加

- **后端（决定翻页边界）**：`-调拨日期, -created_at` 纯日期倒序
- **前端（页内重排）**：待审批置顶 → 草稿 → 其余；同组内按调入分公司名（zh 拼音）→ 日期倒序
- 潜在问题：(a) 状态置顶仅页内有效——第 2 页可能出现待审批而第 1 页末尾是已入库；(b) 按分公司名排序对只看本公司的经办人无意义，对 admin 才有意义

## What Changes

用户四项拍板（2026-09-22）：

1. **分公司选项全站按名称拼音排序**（前端 localeCompare 收口；不动编码数据，测试公司保留）
2. **分公司筛选改多选**（组件 ElSelect multiple；值沿各页现状口径仅单值→多值；逗号分隔传输→后端 `__in`）
3. **采购/五单据列表统一后端排序**：待审批→草稿→其余 + 日期倒序，跨分页一致，前端删页内重排；分公司名退出排序键（用户选定五类型一致方案）

## Capabilities

### New Capabilities

（无）

### Modified Capabilities

- `branch-filter`: 筛选命中单值→多值（资产/流转两条需求修订）；新增「分公司选项按名称拼音排序」
- `split-transfer-pages`: 新增「流转列表统一排序」（五类型后端置顶+日期倒序）

## Impact

- 后端：transfers 列表排序注记、各 filterset 分公司过滤多值化（transfers/assets/inventories 逐一核对口径）
- 前端：sortBranchesByName 工具、BranchFilterSelect 多选化、9 个消费页透传、创建页下拉与组织树排序、PurchaseList 删页内排序
- 零数据变更：不治理编码、不迁库、测试公司不处理
