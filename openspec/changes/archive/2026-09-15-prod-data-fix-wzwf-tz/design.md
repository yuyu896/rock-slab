## Decisions

### D1. 删错误单据的回账方式：应用之逆（同事务直减台账），不走调整单补偿

删除温州 138 张单 / 台州 2 张单时，同时**直接**把对应 (分公司×品目×列) 的存储值减去这些单据的入账量。

- 为什么不用 `apply_adjustment(−N)` 补偿：补偿单会让流水 = 存量单据(已删) 与调整单(−N) 不再解释存储值——删单后 replay 里已无 +N，再挂 −N 调整单反而制造 −N 的对账差异。保留单据不删、只挂 −N 调整单虽可对平，但采购列表仍留错误单，与"清空重导"的目标矛盾（用户已确认连单删）。
- 铁律 2 的立法本意是"每一次数量变动都能被单据流水解释"。删错误单 + 同额回退存储值 = 该单"从未存在"，剩余流水依然完整解释剩余存量，不变量零差异——这是"应用之逆"，与既有先例 `purge_business_data`（整删单据与台账）同一法理。
- 实现上回退仍收敛在命令内以 `_line_plan` 同源矩阵计算回退量，杜绝手算口径漂移。

### D2. 潍坊合并：引用改挂 + 硬删节点，而非调拨单

- 调拨单方案无法交付目标：历史单据 PROTECT 使节点删不掉，只能停用；而组织/台账/报表视图均无 status 过滤，停用节点照样出现在架构里。
- 改挂方案：二分的 4 张采购单（`to_branch` FK + 单头文本"调入分公司"同步改文本）、75 张调整单（`branch` FK）、75 行台账（与分公司品目全交集 → 数值相加进分公司行、删二分行）同批迁移。存储值与流水**同侧同迁**，replay(潍坊分公司) 与 stored 同步增长——对账不变量保持。
- 单头文本字段（调入分公司/调出分公司）是展示冗余，必须与 FK 同改，否则列表页显示旧名。
- 部门字典：二分 6 条与分公司 6 条同名（uniq branch×name），且零引用（单据行/实例均无），直接删除二分侧。
- 员工朱鑫丽：`branch` 改挂 + 其 `ManagementScope(branch=二分)` 改挂潍坊分公司（与黄琪的授权叠加，二人共管，符合授权可叠加设计）。
- 删除顺序：先迁移全部引用 → 复核二分零引用 → 删节点。命令内以"引用清零断言"门禁，不为空即中止。

### D3. 删除顺序与事务边界

- 实例删除顺序：`TransferLineInstance`(链接) → `FixedAsset`(实例) → `Transfer`(单头, 级联明细行)。实例的 `birth_line` 指向明细行，先删实例才能 CASCADE 删行。
- 通知清理：`related_object_id in (被删单据 id)` 且 `related_object_type` 为单据类型的记录同批删除（防悬空引用出现在通知中心）。
- 每案一个 `transaction.atomic()`，案间独立（一案失败不连坐另案）。对账复验在三案全部提交后统一执行一次（读同库数据，无跨库问题）；若复验发现差异则 exit 1 暴露，恢复走备份还原。

### D4. 形态：management command + dry-run，参数写死

- 参照 `seed_position_grants`/`purge_business_data` 先例：`python manage.py prod_data_fix_20260914 [--apply]`，默认 dry-run 打印逐项计划（删哪些单号/实例编号/台账回退量/改挂明细）。
- 数据点（分公司名、单号、品目回退量）以常量固化在命令里，不做成参数化工具——避免"通用删数据入口"变成铁律旁门。
- 上线执行链：备份 → dry-run 人工复核 → `--apply` → 对账零差异 → 健康检查。

## Risks / Trade-offs

- [执行中瞬间故障留下半程数据] → 案级 atomic + 幂等设计（重跑只处理仍存在/仍指向旧值的数据），dry-run/apply 均可安全重复
- [回退量与实删单据不符（数据在写脚本与执行间又变了）] → 命令运行时**实时**从待删单据的明细行计算回退量，不用调研快照的静态值；执行前断言前置条件（单据状态=已入库、实例计数=镜像值、库存充足不为负）
- [潍坊台账合并后单行数量与直观预期不符引发质疑] → dry-run 输出合并前后对照表（品目×两行原值→合并值）留档
- [员工重导温州数据时撞内部编号] → 实例发号行（item×branch）不清零，序号继续自增，重导编号只会更大不会重号
- [误操作] → 生产执行前 `backup_db.sh` 即时备份（deploy.sh 同款），SQL 级可整体还原；单号/分公司名等常量执行前再核对一遍
