## Context

- 上次 `fix-branch-filter` 把资产筛选改成「前端发 code + 后端按 `分公司编号` 过滤」。
- 但 `import_excel`（`views.py:213`）`分公司编号=str(cell(row,'分公司编号'))`——**从文件读用户手填值**，与 Branch.code 常不一致。
- 单条创建由 `AssetSerializer.create`（`serializers.py:55-56/62-63`）按分公司名反查 Branch、回填 `分公司=branch.name / 分公司编号=branch.code`，**正确**。
- 因此按编号过滤：单条创建资产命中、导入资产不命中。线上多数资产来自导入 → 筛选大面积失效。
- `分公司`(名称) 在创建（select 发名）与导入（按名登记 + `branch_validation_error` 校验存在）均可靠为真实分公司名。
- 固定资产 `分公司编号` 继承自父资产（`FixedAssetSerializer.create`），父资产编号错则子亦错——同样问题，按名称过滤一并解决。

## Goals / Non-Goals

**Goals:**
- 资产/固定资产分公司筛选对**创建+导入**两种来源都可靠命中。
- 导入回填正确分公司编号，消除该字段不一致。

**Non-Goals:**
- 不改流转筛选（上次已按名称修好、正常）。
- 不回填历史资产分公司编号（仅影响该列展示，可选）。
- 不改单条创建路径（其编号本就正确）。

## Decisions

### 决策 1：按分公司「名称」过滤（而非编号）
- **做法**：`AssetFilterSet`/`FixedAssetFilterSet` 的 `branch` 字段由 `分公司编号` 改为 `分公司`；前端下拉值 `b.code`→`b.name`。
- **理由**：名称在所有来源一致可靠（创建/导入均按名登记且校验）；编号对导入不可靠。按名称过滤**立即对全量（含历史）资产生效**，无需数据迁移。
- **备选**：保持按编号过滤 + 导入派生编号 + 回填历史编号——需数据迁移、且历史须回填才立即生效，**否**。

### 决策 2：导入由名称反查回填分公司编号 + 模板去该列
- **做法**：`import_excel` 第 213 行改为按已校验的分公司名反查 Branch、回填 `分公司编号=branch.code`（不再读文件）；导入模板表头去掉「分公司编号」。
- **理由**：消除编号不一致（数据质量），与序号/警戒线「系统派生、不入模板」一致。

## Risks / Trade-offs

- **[按名称理论上同名歧义]** 分公司名可能重名 → **缓解**：分公司名受控、实践中唯一。
- **[历史编号展示不符]** 旧导入资产分公司编号仍可能错 → **缓解**：筛选已按名称、不依赖编号；编号展示可选回填（Open Questions）。

## Migration Plan

1. 后端：过滤字段改名称；导入回填编号 + 模板去列。
2. 前端：下拉值改 `b.name`。
3. 纯前后端逻辑，**无 DB 迁移**；按名称过滤部署后立即对全量资产生效。
