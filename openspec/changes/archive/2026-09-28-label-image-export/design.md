# 设计：标签导出图片（打印第二通道）

## Context

V1 标签规范已实施：60×40 单签（QR 左/文字右、mm 字号、防越界）+ A4 双列，浏览器打印管线就绪。用户侧硬件是汉印 M1 蓝牙标签机（App 生态、无 Windows 驱动，实测装 60×40 热敏纸），各分公司将推广同类机器。此类机器的共性出口是"App 打印相册图片"。

## Goals / Non-Goals

**Goals:**

- 每张标签导出为独立 PNG，版式/内容/QR 参数与打印通道完全同规范（60×40、QR 13mm ECC M、三区文案、SN 空隐藏）
- PNG 在 203dpi 热敏机上清晰可扫（超采样），在手机上可长按保存
- 单张下载与全部下载两种取图方式
- 不引入新依赖

**Non-Goals:**

- 不做 zip 打包（多一张签一个文件，浏览器授权一次即可；引入 JSZip 不值得）
- 不做 Web Bluetooth 直连（将来单独立项）
- 不做 50×30 等其他尺寸预设（M1 实测 60×40 可用）
- 不改打印通道任何行为

## Decisions

**D1：canvas 直绘，不引 html2canvas 类库**

标签版式简单（QR + 四行文字），用 Canvas 2D 手绘完全可控：`qrcode` 包自带 `toCanvas`（画 QR 到离屏 canvas 后 drawImage），文字用 canvas fillText。mm→px 换算 `mm * dpi / 25.4`。

- 备选 html2canvas 截取 DOM：多一个依赖、mm 单位与字体渲染保真度不可控、暗色模式下取色风险，否决。
- 代价：版式参数在 CSS 与 canvas 两处各一份——用共享常量对象（`utils/labelImage.ts` 导出 `LABEL_SPEC`：边距/QR 尺寸/字号/颜色）收敛，打印 CSS 侧注释指向同规范。

**D2：960×640 超采样（203dpi × 2）**

60×40 @203dpi = 480×320；×2 超采样后 QR 模块边缘在缩放到物理点时更圆润，300dpi 机器也不过采样不足。PNG 白底黑字黑边框，导出即所见。

**D3：导出交互——预览即取图**

「导出图片」不直接下载 N 个文件，而是把渲染结果作为 `<img>`（canvas.toDataURL）列在弹窗内新开的导出视图：
- 每张下方「下载」按钮（`a[download]`，文件名 `标签_<内部编号>.png`）
- 顶部「全部下载」逐张触发（Chrome 首次弹"允许下载多个文件"授权一次）
- 手机浏览器：长按图片即可存相册——这正是印条类 App 取图的路径，无需任何按钮
- 备选「静默全部下载」：跳过预览少一步，但手机端多个下载项不如长按相册直观，PC 端预览也能当核对清单，选预览方案。

**D4：canvas 侧缩号规则与打印一致**

行宽超可用宽度时降字号（步进 0.1mm、下限 2.2mm），用 `ctx.measureText` 测量——比 DOM 的 scrollWidth 更精确。SN 空则整行跳过、后续行上移。

## Risks / Trade-offs

- [canvas 字体与打印 CSS 字体渲染差异（抗锯齿/字重）] → 视觉上轻微差异可接受；字号与几何参数一致保证信息布局相同
- [全部下载被浏览器策略拦截] → 授权提示一次后放行；预览页保留单张下载兜底
- [手机相册打印时 App 强制缩放] → 提示文案注明"App 内选择原尺寸 60×40"
