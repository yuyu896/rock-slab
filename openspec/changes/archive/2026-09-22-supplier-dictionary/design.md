## Context

字典哲学：品目身份在字典（Category）、部门扁平化已定案、供应商同理全集团一套（各分公司大差不差、量少）。行级供应商字段已存在（TransferLine.供应商，"行级，空=继承单头"——表头界面已移除仅存量兼容）。导入流建行时供应商来自 Excel 文本。

## Goals / Non-Goals

**Goals:** 供应商身份有唯一字典源；建单只准选；admin 统一维护；存量与导入路径零破坏。

**Non-Goals:** 不做存量归一（报表只统计新单，另案）；不在 API 层强校验供应商值（导入路径依赖自由文本）；不做供应商维度报表/历史价（后续立项）；不做联系人之外的字段（账期/资质等企业级功能明确不做）。

## Decisions

| 决定 | 理由 |
|------|------|
| `TransferLine.供应商` 继续存名称文本，不 FK 化 | 展示兼容最大化（存量/导出/导入全不动）；字典是身份源、行上是记录性快照——同「创建人」模式，不违反铁律 1 |
| API 读开放、写收 admin | 全员建单要读选项；字典维护收口系统管理员（用户拍板），后续权限细化另案平移 |
| 下拉用朴素 `<select>`（不做可搜索组件） | 量少（十几~几十），原生下拉足够；与朴素表格偏好一致；量大再升级可搜索 |
| 管理页挂组织架构组（部门字典下方） | 用户拍板：字典归拢组织架构组 |
| 新建独立 app `apps/suppliers` | 镜像 categories 等小 app 结构，避免塞进 organizations 语义混杂 |

## Risks / Trade-offs

- [字典未初始化时行编辑器下拉为空] → 上线后 admin 先录供应商（tasks 含初始化步骤提示）；空字典时单元格显示占位"暂无供应商（管理员维护）"，不阻断建单（该字段本就选填）
- [员工想用字典外供应商] → 需 admin 添加——用户明确选择此口径（保字典干净），沟通成本可接受
- [导入单据的供应商不入字典] → 导入行存文本照旧；此类单据不参与未来按字典的统计，口径在报表立项时明确
- 回归面：后端新 app 用例（CRUD 权限边界/重名 400）；前端行编辑器用例（选项加载/选择落值/空字典占位）；vitest+build；既有采购建单/导入用例回归
