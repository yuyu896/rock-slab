## Context

- `Asset.分公司`、`Transfer.调出分公司`/`调入分公司` 均为 **CharField（按名称存）**，非外键。
- 资产导入（`assets/views.py` `import_excel`）直接 `分公司=str(row[1])`、`分公司编号=str(row[3])`，**无任何存在性校验**。
- 流转导入（`transfers/views.py` `import_excel`）按 `type` 参数区分列映射，写入 `调出分公司`/`调入分公司`，同样不校验。
- `Branch` 模型有 `name`（分公司名称）与 `code`（唯一）；分公司总量小。
- 导入返回 `{ imported, errors }`：资产导入经 `merge_errors([(行号, msg)])` 合并；流转导入用 `errors` 列表。
- 固定资产导入的分公司**继承自父资产**（非用户输入）、盘点结果导入按资产编号（无分公司）、分类导入无分公司——均不在范围内。

## Goals / Non-Goals

**Goals:**
- 资产、流转两类导入校验分公司名称存在于 `Branch`，不存在则拒该行并报错。
- 两类导入复用同一分公司名称查询逻辑。

**Non-Goals:**
- 不校验「分公司编号」与「分公司名称」的一致性（仅名称存在即可）。
- 不改单条创建接口的分公司校验（仅批量导入）。
- 不动固定资产/盘点/分类导入。
- 不改变 `分公司` 字段的存储方式（仍按名称存 CharField，不转外键）。

## Decisions

### 决策 1：预加载分公司名称集合，逐行 `in` 判断
- **做法**：每次导入开始时 `valid = set(Branch.objects.values_list('name', flat=True))`，逐行将 `分公司.strip()` 与集合做 `in` 判断。
- **理由**：分公司数量少，一次查询远优于逐行查询；封装为助手 `apps/organizations/utils.py::get_branch_name_set()` 供资产与流转复用。
- **备选**：逐行 `Branch.objects.filter(name=…).exists()`——每行一次查询，偏重，**否**。

### 决策 2：仅校验名称存在，不强制编号匹配
- **做法**：只判断分公司名称是否在集合中；不校验 `分公司编号` 是否与该名称对应同一 `Branch`。
- **理由**：用户裁定；流转导入只有名称无编号，统一按名称校验更一致。

### 决策 3：trim 后比较；空分公司也拒（必填）
- **做法**：名称 `.strip()` 后比较；分公司为空 → 拒该行并提示「分公司为空，请填写」；非空但不在集合 → 提示「分公司「X」不存在」。
- **理由**：用户裁定分公司为必填，空值同样视为不可导入，避免脏数据。

### 决策 4：报错沿用各导入既有行级格式
- **做法**：资产导入走 `raw_errors.append((行号, f'分公司「{name}」不存在'))` 经 `merge_errors`；流转导入按其既有 `errors` 追加（含行号 + 提示）。
- **理由**：与「资产编号已存在」等既有报错风格一致，前端无需改动展示。

## Risks / Trade-offs

- **[空分公司现被拒]** 分公司改为必填后，原先分公司为空能导入的行将改为被拒 → **缓解**：属预期行为改变；导入模板已含分公司列、正常填写不受影响，报错明确提示「分公司为空」。
- **[名称带空白]** 名称前后空格导致匹配失败 → **缓解**：trim 后比较。
- **[历史脏数据]** 已导入的不存在分公司不受影响（仅拦截新导入） → **接受**，本变更只做前置校验，不回溯清理。
- **[名称大小写/同音]** 名称须精确匹配 → **接受**，分公司名称为受控字典，由组织架构维护。

## Migration Plan

1. 新增 `get_branch_name_set()` 助手。
2. 资产 `import_excel`、流转 `import_excel` 接入校验。
3. 纯后端逻辑改动，**无 DB 迁移**；部署即生效，前端无需改动。
