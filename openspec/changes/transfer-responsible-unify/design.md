## Context

调拨单头现有 `调出负责人`/`调入负责人` 两个文本字段（models.py:80-81）。经办人统一口径（transfer-handler-unification，2026-09-23 上线）后，调拨创建页出现「调出负责人 + 经办人」并排的语义重复。调拨导入路径直拼 header dict（views.py:898-910）不经 `_create_action`，导入单的经办人现为空。员工即系统账号（User.branch FK），`GET /api/users?branch=<id>`（UserFilterSet.filter_branch）list 权限已对全体登录用户放开（通讯录口径），下拉数据现成。

用户拍板：A 存量合并后删字段；B 旧模板文件 400 不接受兼容；C 调入负责人纯下拉（员工都有账号）。

## Goals / Non-Goals

**Goals:**

- 调出负责人信息归一到经办人（存量无损合并），字段物理删除，五处消费面收口
- 调拨导入对齐采购口径：经办人=导入操作人
- 调入负责人按调入分公司员工纯下拉，存姓名快照

**Non-Goals:**

- 调入负责人导入侧强校验（导入仍是自由文本列，不做员工字典核验）
- 移动端调拨页（无负责人字段，零影响）
- 调入负责人引 User FK（维持姓名文本快照，同使用人模式，避免档案耦合账号生命周期）
- 采购/领用/回收单据（无负责人字段概念）

## Decisions

### D1：存量合并与删列分两条迁移，规避 PG 同表 DML+DDL

迁移 0022（数据迁移，DML）：`Transfer.objects.filter(action_type='transfer', 经办人='')` 逐单把 `调出负责人` 非空值写入 `经办人`（纯 Python 遍历，不用 bulk_update 原子 SQL，保持本项目迁移惯例——见 sqlite-vs-pg-migration-pitfall）。迁移 0023（结构迁移，DDL）：`RemoveField(Transfer, '调出负责人')`。两条分离，各自事务安全；不合并为单迁移（PG 同事务同表 DML+DDL 触发 pending trigger events 崩溃，0009 教训）。
- 备选：单迁移 atomic=False——可行但把安全边界交给开关而非结构；分两条更稳，且数据迁移可单独重放校验。

### D2：导入兜底复用采购模式，收口在导入 header 拼装处

调拨导入 header dict 显式补 `'经办人': creator`（与采购 `'经办人': creator` 同款，views.py:838），不把导入改走 `_create_action`（两条路径校验管线不同，重构造风险大于收益）。`调出负责人` 的 `_cell` 读取随列删除。

### D3：调入负责人纯下拉，分公司联动清空，存姓名快照

TransferCreate 选完调入分公司（toBranch）后拉 `getUsers({ branch: toBranch })` 渲染 `<select>`（选项=员工姓名）；watch toBranch 变化时清空已选调入负责人并重拉员工列表；未选调入分公司时下拉禁用。提交值=所选员工姓名字符串（快照），序列化/存储零改动。编辑态调拨单（若有）同规则。员工接口分页上限 100，单分公司人数远低于此，一次拉全量即可。

### D4：导出列序调整

调拨导出头：`调拨日期、调出分公司、调出部门、调入分公司、调入部门、资产编号、资产名称、规格型号、调拨数量、调拨原因、调入负责人、经办人、备注`（原「调出负责人」列删除，「调入负责人」保留，「经办人」列已存在）。

### D5：表头守卫直接换新，不做旧表头兼容

TYPE_TEMPLATES（后端唯一来源）与 importTemplate.ts TRANSFER_HEADERS 同步删「调出负责人」；守卫按新表头严格匹配，旧模板文件 400 由提示语引导重新下载（用户拍板 B）。

## Risks / Trade-offs

- [迁移先合并后删列的顺序依赖] → 0023 depends_on 0022，Django 线性保序；部署前自动备份兜底（deploy.sh 步骤 1）
- [调入分公司员工为空（新分公司无账号）] → 下拉空列表显示「该公司暂无员工」，允许留空提交（调入负责人本就选填）
- [切换分公司漏清空导致错配] → watch 清空 + 下拉禁用双保险，前端测试覆盖
- [导入旧模板 400 引发用户困惑] → 模板下载入口就在导入弹窗内，报错信息含表头清单比对提示（现状已有），重新下载即恢复

## Migration Plan

部署走常规 deploy.sh：migrate 依次跑 0022（数据合并，秒级，约百行量级）→ 0023（删列，元数据级）。部署后抽查：存量调拨单详情经办人=原调出负责人值、创建页无调出负责人、导出无该列。回滚：数据回滚用部署前备份；代码回滚 git reset（0023 回滚会丢列，须先恢复备份）。
