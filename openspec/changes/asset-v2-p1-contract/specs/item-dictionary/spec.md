## ADDED Requirements

### Requirement: 品目字典数据模型
`Category` SHALL 升级为品目字典（物品户口本），字段 MUST 包含：资产编号（唯一，既有）、资产名称、规格（定义性，可空）、资产类目、物品分类、管理方式（quantity=数量管理 / instance=实例管理，默认 quantity）、图片、是否租用（默认否）、默认警戒线、默认供应商（仅预填便利，非事实）、计量单位。品目字典 MUST NOT 存放库存数量、单价、购入日期等任何事实性数据（它们分别属台账与单据层）。

#### Scenario: 创建数量管理品目
- **WHEN** 管理员创建品目「NB-001 笔记本」且未指定管理方式
- **THEN** 保存成功，管理方式为「数量管理」

#### Scenario: 创建实例管理品目
- **WHEN** 管理员创建品目时选择管理方式为「实例管理」
- **THEN** 保存成功，该品目后续领用需绑定具体实例（实例行为 P2 接入，字典先承载属性）

#### Scenario: 编号重复被唯一约束拒绝
- **WHEN** 创建品目时使用的资产编号已存在
- **THEN** 系统拒绝保存并提示编号已登记

### Requirement: 品目字典管理接口
系统 SHALL 提供品目字典的新增、编辑、删除、列表、详情接口；写操作 MUST 要求 `manage_dictionary` 操作码。删除被台账行或已生效单据引用的品目 MUST 被拒绝（PROTECT），错误信息 MUST 提示引用方。

#### Scenario: 无权限创建被拒
- **WHEN** 不持 `manage_dictionary` 操作码的用户调用品目创建接口
- **THEN** 返回权限不足错误，无数据写入

#### Scenario: 删除被台账引用的品目被拒
- **WHEN** 管理员删除已被台账行引用的品目「NB-001」
- **THEN** 删除被拒绝，提示存在台账引用

### Requirement: 字典管理页判定测试提示
品目字典管理页 MUST 展示「分编号判定测试」提示文案：领用的人会挑这个规格吗？警戒线需要分开设吗？价格差异大到需要分开核算吗？任一「是」即应分编号。

#### Scenario: 管理页展示判定提示
- **WHEN** 用户打开品目字典管理页
- **THEN** 页面可见分编号判定测试的三问提示文案

### Requirement: 单据与台账引用品目的前置校验
流转单创建时携带的资产编号 MUST 在品目字典中存在，否则创建被拒绝并提示相近编号；台账行的品目引用 MUST 为字典外键。

#### Scenario: 单据引用未登记编号被拒
- **WHEN** 用户创建领用单，资产编号为字典中不存在的「NB-009」
- **THEN** 创建被拒绝，错误信息包含提示（含相近编号建议）
