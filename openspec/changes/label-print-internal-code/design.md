# 设计：标签规范 V1（QR + 内部编号 + 双轨纸型）

## Context

打印链路现状（标签未修改基线）：弹窗内联在 `FixedAssetList` 模板里、`window.print()` 无任何打印样式（此前单独合入的输出隔离改动已 revert，**并入本提案整体实施**）；CODE128 印品目编号、A4 双列网格、`max-height: 90vh` 滚动裁剪。规范探讨定稿：QR（V2/ECC M）编码内部编号（17 字符左右，如 `A-a00008-BJ001-1`）、60×40 标准纸型、A4 双列保留、不加抬头、SN 上签（空则隐藏）、不印使用人/部门/状态（身份在标签、状态在系统）。

员工动线：实例档案页（补录完序列号）→ 勾选 → 打印 → 撕下贴机，扫码对机靠 SN 对照。

## Goals / Non-Goals

**Goals:**

- QR 编码内部编号，扫标签唯一定位该台设备
- 60×40 单签在标签打印机上逐张可用：一页一签、内容不越界、QR 模块 ≥0.5mm
- A4 双列兼容（普通打印机 + 不干胶预裁纸）
- SN 有则显示、空则整行隐藏
- 纸型切换可记忆，打印设置风险有提示

**Non-Goals:**

- 不做入库单「打印本单标签」入口（用户已否：贴标发生在实例档案页补录序列号之后）
- 不加公司/系统抬头
- 不做 40×30、70×40 等其他纸型（将来加预设即可）
- 不做 ZPL/TSPL 原生指令、WebUSB、本地打印服务
- 不改扫码端与后端

## 版式规范

**60×40 单签（标签打印机，默认）**——横排，左 QR 右文字：

```
◄────────────────── 60 ──────────────────►
┌─────────────────────────────────────────┐ ↑
│ ┌────┐   A-a00008-BJ001-1   3.2mm 等宽粗 │
│ │ QR │   SN: PF3XK2LM        2.8mm 等宽  │ 40
│ │13mm│   笔记本电脑           3.0mm 粗    │
│ └────┘   品目 A-a00008·北京   2.4mm 灰   │ ↓
└─────────────────────────────────────────┘
  盒 padding 1.5mm（即四周边距）· QR 静区 2mm · 文字区 ~42mm
```

**A4 双列（普通打印机）**——上下结构卡片（沿用现有），码区换 QR 居中，页边距 8mm。

## Decisions

**D1：码制 QR，库用 `qrcode`（npm）**

- `QRCode.toString(内部编号, { type: 'svg', errorCorrectionLevel: 'M', margin: 0 })` → SVG 字符串注入容器；尺寸由 CSS 定死 13×13mm（宽高都定，防拉伸变形），静区由容器 padding 2mm 自控（margin: 0 免得库再外加白边）
- 内容 = 内部编号纯文本：扫码枪/摄像头回传原文，扫码查询 keyword 唯一命中；未来可改编码资产 URL 直达详情页，扫码端无需改动
- 17 字符 → V2（25 模块）ECC M；203dpi 下模块 ≈ 0.5mm（13mm/25），高于扫码下限
- **移除 jsbarcode**：全站唯一使用处是本弹窗，QR 化后无用；`@types/qrcode` 进 devDependencies

**D2：60×40 防越界 = 固定高度盒 + 宁缩勿溢**

一页=一张实物标签（间隙传感器对齐），任何标签内容溢出 40mm 都会被浏览器挤到下一页，打乱整卷对齐。因此单签版式：外盒固定 40mm 高、内部各行单行不换行（`white-space: nowrap`）、辅助行超宽自动缩号（下限 2.2mm）、`overflow: hidden` 兜底。

**D3：`@page` 动态切换用专属 style 元素**

`@page` 无法按 class 作用域。打印组件挂一个专属 `<style>`（如 id=`label-page-size`），纸型切换时改写其内容：60×40 模式 `@page { size: 60mm 40mm; margin: 0 }`；A4 模式 `@page { size: A4; margin: 8mm }`。`break-after: page` 只在 60×40 版式的签卡片上生效（A4 双列网格自然流式分页，沿用现状）。

**D4：纸型状态与提示**

默认 60×40（主场景），localStorage `rock_slab_label_paper` 记忆上次选择（与 `rock_slab_token` 命名一致）。弹窗常驻小字提示：「打印时请选择实际大小/100%」——浏览器默认"适应页面"会缩放 mm 版式导致作废。

**D5：渲染时机沿用现有编排**

`watch(visible) + nextTick` 触发，逐签 `await QRCode.toString(...)` 注入（Promise）；失败沿用静默 catch（内部编号为必填字段，存量无空值）。

**D6：打印输出隔离并入本提案（原 label-print-isolation 回退重做）**

弹窗整体 `Teleport to="body"` 与 `#app` 平级；组件 scoped `@media print`（去遮罩/去 `max-height` 裁剪/隐藏弹窗头脚/白底黑字固定值）+ 非 scoped `@media print { #app { display: none !important } }`。其中 A4 模式 `@page` 边距 8mm 与 D3 的动态 style 合并管理（60×40 模式 margin 0、A4 模式 margin 8mm），打印 CSS 全部随组件走、不动 `global.css`。

## 打印机制备忘（实施与验收依据）

- **分页即切刀**：N 签 = N 页；驱动把一页打到一个间隙内的物理标签上，浏览器分页边界 = 传感器标签边界
- **续打**：卡纸/断碳带处理后，打印对话框页码范围（如 18-30）续打剩余，不必整批重打
- **装机一次性配置**：驱动确认 60×40 纸型表单、跑一次纸张校准；日常零操作
- **物理参数**：热转印 + PET/合成纸 + 树脂碳带（纯热敏一年褪色）；设计按 203dpi 下限校验，300dpi 更佳

## Risks / Trade-offs

- [部分驱动不认 `@page size` 自动带出纸型] → 对话框手选纸型；弹窗提示覆盖
- [QR SVG 注入是异步串行，几百签时渲染稍慢] → 场景为几十签量级，可接受；必要时 Promise.all 并行
- [移除 jsbarcode 触碰 lockfile] → `npm install` 后跑全量测试与 build 验证
- [浏览器位图化打印在低 DPI 设备上 QR 边缘发虚] → 13mm/V2 的模块尺寸留了余量；实测验收把关
