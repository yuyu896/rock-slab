# ledger-consistency-guard Specification（修改）

## MODIFIED Requirements

### Requirement: 对账命令

系统 SHALL 提供 `check_ledger_consistency` 管理命令，执行双重不变量：

一（数量）：对每「分公司 × 品目」行，以单据流水（期初调整单 + 期初时刻之后的已通过流转单 + 全部非期初调整单）重算在库/在用/回收库期望值，与台账存储值逐列比对。

二（实例）：对每「分公司 × 实例管理品目」，各状态实例计数 MUST 等于台账对应列（在库实例数==在库数量、在用==在用数量、回收库==回收库数量；退役实例不参与，其减少量由回收去向=直接处置的单据流水解释）。实例聚合查询 MUST 显式清空模型默认排序（`.order_by()`），MUST NOT 让排序列混入 GROUP BY 使聚合按实例细分。

全部一致时输出零差异并以退出码 0 结束；任何不一致 MUST 输出差异清单（分公司、品目、列、台账值、期望值）并以退出码 1 结束。数量管理品目挂有实例 MUST 输出警告清单（**每个品目一行并携带实例条数**，不按实例重复；不改变退出码，交管理员决断）。

#### Scenario: 全库零差异

- **WHEN** 系统所有数量变动均经唯一写入口，执行 `check_ledger_consistency`
- **THEN** 输出零差异汇总，退出码 0

#### Scenario: 漂移被检出

- **WHEN** 绕过唯一写入口直接篡改某台账行在库数量后执行命令
- **THEN** 输出该行差异明细（台账值 vs 期望值），退出码 1

#### Scenario: 实例计数与台账不符被检出

- **WHEN** 某实例管理品目在分公司 A 在库数量为 5，但状态在库的实例仅 4 个
- **THEN** 对账输出实例维度差异（台账 5 vs 实例 4），退出码 1

#### Scenario: 数量管理品目挂实例警告一行一品目

- **WHEN** 数量管理品目 X 挂有 3 条实例档案，执行对账命令
- **THEN** 输出一行警告「品目 X 挂有 3 条实例档案，请决断」，不重复、退出码不变

## ADDED Requirements

### Requirement: 管理方式切换对齐命令

系统 SHALL 提供 `align_ledger_to_instances` 管理命令，作为设计书十一节决断路径的落地工具：品目从数量管理改为实例管理后，把该品目全部「分公司 × 台账列」对齐到实例计数（退役实例不参与），消除实例镜像差异。

命令 MUST 默认仅预览（逐条列出 分公司 × 品目 × 列 的 台账值 → 实例计数与 ±delta，不落任何单）；`--confirm` 时经台账唯一写入口逐条生成**非期初**调整单（事由注明管理方式切换对齐）。命令 MUST 幂等（无差异时零落单、可重复执行）；对齐方向以实例计数为准；branch 为空的实例 MUST 跳过并输出警告。

#### Scenario: 切换后预览差异

- **WHEN** 品目 X 由数量管理改为实例管理（台账在库 5，实例在库 2），执行 `align_ledger_to_instances`
- **THEN** 预览输出「在库 台账=5 → 实例计数=2（-3）」，不生成调整单，对账仍失败

#### Scenario: 确认对齐后对账通过

- **WHEN** 承上执行 `align_ledger_to_instances --confirm`
- **THEN** 生成非期初调整单（目标列=在库，变动量 -3，经唯一写入口），台账在库变为 2，`check_ledger_consistency` 退出码 0

#### Scenario: 幂等重跑

- **WHEN** 对齐完成后再次执行命令（无论是否 --confirm）
- **THEN** 输出「实例镜像已对齐，无需调整」，不生成任何调整单
