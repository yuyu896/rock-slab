# 设计：标签版式 V3（英文字段前缀）

## Context

V2 行集：内部编号 / SN / 品目名称 / 品目编号 / 分公司 / 供应商·采购日期。用户定稿新模板：全部行带字段前缀、中文换英文短标签、删品目编号行。前缀会让每行变长，首行（内部编号 17 字符）在 3.6mm 等宽下加前缀必然超宽，需要混合字号处理。

## Goals / Non-Goals

**Goals:**

- 五行英文前缀模板，与用户给定的版式一致
- 首行主码字号尽量不因前缀而缩水（3.4mm）
- 打印/导出两通道同步，空值隐藏规则不变

**Non-Goals:**

- 不改 QR 码制与尺寸
- 不改 60×40 版式几何（QR 左置、居中上移校正沿用）
- 前缀不做国际化/可配置（要换词改 `LABEL_SPEC.prefixes` 一处常量即可）

## 版式（60×40）

```
┌──────────────────────────────────────┐
│ ┌────┐   NO: A-a00008-BJ001-1  3.4mm │  ← NO: 2.6mm + 主码加粗
│ │ QR │   SN: PF3XK2LM         3.0mm  │
│ │13mm│   ITEM 笔记本电脑       3.4mm  │
│ └────┘   BRANCH: 北京分公司   2.6mm  │
│          VENDOR: 小熊  DATE: 2026-09-16 │
└──────────────────────────────────────┘
```

宽度核算（38.5mm 可用）：首行 NO:(2.6mm×3字符≈4.3mm) + 17 字符主码 3.4mm×0.55≈31.8mm ≈ 37.5mm ✓；末行 VENDOR+小熊+DATE+日期 ≈ 35mm ✓。

## Decisions

**D1：前缀词表固定为常量 `LABEL_SPEC.prefixes`**

`{ code: 'NO:', sn: 'SN:', name: 'ITEM:', branch: 'BRANCH:', vendor: 'VENDOR:', date: 'DATE:' }`。全大写短词；换词只改这一处，两通道共享（打印 CSS 侧文案在模板里硬编码，注释指向该常量——CSS 无法引用 JS 常量，靠测试源码断言对齐）。

**D2：首行混合字号，其余行统一字号**

首行 = 前缀（2.6mm）+ 主码（3.4mm 加粗）两段拼接；其余行前缀与值同字号。canvas 侧每行改为 segments 数组（`[{text, sizeMm, weight, mono}...]`），fillText 顺序绘制并累进 x；CSS 侧用 `<span class="label-prefix">` + 值 span。缩号规则作用于整行（measureText 按拼接后总宽），主码段优先保字号——实现上整行同比例缩，超出下限再动主码。

**D3：删除品目编号行**

内部编号 `A-a00008-BJ001-1` 的首段即品目码，品目行删除无信息损失；行集从六行减到五行，末行供应商/日期保留同行。

## Risks / Trade-offs

- [英文前缀对不识英文的分公司人员有门槛] → 前缀均为资产行业惯用短词（SN/DATE 全球通用），且扫码场景不依赖人读前缀；用户已明确要求英文
- [canvas 段式绘制增加行构造复杂度] → `LabelLine` 泛化为 segments，fitLines 按段聚合宽度，纯函数仍可单测
