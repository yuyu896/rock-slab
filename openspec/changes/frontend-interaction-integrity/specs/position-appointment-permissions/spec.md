## MODIFIED Requirements

### Requirement: 权限分配页保存脏检查与只补不删
权限分配页「保存岗位」的可用条件 MUST 为：岗位变化**或**操作码勾选集与该用户既有授权码集存在差集。换岗选择岗位模板时，操作码勾选集 MUST 初始化为**模板操作码 ∪ 既有授权码集**（MUST NOT 整体替换清空既有授权）；既有授权中不属于新模板的项 MUST 默认保留并 SHALL 在页面提示保留数量，仅显式取消勾选后才在保存时删除。保存写入语义与 `migrate_positions` 命令"只补不删"原则统一。

**admin 判定口径（frontend-interaction-integrity）**：操作码勾选禁用、脏检查、保留计数、范围预览的「admin 内置特权」判定 MUST 基于**保存后岗位**（页面所选岗位）而非用户当前岗位——admin 用户换岗到非 admin 岗位时：勾选框 MUST 可用、勾选集 MUST 按本要求初始化（admin 无既有授权时即模板集）、「保存岗位」MUST 可用；降级保存后该用户 MUST 持有所选岗位模板的全部操作码（MUST NOT 清零）。仅当保存后仍为 admin 时操作码区才呈现禁用态（运行时恒真、无可管理项）。

#### Scenario: 仅调整操作码可保存
- **WHEN** 管理员选中用户后未改岗位，仅勾选一项其未持有的操作码
- **THEN** 「保存岗位」按钮可用，保存后该操作码授予成功

#### Scenario: 无变化时不可保存
- **WHEN** 岗位未变且勾选集与既有授权码集一致
- **THEN** 「保存岗位」按钮禁用

#### Scenario: 换岗保留模板外既有授权
- **WHEN** 某用户持有模板外单独授予的 `dispose_assets`，管理员将其换岗为「分公司行政」并直接保存
- **THEN** 勾选集为模板 8 项 ∪ 既有授权（含 dispose_assets），保存后 dispose_assets 授权保留，页面曾提示"将保留岗位外的既有授权"

#### Scenario: 显式取消勾选才删除
- **WHEN** 管理员在勾选区显式取消某既有授权项后保存
- **THEN** 该授权被删除

#### Scenario: admin 降级不清零权限
- **WHEN** 管理员在权限分配页将一个 admin 用户换岗为「分公司行政」并保存
- **THEN** 换岗后勾选框可用且预填分公司行政模板操作码，「保存岗位」可用；保存后该用户持有模板 8 项操作码（不是 0 项）

## ADDED Requirements

### Requirement: 权限分配页预览正确性与组织名安全渲染

「若保存后的范围」预览 MUST 按保存后岗位与授权行拼装：保存后仍为 admin 才显示「全部（内置）」，非 admin（含降级中）按当前生效范围 ∪ 待任命节点子树显示（MUST NOT 因未解包的响应式引用而对所有用户恒显「全部」）。页面以 `v-html` 渲染的范围标签中，组织名称（大区/分公司/行政组名）MUST 经 HTML 转义（& < > " '），MUST NOT 将数据库文本未经转义拼入 HTML（存储型 XSS 面）。

#### Scenario: 非 admin 用户的范围预览
- **WHEN** 选中一个持「某大区授权」的 manager 用户查看范围预览
- **THEN** 预览显示该大区范围（非「全部（内置）」）

#### Scenario: 组织名含 HTML 时不注入
- **WHEN** 某分公司名称被写入 `<img onerror>` 之类的 HTML 片段并出现在授权列表
- **THEN** 页面按纯文本渲染该名称，不执行任何注入内容
