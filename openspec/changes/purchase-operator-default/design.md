## Context

PurchaseCreate 表单初始值全部为空串；userStore.profile.name 在路由守卫后必可用（登录才能进创建页）。后端创建 action 已有「创建人」快照逻辑，与经办人是两个字段、互不干扰。

## Goals / Non-Goals

**Goals:** 创建页打开即见自己姓名，免手敲。

**Non-Goals:** 不做后端默认值（避免前端/后端双默认源打架）；不改编辑表单（编辑改的是单据内容，非默认身份）；不做必填收紧。

## Decisions

| 决定 | 理由 |
|------|------|
| 仅前端预填，后端零改动 | 字段语义（选填自由文本）不变；代建场景（替他人建单）需可改，保持自由度 |
| 预填 `profile.name`（无 phone 兜底） | 该字段展示口径就是姓名；profile 加载失败时留空回退现状，不引入新错误路径 |

## Risks / Trade-offs

- [profile.name 为空（异常态）] → 初始值为空串，行为与现状完全一致，无害
- 回归面：vitest 全量 + `npm run build`；无既有用例依赖「初始为空」（提交前可改），如有断言失败按实情修用例
