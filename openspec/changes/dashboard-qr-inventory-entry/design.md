# 设计：工作台二维码改为移动端盘点入口

## Context

- 移动端自 f622069「扫码化改造」起定位为**扫码盘点终端**：导航只剩 扫码/盘点任务/我的，入口重定向到扫码页
- 工作台二维码卡片（InstallQrCard）当前文案承诺 PWA 安装，指向 `/install` 安装向导页；手机实测微信内装不了（iOS 微信无「在浏览器打开」入口，PWA 安装在国产浏览器生态基本不可用）
- 登录回跳链路今日已修（ffed21b）：401 死 token 场景下重登也能回到 `?redirect` 指定的移动端页面，本变更的动线因此全程成立

## Goals / Non-Goals

**Goals:**

- 二维码卡片文案如实：微信扫码 → 用移动端盘点，不再出现任何安装话术
- 二维码指向移动端盘点流程（登录后直达盘点任务列表）

**Non-Goals:**

- 不删除 `/install` 路由与 InstallGuide 页、PWA manifest/图标（保留给愿意装的 Chrome/Safari 用户，只是不再导流）
- 不处理 MobileLayout 安装横幅在微信内的失实文案（另行立项）
- 不解决 MobileScan（数量盘任务页）在微信内无法扫码的问题（缺 jsQR 兜底，另行立项）
- 不改二维码「运行时按 origin 生成」的机制（开发环境 localhost 扫不通是已知特性）

## Decisions

1. **指向 `/mobile/inventory`（盘点任务列表），不是 `/mobile` 也不是保留 `/install`**
   - 文案承诺的是「进行盘点」，落地应是任务列表（选任务进场），而非扫码查询页（`/mobile` 重定向到 `/mobile/scan`，其盘点模式需要 `?task=` 上下文才有意义）
   - 保留 `/install` 与新文案直接矛盾（扫码落在一个教人装 App 的页面）
   - 未登录时路由守卫自动带 `?redirect=/mobile/inventory` 跳登录，登录后原路返回——新设备与死 token 重登（ffed21b）两条路都已验证
2. **文案定稿**（卡片三行结构不变）：
   - 标题 h3：`移动端盘点`（原「移动端安装」）
   - 主文案 p：`微信扫码使用移动端进行盘点`（用户指定原句）
   - 提示行 hint：`首次使用需登录，登录后选择盘点任务`（替代「安卓两下 · iPhone 四下」安装话术，与实际动线一致）
3. **组件文件名不改**（仍叫 InstallQrCard.vue）：改名牵连 Dashboard 引用与测试文件名，收益纯审美；在组件头注释标注「盘点入口」语义即可
4. **二维码内容仍为 `location.origin + 路径` 运行时生成**：本地/生产自适应的特性保留，只换路径段

## Risks / Trade-offs

- [员工扫码落在盘点任务列表，但数量盘任务页在微信内不能扫（MobileScan 无 jsQR 兜底）] → 本次不改；实例盘（跳扫码器 ScanAsset，有 jsQR 兜底）微信内可扫。数量盘的微信兼容另行立项，属既有问题非本次引入
- [`/install` 成为无导流入口的孤儿页] → 保留无妨：直接输 URL 仍可用，历史已传播的二维码若被再扫也仍能走安装引导
- [新文案宣称「微信扫码」，但 PC 浏览器扫码同样能进] → 文案是主用法描述不是排他承诺，可接受
