# 设计：移动端扫码化改造

## Context

移动端已有 `/mobile/scan`（扫码查询）与 `/mobile/inventory/:taskId`（盘点扫码），但两者各自维护一套摄像头代码、识别都只靠 BarcodeDetector（iOS Safari/微信不可用）、扫一台关一次摄像头；导航与落地页承载大量非现场功能。用户定稿：移动端 = 扫码终端，只做扫码盘点 + 扫码查询。

## Goals / Non-Goals

**Goals:**

- 登录即扫码：摄像头常开连扫，扫完不停机
- iPhone Safari / 微信内置浏览器摄像头可用（jsQR 兜底）
- 查询/盘点双模式一屏切换，扫同一张标签按模式分流
- 导航与落地页做减法；摄像头逻辑全站收敛为一个 composable

**Non-Goals:**

- 不做 PWA/离线（P2 另议）
- 不做未核对清单视图、盘盈上报、手电筒（P1 第二条提案）
- 不改 PC 端任何页面；不删移动端旧页面文件（重定向退役）
- 不改后端与业务规则

## 页面形态

```
┌──────────────────┐
│  ◎查询  ○盘点(任务名) │ ← 模式开关；盘点项仅在有进行中任务时出现
│ ┌──────────────┐ │
│ │              │ │
│ │  ［开始扫码］  │ │ ← 显式入口，点击后才请求摄像头并开始取景
│ │   (大按钮)    │ │    （避免进页面即弹权限授权框）
│ │              │ │
│ └──────────────┘ │
│ [手动输入框      ↓]│ ← 兜底入口常显（扫码枪/手输同链）
├──────────────────┤
│ 查询模式：资产卡片  │ ← 内部编号/品目/状态/使用人/分公司 + 查看详情
│ 盘点模式：流水     │ ← ✓已核对 xxx（品目）/ ⚠重复 / ⚠清单外
└──────────────────┘
  底部导航：扫码 | 盘点任务 | 我的
```

扫码会话：点「开始扫码」→ 弹摄像头授权（首次一次，之后记住）→ 取景框替换按钮 → **会话内摄像头常开连扫** → 手动停止或离开页面才关。

## Decisions

**D1：统一扫码器为实例盘点唯一入口，旧 MobileScan 仅保留数量盘**

盘点扫描的实现以扫码器为准（实例盘）。任务列表页「去盘点」按任务类型分流：instance → `/mobile/scan?task=<id>`（自动切盘点模式并锁定任务）；stock → 旧 `/mobile/inventory/:taskId`（数量盘需逐项确认数量，交互不同，本轮不并入）。旧路由**不做全局重定向**，深链自然兼容；扫码器不重复承载 MobileScan 的进度统计（任务列表已承载）。

**D2：双引擎在 composable 内部选择，调用方无感**

```ts
useBarcodeScanner(videoRef, { onDetect })  // 内部：
//   'BarcodeDetector' in window → detector.detect(video)
//   否则 → canvas.drawImage(video) → getImageData → jsQR(data, w, h)
```

jsQR 路径把帧降采样到 ~480px 宽再解码（识别够用、CPU 可控）；轮询 400ms；`onUnmounted` 停流防泄漏。摄像头取流沿getUserMedia（facingMode: environment；`<video playsinline muted>` iOS 必需）。

**D3：显式开始 + 会话内连扫与去抖**

摄像头**不在进入页面时自动开启**——权限授权框在用户理解页面后、点「开始扫码」时才弹（避免落地即弹权限导致误拒，拒绝后恢复成本高）。扫码会话内：识别成功后**不 stop 摄像头**（连扫），仅记录 `lastCode + lastTime`；同一码 1000ms 内重复识别忽略；不同码即时处理；手动停止或路由离开才停流。反馈：`navigator.vibrate(80)`（Android）+ Web Audio 短哔声（iOS 亦有效）；失败（清单外/重复）用低音调区分。

**D4：模式分流**

- 查询（默认）：命中 → 并行查台账行+实例（现有 keyword 链）→ 渲染资产卡片（复用现有字段），「查看详情」跳 `/mobile/assets/:id`
- 盘点：仅实例盘任务进入扫码器（数量盘走旧任务页，见 D1）；进入时拉任务清单缓存于内存；识别码与清单 `instanceCode/serialNumber` 精确匹配 → `checkInventoryInstance` 打钩 → 流水插入 ✓ 行；重复扫提示"已核对"；清单外提示并可继续

**D5：导航与落地**

MobileLayout 底部 tab 改为三项：扫码（/mobile/scan）/ 盘点任务（/mobile/inventory）/ 我的；`/mobile/home` 重定向 `/mobile/scan`。审批/资产浏览等路由保留（深链可用），导航不再露出。

## Risks / Trade-offs

- [进入页面即请求摄像头，用户拒绝授权] → 手动输入框常显为兜底，页面顶部提示去浏览器设置开启
- [微信 iOS 的 getUserMedia 在旧版 WKWebView 受限] → jsQR 就绪后大部分场景可用；仍失败的降级手输（链路一致）
- [连扫时页面请求频率] → 400ms 轮询 + 降采样解码，实测 CPU 占用低；电量影响可接受（盘点时长有限）
- [退役重定向漏改调用点] → 全局搜引用 + 路由测试覆盖
