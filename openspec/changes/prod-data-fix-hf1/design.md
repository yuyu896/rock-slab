# design — 合肥分公司资产全清（任意单据构成）

## Context

三源并存：实例出生（57 纯 + 7 混行生效单）、非实例库存（102 调整单 + 119 生效采购行）、218 待审批单。此前各路径（成对删/出生单连删/未生效清理）单独都不适用——生效采购行与调整单**共同**解释非实例库存，无法拆开清。

## Decisions

### D1. 全清 = 流水源与存储值同侧归零（不做回退算术）

删除集合：实例+关联、全部单据（任意状态）、全部调整单、全部台账行。对账不变量的两侧——重算值（生效单流水 ∪ 调整单）与存储值（台账行）——同时清空，0==0 自洽；镜像两侧（实例计数/台账列）同空。混行单整单删除天然正确（其两类行的贡献都在删除集合内）。这把 hz235（纯调整单）/xm25（待审批）/hz2（纯实例+调整单）三种形态统一为"全清"特例。

### D2. 前置断言（全清特有）

1. **无 from 方向单据**：本司作为调出方的单据（调拨/领用/回收）意味着他司数据耦合本司库存，全清会破坏他司对账——存在即中止；
2. **无盘点引用**：盘点任务/明细/核查挂本司（节点或台账行）即中止（盘点差异单也是流水源，混入则归零论证不闭合）；
3. **镜像一致**：品目级台账 == 在库实例（一致性全局兜底前的快节奏本地断言）。

### D3. 删除顺序与形态

单事务内：行-实例关联 → 实例 → 单据（级联明细行）→ 调整单 → 台账行 → 通知（related_object_id 指向被删单据）。语义计数先取后删（delete() 返回含级联）。dry-run 输出生效/待审批/调整单/台账行/实例五类计数与实例品目回退对照。命令形态沿用：常量固化、幂等、末尾内嵌对账复验。

## Risks / Trade-offs

- [误伤他司] → 全部集合以 branch 收敛 + from 断言 + 对账复验兜底
- [执行中有人新导入] → 断言与删除同事务；事务内新写入会被锁等待，提交后对账复验暴露异常增长
- [员工重导] → 节点/员工/字典/发号序列保留

## Migration Plan

push → 部署（无 migration，重建镜像）→ 备份 → dry-run 复核 → `--apply` → 独立对账 + 抽查（五类全零、员工在）→ 幂等复证。
