# branch-filter-search Specification

## ADDED Requirements

### Requirement: 分公司筛选可键入搜索

列表页的分公司筛选 SHALL 使用可键入搜索的下拉（filterable）：用户键入文字时选项按分公司名**包含匹配**实时收窄；支持一键清空回到「全部分公司」；空值语义与既有筛选一致（空=不过滤）。选中值、筛选查询参数、结果口径 MUST 与替换前完全一致（仅交互升级，无行为变化）。分公司选项较多的账号（大区级数十家）MUST 可经键入直接定位目标分公司。

#### Scenario: 键入收窄选项

- **WHEN** 大区账号在实例档案页分公司筛选键入「杭州」
- **THEN** 下拉仅显示名称含「杭州」的分公司，选中后列表按该分公司过滤

#### Scenario: 清空回到全部

- **WHEN** 用户点击筛选框清空按钮
- **THEN** 筛选值回到空（全部分公司），列表恢复未过滤结果

#### Scenario: 筛选口径不变

- **WHEN** 用可搜索下拉选中某分公司
- **THEN** 后端收到的筛选参数与替换前的原生下拉完全一致，列表结果一致

### Requirement: 筛选组件统一复用

分公司筛选下拉 SHALL 收敛为共用组件（BranchFilterSelect）：各列表筛选位（实例档案、库存台账汇总、调整单记录弹窗、盘点任务列表、部门管理、流转列表）MUST 使用同一组件；新增页面需要分公司筛选时 SHALL 直接复用该组件，MUST NOT 再新建原生下拉。报表页既有的多选筛选（el-select multiple）保持现状不迁移。

#### Scenario: 各筛选位统一

- **WHEN** 用户在实例档案、台账汇总、盘点列表等任一页面使用分公司筛选
- **THEN** 交互一致（可键入、可清空、空值=全部），组件同源
