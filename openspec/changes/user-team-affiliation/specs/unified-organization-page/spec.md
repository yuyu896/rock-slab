## MODIFIED Requirements

### Requirement: 左侧组织树（区域→行政组→分公司）

左侧 MUST 按 **区域 → 行政组 → 分公司** 三层展现组织树；每个分公司必有行政组父级，MUST NOT 出现「未分组」虚拟节点。**员工 MUST NOT 作为树节点出现**（员工在右侧列表呈现）。点击组织节点 MUST 选中，右侧员工列表 MUST 按以下沿树派生的规则显示该节点范围内的员工（节点员工 = 子树分公司挂靠员工 ∪ 子树内全部负责人任命 ∪ 子树行政组直属员工）：

- 分公司节点：`u.branch = 该分公司` ∪ `u = branch.manager`
- 行政组节点：`u.branch ∈ 该组下分公司` ∪ `u ∈ 组内分公司 manager` ∪ `u = team.leader` ∪ `u.team = 该行政组`（直接归属行政组的员工）
- 区域节点：`u.branch ∈ 该区域旗下分公司（经行政组）` ∪ `u ∈ 旗下分公司 manager` ∪ `u ∈ 该区域各组 leader` ∪ `u = region.manager` ∪ `u.team ∈ 该区域旗下行政组`

#### Scenario: 行政组节点显示组内分公司员工与组长及直属员工

- **WHEN** 选中某行政组节点
- **THEN** 右侧显示该组全部分公司下的员工，以及 `team.leader`（即使其无分公司挂靠），以及 `team` 直接等于该行政组的员工（无分公司挂靠）

#### Scenario: 区域节点显示该区域全员与负责人及 team 直属员工

- **WHEN** 选中某区域节点
- **THEN** 右侧显示该区域旗下（经行政组）分公司员工，以及区域负责人与各组组长（即使其无分公司挂靠），以及 `team` 直接属于该区域旗下行政组的员工（无分公司挂靠）

### Requirement: 员工操作（创建 / 移动 / 删除）

员工列表上方 MUST 提供「创建 / 移动 / 删除员工」，受 `manage_users` 权限控制。创建默认挂当前节点。**移动员工 MUST 通过 区域 → 行政组 → 分公司 三级级联弹窗选择目标，分公司可选（支持仅归属行政组）**；行政组下拉列所选区域的真实行政组（无「未分组」选项）；选行政组时分公司下拉只列该组下分公司；**提交 MUST 仅写 branch 与 team**（区域由分公司/行政组沿树派生，不再同步写入区域字段）：
- 分公司有值：`branch = 分公司id, team = null`
- 分公司空但行政组有值：`branch = null, team = 行政组id`
- 两者均空：`branch = null, team = null`（移出所有组织归属）

#### Scenario: 移动弹窗三级级联且分公司可选

- **WHEN** 点击「移动」打开移动弹窗
- **THEN** 弹窗依次提供「区域」「行政组」「分公司」三个下拉（无「未分组」选项）；分公司为可选；切换区域清空行政组与分公司，切换行政组清空分公司

#### Scenario: 移动员工到分公司清空 team

- **WHEN** 确认移动，选中目标分公司
- **THEN** 员工的 `branch` 改为目标分公司，`team` 置为 null，无其他组织字段被写入

#### Scenario: 移动员工到仅行政组

- **WHEN** 确认移动，选中目标行政组但分公司留空
- **THEN** 员工的 `branch` 置为 null，`team` 改为目标行政组

#### Scenario: 移动员工移出所有组织

- **WHEN** 确认移动，行政组与分公司均留空
- **THEN** 员工的 `branch` 与 `team` 均置为 null
