## Why

实例图片覆盖时可能继续使用相同的存储路径和 URL，浏览器或中间缓存因此把旧图片当作新图片展示；不同设备会看到不一致的结果。图片更新需要有稳定、可识别的版本地址，同时在新图保存失败时保留原图。

## What Changes

- 实例图片每次上传后都获得新的图片版本 URL，避免同一资源地址对应不同图片内容。
- 图片替换先保存新文件并更新档案，成功后再清理旧文件；失败时保留原图。
- 图片删除和替换后的 API 响应继续返回当前图片地址，供前端立即更新和后续重新读取。
- 增加同名文件连续替换、版本地址变化及失败回退的回归验收。

## Capabilities

### New Capabilities

（无）

### Modified Capabilities

- `fixed-asset-instance`：增加图片版本地址语义，并明确图片替换的保存、切换和旧文件清理顺序。

## Impact

- 后端 `FixedAsset` 图片存储、序列化和图片上传/删除端点。
- 前端实例档案图片 URL 更新行为及相应测试。
- 实例图片 API 与 `/media` 缓存交互；不要求全局关闭媒体缓存。
