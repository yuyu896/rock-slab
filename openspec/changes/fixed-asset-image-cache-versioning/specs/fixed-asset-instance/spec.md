## ADDED Requirements

### Requirement: 实例图片版本化与安全替换

系统 MUST 为每张实例档案图片提供可识别的持久化版本。每次成功上传或删除图片时，系统 MUST 更新该图片版本；普通档案字段更新 MUST NOT 改变图片版本。非空图片 URL MUST 包含版本标识，且每次成功替换 MUST 返回与替换前不同的图片 URL。每次替换 MUST 使用此前未使用的存储路径，不得因上传文件名相同而覆盖旧图片路径。

图片替换 MUST 先保存新文件并成功更新档案引用，再清理旧文件。若新文件保存或档案更新失败，系统 MUST 保留原图片引用及原文件，并清理未被引用的新文件。既有图片 MUST 在首次读取时获得带版本标识的 URL，以避免继续使用未版本化的客户端缓存键。

#### Scenario: 既有图片返回版本化 URL

- **WHEN** 客户端在该能力部署后读取已有图片的实例档案
- **THEN** `图片` 字段包含持久化版本标识，且 URL 不再等于部署前未带版本标识的 URL

#### Scenario: 同名图片替换生成新 URL

- **WHEN** 用户连续两次上传文件名相同的图片并且两次请求均成功
- **THEN** 第二次响应及后续查询的 `图片` URL 与第一次不同，且指向第二次上传的图片

#### Scenario: 替换失败保留旧图片

- **WHEN** 已有图片的实例替换图片，但新文件保存或档案更新失败
- **THEN** 档案仍引用原图片，原文件仍存在，未被引用的新文件被清理

#### Scenario: 成功替换后清理旧文件

- **WHEN** 新图片保存成功且档案更新事务提交
- **THEN** 档案引用新图片和新版本，旧文件随后被清理，客户端可通过新 URL 请求新图片

#### Scenario: 删除图片后重新上传

- **WHEN** 用户成功删除实例图片，之后再次上传图片
- **THEN** 删除后的档案不返回图片 URL，重新上传后的 URL 使用高于删除前的图片版本且不同于此前 URL
