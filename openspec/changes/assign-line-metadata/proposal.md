## Why

领用明细表的设备用途不是必需字段，增加了表单与详情列宽，也让明细更拥挤。设备备注仍需按明细记录，但其输入和展示高度必须固定，避免长文本撑高整行。

## What Changes

- 从领用 Web/移动端表单、详情、行级 API、导入新模板和导出中彻底移除“用途”；旧导入模板中的用途列兼容接收但忽略。
- 继续将备注按领用明细行读写、导入和导出；输入控件锁定为与普通单行输入相同的固定高度，详情长备注不撑高明细行。
- 从领用表单和详情中移除单头“调出部门”；领用部门继续存于明细，部门统计继续按行部门计算。
- 保留共享单头用途字段对其他单据的兼容。历史单头/明细用途数据留在数据库中，但领用 API 不暴露、不再读写用途；保留单头历史备注及审批驳回信息。

## Capabilities

### New Capabilities

（无）

### Modified Capabilities

- `transfer-line-items`：领用明细只公开备注，不再公开用途；详情备注固定高度。
- `transfer-create-pages`：领用表单只支持逐行备注并锁定输入高度。
- `transfer-batch-import`：模板移除用途，旧用途列忽略；导出不含用途。
- `transfer-type-templates`：更新领用模板和导出字段。

## Impact

- 后端：领用序列化、导入模板守卫、导入/导出映射及相关测试。
- 前端：Web 和移动端领用表单、详情、明细草稿类型、模板生成和测试。
- 数据：保留已存在的用途数据库字段和值，不新增删除字段的迁移；领用 API 隐藏用途，其他单据共享单头字段维持原行为。
- 测试：覆盖用途不显示/不提交/不导出、旧模板用途列被忽略、备注按行保存以及固定高度样式。
