## MODIFIED Requirements

### Requirement: 后端批量导入 API

TransferViewSet SHALL 提供 `import_excel` action（POST `/api/transfers/import`），接受 Excel 文件上传并按单据类型解析有效行。采购行按日期、入库分公司和需求部门合并；领用行按日期和所属分公司合并为一张单据，来源“备注”“领用部门”分别写入该源行对应的领用明细，不得作为单头值或合并键；领用用途不再导入，旧模板中可选的“用途”列 MUST 被忽略；调拨和回收行仍各创建一张单头及一条明细。品目按资产编号解析为字典 FK，编号未登记时整行拒绝并提示相近编号；采购单价/金额、回收存放位置等字段继续按现有类型映射。模板列、分公司校验、错误提示格式 MUST 保持既有契约。导入结果 SHALL 返回 `{ imported: number, imported_lines: number, errors: string[] }`。

#### Scenario: 领用导入行字段逐行保留
- **WHEN** 用户导入同日期、同分公司的多条领用记录，且各行备注或部门不同
- **THEN** 系统合并为一张领用单并为每条有效源行创建明细，各行的备注、领用部门保持与源行一致

#### Scenario: 忽略旧模板用途列
- **WHEN** 用户上传包含旧版“用途”列的领用模板
- **THEN** 系统接受模板，忽略用途值，并按备注和部门导入领用明细

#### Scenario: 采购、调拨和回收导入行为保持
- **WHEN** 用户导入采购、调拨或回收模板
- **THEN** 采购仍按其既有单头键合并，调拨和回收仍逐行建单，行级字段按各自类型映射

#### Scenario: 部分行无效
- **WHEN** Excel 中某行的资产编号未登记或领用部门不属于指定分公司
- **THEN** 该行导入失败并在 errors 中给出行号与原因，其他有效行可继续导入
