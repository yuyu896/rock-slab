## ADDED Requirements

### Requirement: 领用创建和编辑支持逐行填写备注

Web 与移动端领用创建、草稿编辑及驳回后编辑 MUST 将备注作为领用明细行字段录入和提交；备注可选，每行可填写不同值。领用页面 MUST NOT 显示或提交用途字段。备注输入框高度 MUST 固定、MUST 与同表单其他单行输入控件等高，并 MUST NOT 允许手动缩放或因内容自动增高。加载既有单据时 MUST 从对应明细行回显备注。领用创建和编辑表单 MUST NOT 显示单头“调出部门”输入项。移动端单物品表单 MUST 将备注提交到唯一明细项，而非单据头。

#### Scenario: Web 新建多行领用单
- **WHEN** 用户在 Web 领用表单为两条明细分别填写备注并提交
- **THEN** 备注随对应明细发送，详情重新打开时仍回显到原行，表单不显示用途

#### Scenario: 移动端提交单物品领用
- **WHEN** 用户在移动端填写一项设备的备注后提交
- **THEN** 备注写入该单唯一明细行，单据头备注不被用作设备备注，备注框保持固定高度

#### Scenario: 编辑草稿或驳回单
- **WHEN** 用户打开已有草稿或已驳回领用单
- **THEN** 每行备注从明细回显，修改后仅更新所选行，备注框不因内容或手动操作改变高度

### Requirement: 领用页面移除单头调出部门

领用创建、编辑和详情页面 MUST NOT 展示或要求填写单头“调出部门”。领用部门 MUST 继续作为每条明细的部门字段。若历史单据仍有非空单头备注或审批意见，详情 MUST 以明确的历史/审批信息展示，不得放入设备行备注。

#### Scenario: 查看新领用详情
- **WHEN** 用户查看新建或已编辑的领用单
- **THEN** 页面显示逐行领用部门和备注，不显示用途或单头调出部门
