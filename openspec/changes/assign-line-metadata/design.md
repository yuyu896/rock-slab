## Context

领用单头仍有共享的 `用途`、`备注` 和 `调出部门` 字段。行级元数据变更已为 `TransferLine` 增加用途和备注字段，并把旧领用单头用途回填到明细；现在业务决定是不再使用领用用途。领用部门已经按明细行保存，库存扣减仍按分公司、品目和领用来源确定。

`Transfer.备注` 还承载审批驳回意见，审批处理会将原因追加到该字段。该单头字段必须与设备行备注区分，并在编辑时保留。

## Goals / Non-Goals

**Goals:**

- 从领用 Web/移动端、API 行字段、导入模板和导出中移除用途；历史用途值保留在数据库中但不返回、不再写入或展示。
- 领用明细继续逐行保存备注，并覆盖创建、编辑、驳回后重提、导入、详情和导出。
- 备注输入框高度固定且不可手动缩放；详情长备注不得撑高明细行。
- 领用部门统计及导出从明细部门取值，领用不再读写单头“调出部门”。
- 共享 `Transfer.用途` 字段和其他单据类型保持兼容。

**Non-Goals:**

- 不删除数据库中历史用途字段和值，也不改变采购/调拨等单据类型对共享单头字段的兼容行为。
- 不改变库存来源、台账扣减、审批规则及领用部门必填规则。
- 不推断历史单头备注分别属于哪台设备；不改变使用人、部门或资产明细的粒度。

## Decisions

1. **停用领用用途业务字段。** 领用明细输入/输出序列化器不再包含用途；领用单响应也不返回旧单头用途。行模型中的历史用途列保留，旧数据不清除；其他单据类型的共享单头用途行为保持不变。旧客户端若仍提交用途，领用创建/编辑继续忽略该值。

2. **备注按设备行读写。** Web 多行编辑器、移动端单行表单、详情、批量导入/导出只读写 `TransferLine.备注`。`Transfer.备注` 保留用于历史单据内容和通用审批意见；更新领用单时未提交单头备注不得清空既有值。

3. **备注高度固定。** Web 明细备注 textarea 固定为 36px，移动端固定为 44px，分别与同表单普通输入框等高；两端均禁止 resize 并使用输入框内部滚动承载超长内容。Web 和移动端详情备注限制为单行高度并截断，不改变整行高度；当前用 `title` 暴露完整文本，长文本展示方式可后续单独讨论。

4. **历史数据及部门回填不变。** 已应用的 0031 迁移仍负责将旧单头用途留存于历史明细，并仅在明细部门为空且单头部门名与全集团唯一部门字典精确匹配时回填部门。本次不新增删除用途字段的迁移，避免销毁已有数据。单头备注不复制到行备注。

5. **领用“调出部门”只从领用路径退役。** 领用创建/编辑 payload 不写该字段，领用详情和导出不显示或读取它，部门统计按 `TransferLine.department` 归集。共享字段、调拨创建/详情/Excel 列及其他类型的行为不变。

6. **导入模板移除用途并兼容旧表。** 新领用模板保留分公司、日期、资产编号、领用数量、使用人、领用部门、备注七列。导入接受旧模板附带的可选“用途”列但忽略其值；分组仍按日期和分公司，备注或部门差异不拆单。导出不再包含用途列。

7. **改动覆盖 Web 与移动端。** Web 多行编辑器、移动端单行领用表单及审批详情均隐藏用途；API 仍保持一张领用单一次提交、明细行数组结构。

## Risks / Trade-offs

- [历史用途无法再通过领用界面查看] → 旧值留在数据库中，但不出现在领用响应、页面或导出中；共享单头字段仍保留给其他单据类型。
- [长备注在详情表中被截断] → 固定行高并通过 `title` 查看完整值；更合适的长文本查看交互留待后续讨论。
- [旧模板仍含已取消用途列] → 导入守卫将该列作为唯一可选旧列接受并忽略；新模板和导出不再生成该列。
- [旧领用单头部门无法匹配当前部门字典] → 仅将完全匹配的名称回填到空明细；未匹配记录不创建部门、不猜测关联。
- [其他单据依赖同名共享字段] → 仅按 `action_type=assign` 隐藏用途并忽略旧值，调拨等类型回归测试验证字段兼容。

## Migration Plan

1. 已应用的 0031 迁移保留；其新增用途历史列不再由领用 API 暴露。本次不物理删除该列或共享单头用途字段。
2. 更新后端领用 API、导入/导出、Web/移动端表单与详情及相关 OpenSpec。
3. 验证历史备注、领用库存/台账结果不变，并验证旧导入模板中的用途列被忽略。
