## Requirements
### Requirement: 明细行实例引用输入矩阵

单据创建/编辑的明细行 MUST 支持携带 `instances`（实例 uuid 数组），并按「品目管理方式 × 单据类型」矩阵校验：

- 实例管理品目 × 领用/归还/调拨/回收：MUST 携带实例，且 `len(instances) == 数量`；实例的品目 MUST 与行品目一致
- 实例管理品目 × 采购：MUST NOT 携带实例（实例在生效时自动生成）
- 数量管理品目 × 任意类型：MUST NOT 携带实例（携带即 400）

领用单 MUST 携带库存来源（`领用来源`：stock 新品库（默认）/ recycle_bin 回收库，单头级，与回收去向对称）；来源=新品库时实例 MUST 为「在库」态，来源=回收库时实例 MUST 为「回收库」态，且实例分公司 MUST 等于调出分公司。归还/回收行实例 MUST 为「在用」态；调拨行实例 MUST 为「在库」态且分公司等于调出分公司。领用行使用人 MUST 非空（实例绑人语义）。

#### Scenario: 领用实例管理品目必须绑实例

- **WHEN** 用户提交领用单，行品目为实例管理且未携带 instances
- **THEN** 返回 400，提示该行必须选择与数量等长的实例

#### Scenario: 实例数量与行数量不符被拒

- **WHEN** 领用行数量 3 但仅携带 2 个实例
- **THEN** 返回 400，提示实例数与数量不一致

#### Scenario: 数量管理品目携带实例被拒

- **WHEN** 某行品目为数量管理但携带 instances
- **THEN** 返回 400，提示数量管理品目无需选择实例

#### Scenario: 领用来源与实例状态不符被拒

- **WHEN** 领用来源=新品库，但携带的实例中含回收库状态实例
- **THEN** 返回 400，提示实例状态与领用来源不符

#### Scenario: 采购行携带实例被拒

- **WHEN** 采购单明细行携带 instances
- **THEN** 返回 400，提示采购实例由入库自动生成

### Requirement: 实例充足性终检与行锁

单据生效（审批通过/即时生效）时，系统 MUST 在与台账变动同一事务内以 `select_for_update` 重取全部行实例，按输入矩阵同一规则终检状态/分公司/品目与数量一致：任一实例校验失败 MUST 整单回滚（台账与实例均无变化），错误信息 MUST 带明细行定位（行号 × 品目编号）。终检 MUST 防止创建到生效之间实例被并发单据占用或状态漂移。

#### Scenario: 生效时实例已被占用整单回滚

- **WHEN** 领用单 A 创建后、审批前，另一张已生效领用单 B 占用了 A 所选的某实例
- **THEN** A 审批时终检失败，整单回滚，提示实例已被占用及行号定位

#### Scenario: 并发领用同一实例仅一单成功

- **WHEN** 两张领用单（immediate 生效）同时绑定同一在库实例并发提交
- **THEN** 仅一单成功，另一单回滚并提示实例状态不符

### Requirement: 五单实例状态迁移矩阵

单据生效时实例状态迁移 MUST 与台账数量变动同事务完成，矩阵如下（设计书 5.2）：

| 单据 | 实例动作 |
|---|---|
| 采购入库 | 每行生成 数量 个实例（状态 在库，branch=入库分公司，birth_line=该行，内部编号锁行发号） |
| 领用（新品库） | 所选在库实例 → 在用，写入使用人/部门 |
| 领用（回收库） | 所选回收库实例 → 在用，写入使用人/部门 |
| 归还 | 所选在用实例 → 在库，清空使用人/部门 |
| 调拨 | 所选在库实例 branch → 调入分公司（状态不变） |
| 回收（入回收库） | 所选在用实例 → 回收库，清空使用人/部门 |
| 回收（直接处置） | 所选在用实例 → 退役（终态，档案永久保留） |

实例 MUST NOT 被物理删除；退役为唯一终局出口，档案（含出生与全部流转行）永久可查。

#### Scenario: 采购生成连续编号的实例

- **WHEN** 采购单行（实例管理品目 X × 3）审批通过
- **THEN** 生成 3 个实例 内部编号 X-7/X-8/X-9（承接存量最大序号），状态在库，出生行=该行

#### Scenario: 领用绑定使用人

- **WHEN** 领用单（来源=新品库）行（品目 X × 2，使用人=张三）审批通过
- **THEN** 所选 2 个实例状态→在用，使用人=张三，部门=行部门

#### Scenario: 回收直接处置实例退役不删除

- **WHEN** 回收单（去向=直接处置）行绑定的实例审批通过
- **THEN** 实例状态→退役，记录仍存在于库中，生平可查

#### Scenario: 并发生成内部编号不重号

- **WHEN** 两张含同一品目的采购单并发生效
- **THEN** 生成的内部编号不重复（锁行发号 + 唯一约束兜底）

### Requirement: 序列号待补录

实例序列号 MUST 可空，空值语义为「待补录」，MUST NOT 阻塞任何单据流程。系统 SHALL 提供列表「待补录」筛选与醒目标识；补录经专用端点渐进完成。

#### Scenario: 采购无序列号正常入库

- **WHEN** 采购单不含序列号信息，审批通过
- **THEN** 实例正常生成（序列号为空/待补录），流程无阻塞

#### Scenario: 待补录筛选

- **WHEN** 用户在实例列表筛选「待补录」
- **THEN** 结果仅含序列号为空的实例
