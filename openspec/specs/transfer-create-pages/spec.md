# transfer-create-pages Specification

## Purpose
流转单新建操作以独立路由页面承载，页面由"单头表单 + 明细行表格"构成：品目经字典点选（禁手抄编号），多行单据一次请求提交。
## Requirements
### Requirement: 新增操作以独立路由页面承载
资产流转（采购入库、领用出库、调拨、回收）以及新增固定资产、新增资产的"新建"操作 SHALL 通过独立的路由页面承载，而非模态弹窗。列表页的"新建"按钮 MUST 改为导航到对应的 create 路由，原内嵌模态（`showCreateModal` / `el-dialog` / `modal-overlay`）MUST 移除。

#### Scenario: 列表页"新建"按钮跳转到创建页
- **WHEN** 用户在采购入库/领用出库/调拨/回收列表页点击"新建"按钮
- **THEN** 系统导航到该类型的 create 路由页面（如 `transfers/purchase/create`），不再弹出模态框

#### Scenario: 创建页提交成功后返回列表并刷新
- **WHEN** 用户在创建页填写完毕并提交成功
- **THEN** 系统导航返回对应的列表页，且列表数据被刷新以包含新增记录

#### Scenario: 创建页取消/返回不产生脏数据
- **WHEN** 用户在创建页点击"取消"或浏览器后退
- **THEN** 系统返回列表页，不提交任何数据，列表内容保持不变

### Requirement: 字段与校验与原弹窗一致

新建页面 SHALL 由"单头表单 + 明细行表格"两部分构成：单头表单保持既有字段、必填项与业务校验（调拨创建 MUST 保留"调出分公司与调入分公司不可相同"校验；领用创建页 MUST 提供库存来源单选：新品库（默认）/回收库）；明细行表格 MUST 支持增删行，每行以品目字典点选组件选择品目（按编号/名称检索，选中回显规格/类目/管理方式，MUST NOT 手抄编号文本），并按类型展示专属列（采购：单价/金额；领用：使用人/领用部门；回收：存放位置；调拨：本批规格）。领用明细行的使用人与部门 MUST 为必填且不分管理方式（数量管理行与实例管理行同等强制）；部门字典 MUST 按所属分公司过滤，未选分公司时部门入口 MUST 提示先选分公司。实例管理品目的领用/归还/调拨/回收行 MUST 出现实例点选表格（按行上下文筛选可选项：领用=调出分公司 × 按来源在库/回收库态；归还/回收=在用；调拨=调出分公司在库；均限行品目），选中数 MUST 与行数量联动（选 N 个则数量 N，或数量 N 则必须选满 N 个）；数量管理品目行 MUST NOT 出现实例点选。领用创建页 MUST 以一次请求提交整张多行单据，MUST NOT 逐行循环发起多张单据。领用行使用人/部门必填在后端 MUST 同步强制（创建、驳回后编辑、Excel 导入同口径）。

#### Scenario: 调拨创建阻止相同出入分公司

- **WHEN** 用户在调拨创建页选择相同的调出分公司与调入分公司并提交
- **THEN** 系统阻止提交并提示调出与调入不可相同

#### Scenario: 必填字段缺失阻止提交

- **WHEN** 用户未填写单头必填字段或明细行为空/数量小于 1 即提交
- **THEN** 系统阻止提交并在对应位置提示必填

#### Scenario: 品目必须字典点选

- **WHEN** 用户在明细行选择品目
- **THEN** 通过字典搜索点选完成，选中后行内自动回显名称/规格/单位，不出现自由文本编号输入框

#### Scenario: 多行领用一次提交一张单据

- **WHEN** 用户在领用创建页添加 3 个明细行并提交
- **THEN** 前端发起一次请求创建含 3 行明细的单张领用单

#### Scenario: 实例管理行点选实例

- **WHEN** 领用创建页某行品目为实例管理（来源=新品库，调出分公司 A）
- **THEN** 该行出现实例点选表格，可选项为「A 分公司 × 该品目 × 在库态」实例，勾选 2 个则行数量自动为 2

#### Scenario: 数量管理行不出现实例点选

- **WHEN** 某行品目为数量管理
- **THEN** 该行无实例点选入口，提交 payload 不携带 instances

#### Scenario: 领用数量管理行使用人部门必填

- **WHEN** 领用创建页某数量管理品目行未填使用人或未选部门即提交
- **THEN** 系统阻止提交并提示该行需填写使用人与部门

#### Scenario: 未选分公司时部门入口引导

- **WHEN** 领用创建页尚未选择所属分公司
- **THEN** 明细行部门下拉提示先选择分公司（无可选项），选择分公司后部门字典切换为该分公司部门

#### Scenario: 后端强制领用行使用人部门

- **WHEN** 客户端绕过前端直接提交缺使用人或部门的领用单（创建或驳回后编辑）
- **THEN** 后端返回 400 并定位到具体行与品目，单据不落库

### Requirement: 旧版采购页清退
旧版采购页（`views/Purchase.vue`、`views/purchases/PurchaseCreateForm.vue`、路由 `/assets/purchase`）MUST 移除，访问旧路由 MUST 重定向到 `/transfers/purchase`；其批量导入弹窗能力 MUST 保留在采购列表页。

#### Scenario: 旧采购路由重定向
- **WHEN** 用户访问 `/assets/purchase`
- **THEN** 系统重定向到 `/transfers/purchase`，不出现 404

### Requirement: 采购行金额留空自动计算

采购明细行的金额留空时 SHALL 自动 = 单价 × 数量（前端录入即时联动：单价或数量变化且金额为空时即补算显示）；手填金额 MUST 以手填为准（不被联动覆盖），清空手填值即回到自动计算。后端对"有单价无金额"的采购行 MUST 补算（表单创建、驳回后编辑、Excel 导入同口径），保证任何路径入库的采购行单价金额自洽。

#### Scenario: 前端留空自动算

- **WHEN** 采购创建页某行填单价 12.50、数量 4，金额留空
- **THEN** 金额自动显示 50.00

#### Scenario: 手填金额优先

- **WHEN** 某行金额已手填 45.00（整批折价），随后修改单价
- **THEN** 金额保持 45.00 不被覆盖；清空金额后随单价联动重算

#### Scenario: 后端补算有单价无金额的行

- **WHEN** 客户端提交采购单某行单价 10、数量 3、金额缺失
- **THEN** 落库明细行金额为 30.00

#### Scenario: 无单价的行不补算

- **WHEN** 采购单某行单价与金额均缺失
- **THEN** 系统不补算，金额保持为空（不报错）


### Requirement: 写单页分公司下拉按授权范围收口

写单页中作为**扣数方/入库方**的分公司下拉——采购入库·入库分公司、领用出库·所属分公司、调拨·调出分公司、回收·调出分公司——MUST 仅列操作者授权范围内的分公司（数据来源 `GET /api/branches?scope=write`）。调拨·**调入**分公司 MUST 维持全量分公司可选（修订 3.1 单边化：调入方不要求授权）。PC 创建页与移动端开单页同口径。提交端的 `validate_branches_in_scope` 校验 MUST 保留不变（选项收口是体验防线前移，非权限模型变更）。

#### Scenario: 员工采购入库只能选授权分公司

- **WHEN** 数据范围仅含分公司 A 的用户打开采购入库创建页
- **THEN** 入库分公司下拉仅含分公司 A（及同范围其他分公司），不含范围外分公司

#### Scenario: 调拨页调出收口、调入全量

- **WHEN** 数据范围仅含分公司 A 的用户打开调拨创建页
- **THEN** 调出分公司下拉仅含授权范围内分公司，调入分公司下拉为全量分公司

#### Scenario: 移动端开单页同口径收口

- **WHEN** 范围受限用户在移动端打开采购/领用/调拨开单页
- **THEN** 入库/所属/调出分公司下拉仅含授权范围内分公司，调拨调入分公司为全量

#### Scenario: 提交端越权校验不回归

- **WHEN** 范围受限用户以某种途径（如缓存旧选项）提交了范围外分公司的单据
- **THEN** 后端 `validate_branches_in_scope` 仍返回 400 拒绝，不落库

### Requirement: 品目点选按扣数列过滤

扣数类单据的品目点选器 MUST 以**所选分公司的台账行**为数据源（`/api/assets/summary`，已按授权范围过滤），仅列对应扣数列数量>0 的品目，选项行 MUST 显示该列可用数量：

| 单据类型 | 扣数列 | 品目过滤 |
|---|---|---|
| 领用（新品库） | 在库数量 | 在库>0 |
| 领用（回收库） | 回收库数量 | 回收库>0，且剔除消耗品（领出即耗用品目不得走回收库） |
| 调拨 | 在库数量 | 在库>0 |
| 回收 | 在用数量 | 在用>0 |
| 采购 | 无（生成制） | 不过滤，维持全量字典检索 |

未选分公司时，扣数单据的品目点选 MUST 禁用并提示先选分公司；检索仍按编号/名称关键字进行。提交端台账充足性校验 MUST 保留不变。

#### Scenario: 领用只列有库存品目

- **WHEN** 用户在领用创建页选定分公司 A（来源=新品库）后检索品目
- **THEN** 品目点选器仅列 A 分公司在库>0 的台账行品目，选项行显示在库数量

#### Scenario: 领用回收库来源剔除消耗品

- **WHEN** 用户在领用创建页选定分公司与来源=回收库后检索品目
- **THEN** 点选器仅列该分公司回收库>0 且管理方式非消耗品的品目

#### Scenario: 回收只列在用品目

- **WHEN** 用户在回收创建页选定调出分公司后检索品目
- **THEN** 点选器仅列该分公司在用>0 的品目，选项行显示在用数量

#### Scenario: 未选分公司时品目入口禁用

- **WHEN** 用户在领用/调拨/回收创建页尚未选择分公司即点开品目点选器
- **THEN** 点选器禁用并提示先选择分公司，不发起点目检索

#### Scenario: 采购维持全量字典检索

- **WHEN** 用户在采购入库创建页检索品目
- **THEN** 点选器仍按全量品目字典检索，不按台账过滤（与所选分公司无关）

#### Scenario: 台账充足性提交拦截不回归

- **WHEN** 用户在品目点选器选定品目后，同品目多行合计数量超出该列可用数量并提交
- **THEN** 后端台账充足性校验仍拦截（前端选项收口不替代提交校验）
