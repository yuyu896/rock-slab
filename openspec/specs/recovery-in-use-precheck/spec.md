# recovery-in-use-precheck Specification

## Purpose
回收错单在创建页拦截：在用数量可见 + 提交预检，审批端在用不足报错说业务语言（asset-model-v2.md 修订 1.3，2026-08-27 修宪）。
## Requirements
### Requirement: 回收单创建页在用数量展示与提交预检

回收单创建页在明细行选定品目后 MUST 显示该（调出分公司 × 品目）的**当前在用数量**（取台账 AssetStock 在用列）；提交时 MUST 对在用不足预检拦截——同品目多行 MUST 合并计量后与在用数量比较，超出即阻止提交并提示行定位。预检为体验层拦截，生效时点的充足性终检仍由台账唯一写入口在行锁内执行（语义不变）。台账列表查询接口 MUST 支持按品目编号（asset_code）精确过滤以供预检取数。

#### Scenario: 选品目后显示当前在用

- **WHEN** 回收单创建页（调出分公司 A）某行选择品目 X，A×X 台账在用 3
- **THEN** 该行显示"在用 3"；将数量改为 4 时行内出现不足提示

#### Scenario: 同品目多行合并预检

- **WHEN** 回收单创建页两行均为品目 X（数量 2 与 2），A×X 台账在用 3
- **THEN** 提交被拦截，提示品目 X 合计 4 超出当前在用 3

#### Scenario: 在用充足正常提交

- **WHEN** 回收单创建页行数量 ≤ 当前在用数量
- **THEN** 预检通过，单据照常进入待审批

#### Scenario: 台账接口按品目编号精确过滤

- **WHEN** 客户端以 asset_code=X 精确参数查询台账
- **THEN** 仅返回品目编号为 X 的台账行，不做关键字模糊误中

### Requirement: 回收审批在用不足报错业务化

回收单审批通过时若台账在用列不足，报错 MUST 使用业务语言：明确"回收只能回收『在用』中的资产"、给出当前在用数量与不足扣减量，并提示核对方向（物品是否未领用、调出分公司是否选错）；报错 MUST 保留明细行定位（行号 × 品目编号）。其余单据类型的台账不足报错格式维持现状。

#### Scenario: 在用不足审批报错可读

- **WHEN** 回收单（品目 X × 2，调出分公司 A）审批通过，A×X 在用为 0
- **THEN** 返回 400，文案含"回收只能回收『在用』中的资产"、当前在用 0、明细行号与品目编号，并提示核对未领用或分公司选错

#### Scenario: 其他单据报错格式不变

- **WHEN** 归还单审批时在用不足
- **THEN** 报错仍为既有通用台账不足格式（分公司 × 品目 × 列 × 现值 × 变动量）
