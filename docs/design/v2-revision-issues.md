## 资产流转模块

### 1. 新建页 960px 限宽像弹窗 💡

- **现象**：采购入库等新建页明明是独立页面，却像弹窗只占页面中央一部分。
- **代码事实**：`frontend/src/views/transfers/components/TransferCreateLayout.vue:37` `.create-page { max-width: 960px; margin: 0 auto; }`。四个新建页（采购/领用/调拨/回收）共用此布局。小案①列表页 flex 改造未覆盖新建页。
- **拟定方向**：四个新建页统一改为撑满内容区宽度。
- **状态**：✅ 已定案，见修宪稿。

### 2. 采购金额未填时不自动计算 💡

- **现象**：采购明细行填了单价和数量，金额不会自动算，必须手填。
- **代码事实**：`frontend/src/views/transfers/components/TransferLinesEditor.vue:149-150` 单价、金额两列均纯手填，无联动。设计书 5.4 未写计算规则。
- **拟定规则**：金额留空时自动 = 单价 × 数量；手填以手填为准（允许整批折价改写）。
- **状态**：✅ 已定案，见修宪稿。

### 3. 领用出库 使用人/部门应为必填 📝

- **现象**：领用单数量管理品目行可不填使用人，部门也全部选填。
- **代码事实**：`TransferLinesEditor.vue:99-108` 校验仅对实例管理行强制使用人；`:154` 部门下拉明写"选填"。后端对数量管理行同样不强制。
- **拟定规则**：领用行不分管理方式，使用人、部门均必填（前后端同步收紧）。
- **连带细节**：领用部门字典按所属分公司过滤，必填后需先选分公司才能选部门，校验提示需引导。
- **状态**：✅ 已定案，见修宪稿。

### 4. 出库后物品未在实例档案生成 —— 待定（A 配置 / B 修宪）

- **现象**：领用出库后，物品没有出现在实例档案。
- **代码事实**：实例在**采购入库时**生成且仅限实例管理品目（`backend/apps/assets/services/instances.py:109-115`）；领用不生成实例，只绑定既有实例（在库→在用+使用人），实例管理品目不选实例无法提交。品目新建时管理方式必选、默认"数量管理"（`frontend/src/views/categories/CategoryCreate.vue:116`），有存量后不可切换。
- **两岔路**：
  - **A**：测试品目本应是实例管理而配成了数量管理 → 字典配置问题，系统无 bug。
  - **B**：用户设想"凡领用到人手的物品皆有档案"（数量管理品目也要）→ 修宪级，冲击决策 #2（管理方式是品目固有属性）与四层架构③定位，需完整评估连锁（编号、档案量级、性能）。
- **状态**：✅ 已定案（2026-08-27）：维持设计 A——档案仅实例管理品目，配错的品目改字典。

### 5. 调拨要求对方分公司权限 📝

- **现象**：创建调拨单必须同时拥有调出、调入两家分公司的权限，否则被拒。
- **代码事实**：`backend/apps/transfers/views.py:132` 创建时 `validate_branches_in_scope(user, from_branch, to_branch)` 双边校验（`backend/core/permissions.py:54-70`）。设计书通篇未写调拨权限规则，实现时自选了最严一档。
- **背景**：调拨一次写两边台账（扣A加B），只校验调出方 = 允许写入对方台账（但有单据留痕 + 对账兜底）。
- **候选方案**：
  | 方案 | 规则 | 代价 |
  |---|---|---|
  | A | 只校验调出方权限 | 贴合要求；连带：调入方列表可见性要不要放 |
  | B | 调出方发起 + 调入方确认（双确认流） | 最严谨；新增待确认状态，流程变长 |
  | C | 维持现状，跨范围调拨由大区/集团操作 | 零开发，组织上不顺手 |
- **状态**：✅ 已定案（2026-08-27）：A——只校验调出方权限，调入方对单据只读可见。

## 回收模块

### 6. 取消库存区的行内回收入口 📝

- **现象**：用户要求取消"资产台账"里的回收功能，理由：回收的定义是针对"领用后的物品"。
- **代码事实**：资产台账页（AssetSummary）本身无回收按钮（操作列仅 调整/下钻/打印）。"库存"菜单下唯一回收入口在**实例档案页**行内（`frontend/src/views/FixedAssetList.vue:291`，仅"在用"实例显示，定义本身无误），但它是**即时生效通道**（`views/assets/RecoveryDialog.vue:71` `immediate: true` → 直接生成"已通过"单据并联动台账，绕过审批流，`backend/apps/transfers/views.py:144-154`）。
- **拟定方向**：回收入口唯一化——取消实例档案行内即时回收，所有回收统一走"回收单 → 审批 → 生效"。
- **待确认**：用户所指是否即实例档案行内回收按钮（有截图编号更稳）；真实诉求是否为"回收必须走审批流"。
- **状态**：✅ 已定案（2026-08-27）：取消行内即时回收，统一走回收单审批流（修宪稿修订 5.1）。

### 7. 回收单审批报"无库存" —— 机制正确 + 体验缺口（待排 bug）

- **现象**：账面有库存，审批通过回收单时告警显示无库存。
- **代码事实**：回收扣的是台账**在用**列（`backend/apps/assets/services/ledger.py:115-118` 回收入回收库=在用−N 回收库+N / 直接处置=在用−N）。若物品从未领用（在库>0、在用=0），审批时 `_apply_delta` 报「分公司 × 编号」在用数量不足（`ledger.py:44-51`）——**设计正确的拦截**。
- **体验缺口**：
  1. 回收单创建页不显示"当前在用"数量，错单提交到审批才炸；
  2. 报错文案「在用数量不足」易被读成"无库存"。
- **待排除**：若物品确实领用过（在用>0）仍报错 → 真 bug，需单据编号追溯（可能调出分公司选错等）。
- **状态**：✅ 定案（2026-08-27）：体验缺口照修（预检+文案）；用户称物品已领用过仍报错 → 真 bug 嫌疑，另立生产排查案（修宪稿第六节遗留事项）。

### 10. 盘点范围模型：区分在库/回收库 + 按部门盘点 📝 设计书留白

- **现象**：盘点不区分在库与回收库；不支持按部门盘点。
- **代码事实**：InventoryTask 范围仅 分公司 × 资产类目（`backend/apps/inventories/models.py:25-33`）；应盘数量取台账"在库"列（`services.py:9` 注释原文"盘点只盘在库列，expected 取自在库"）；差异调整单只修"在库"列。台账行无部门维度（铁律：持有信息只活在单据行与实例档案）。
- **两个需求分层**：
  1. **区分在库/回收库**：任务加"库别"维度，应盘取对应列、差异修对应列——机制照搬，中等改动；
  2. **按部门盘点**：
     - 实例管理品目：可行（实例有部门/使用人字段，= 该部门名下实例逐台清点，扫码式）；
     - 数量管理品目：无持久持有记录（设计如此），按部门盘在用要么靠单据流水推导（脆弱）要么新增"持有登记"层（修宪级，冲击铁律 1）。
- **设计分野**（待写入设计书）：盘点或分为两种模式——数量盘（在库/回收库按数量）与实例盘（在用按部门逐台）。
- **追加（2026-08-27 用户追问）**：现状只盘台账"在库"列，在用（有使用人的电脑等）不在任何盘点范围内；实例盘清单须**按部门/使用人分组**展示（谁名下哪几台逐台打钩），计数单位是"台"非汇总数量，报告层再汇总。
- **待拍板**：部门盘点的对象——只实例管理品目（一案可做），还是必须覆盖数量管理品目（修宪级，需先谈清持有登记模型）？
- **状态**：✅ 已定案（2026-08-27）：任务加库别维度（在库/回收库）；部门盘点=实例盘，仅实例管理品目，差异不自动改账（修宪稿第四节）。

## 权限分配模块

### 11. 保存岗位后无法再次修改具体权限设置 🐛 + 设计陷阱

- **现象**：设置权限选完岗位、点保存岗位后，再次进入不能修改具体的权限（操作码）设置。
- **代码事实**：
  1. **bug**：`frontend/src/views/admin/PermissionAssign.vue:228` `roleDirty = selectedRole !== selectedUser.role` —— 「保存岗位」按钮仅当岗位变化时才亮；重选同一人只改操作码勾选时按钮恒灰，无法保存；
  2. **陷阱**：选岗位时勾选集被模板整体替换（`:283-284`），保存按勾选集差量对齐、未勾即删（`:321-332`）→ 单独授予的额外权限会在重选岗位+保存时被静默清除。而后端换岗迁移命令原则是"只补不删"（`backend/apps/permissions/management/commands/migrate_positions.py:7`）——两处哲学相反。
- **拟定方向**：①脏检查纳入"操作码勾选集 vs 现有授权"的差集；②换岗时模板外既有授权的处置定为明规则（保护或提示确认），写入设计书权限模型节。
- **状态**：✅ 已定案，见修宪稿。

### 12. 分公司行政与分公司负责人的区别 —— 岗位模板空档 📝

- **现象/提问**：两岗位有何区别？
- **代码事实**（`backend/apps/permissions/positions.py:31-51`）：分公司负责人(manager) 预填 管理用户/品目字典/资产管理/审批流转/审批盘点 共 5 项；**分公司行政(staff) 模板预填为空**，行政组长(leader) 亦为空。操作码全表 12 项（`backend/apps/permissions/operations.py`），台账调整(adjust_ledger)/实例管理(manage_instances)/资产处置(dispose_assets) 无任何模板预填——除 admin 外全需单独授予。
- **设计问题**：违背口诀"岗位定操作、特例才单独授予"——最常见的日常操作人群（分公司行政）变成全靠特例授权。验收手册 T03/T06 所需权限也无模板来源。
- **待拍板**：分公司行政（及行政组长）应默认能干什么——开单、执行盘点、导入、补录序列号、开调整单……哪些进模板、哪些留在负责人。需用户给出设想后写入设计书岗位映射表。
- **状态**：✅ 已定案（2026-08-27）：分公司负责人与分公司行政**合并**为一个岗位「分公司行政」（用户：一个分公司行政约 2 人，无区分必要），模板预填 8 操作码，存量 staff 迁移（修宪稿修订 3.2）。

## 品目模型（验收后补充议题）

### 13. 消耗品（卫生纸、笔、打印纸等）在系统中的出库呈现 📝 已定案

- **现象/提问**（2026-08-27）：消耗品在系统中怎么出库呈现？
- **代码事实**：类目体系有"低值易耗品"B 大类（seed_data 内置 A4 打印纸、垃圾袋），但纯标签无行为差异。现状消耗品 = 数量管理品目：采购入库→在库+N，领用出库→在库−N、**在用+N**，此后无出口（无人为卫生纸开回收单）→ 在用只增不减、总量永不降、报表（资产总数/总值/使用率）被灌水。
- **四案**：A 管理方式加第三档"消耗品"（领用=耗用发放：在库−N 总量降，记部门不进在用）｜B 领用单行级去向开关｜C 维持现状｜D 不进系统。
- **已定案（2026-08-27）**：**方案 A + 使用人、部门都必填**——消耗品行"使用人"= 纸质领用单的签字人（记录性文本），部门供成本归属；领用单据行即发放流水，报表可出部门消耗统计。与修订 2.2"领用行使用人/部门必填"统一，无例外。
- **连带细则**：消耗品无回收/无实例/不参与在用盘点；调拨可用（在库两边动）；存量 B 大类品目迁移走预览清单（挂有"在用"的先经调整单归零）。
- **状态**：✅ 已修宪（设计书 #2 三档 + 5.1/5.2/5.4 条文 + 修宪记录），拆案表第 8 案。

## 写单表单选项收口（2026-08-28 议题）

### 14. 写单页分公司下拉与品目选择器未收口 📝

- **现象**（2026-08-28 用户提出）：① 采购入库时员工可选其他分公司，应只显示权限范围内的分公司；② 领用出库是否可只显示权限内分公司有数量的品目。
- **代码事实**：
  1. `organizations/BranchViewSet` 为普通 ModelViewSet 无范围过滤，`getBranches()` 全量下发 → 采购/领用/调拨三个创建页的分公司下拉对所有人显示全部；防线仅在提交时 `validate_branches_in_scope` → 400（体验差，非安全洞）；
  2. `ItemPicker` 调 `getCategories`（全字典），不看所选分公司数量、不看领用来源扣哪列；防线仅在提交时台账充足性校验。
- **拟定规则**：
  1. 分公司下拉按单据类型收口：采购·入库分公司 / 领用·所属分公司 / 调拨·调出分公司 → 仅显示操作者授权范围内分公司（后端按 resolve_user_scope 过滤下发）；**调拨·调入分公司维持全量**（修订单边化 3.1 的设计，调入方任意）；
  2. 品目选择器按单据"扣数列"过滤：领用（新品库）→ 在库>0；领用（回收库）→ 回收库>0；调拨 → 在库>0；回收 → 在用>0；采购 → 不过滤（按所选分公司）。选择器只给"能选的"。
- **连带**：前端"我的授权范围分公司"数据来源，已定走 **branches 接口加 scope 参数**（`GET /api/branches?scope=write`，BranchViewSet 按 resolve_user_scope 服务端过滤；无参维持全量兼容既有 8 处调用；调拨调入方不传参取全量）。不扩权限接口——effective 为管理员全员快照端点，且返回 id 集合需二次换名称对象（2026-08-28 与用户议定）。
- **状态**：✅ 定案（2026-08-28），拆案表第 9 案。
